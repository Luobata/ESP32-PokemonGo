# PokeWalk 保留存档 USB 更新

`PokeWalk-update.zip` 用于已安装 PokeWalk 的设备。分区表相同时只写入 `0x10000` 应用。
V23 首次扩容唯一允许的分区变化是新增 `pokewalk_store`（0x380000 / 0x20000）；
现有所有分区的类型、地址、大小和标志必须完全相同。校验通过后，先写并验证应用，再写
0x8000 的完整 4 KiB 分区表扇区，保留表后原字节。其他布局变化均拒绝。

更新前完整保存原 NVS、分区表、身份/恢复/网络区域以及新增仓库范围到电脑并回读，
更新后逐字节核对数据区域未变。扩容迁移在新固件启动后进行，保留 V5～V22 旧进度。
这是 USB 命令行工具，不是社区蓝牙安装包；不要把应用文件交给地址为 `0x0` 的烧录器。

1. 建议先用存档网页保存一份 `.pksave`，保留原来的备份。关闭浏览器 USB 连接和串口日志。
2. 安装 Python 3 和依赖：`python3 -m pip install 'esptool>=4.8,<5'`。
3. 解压更新 ZIP，在解压目录执行：
   `python3 update_firmware.py --port /dev/cu.usbmodemXXXX --update`。
   Windows 使用 `py -3` 代替 `python3`，端口例如 `COM5`。
4. 等待应用验证、数据回读和重启完成，在设备核对伙伴、等级、图鉴和道具。

默认原始备份位于个人目录 `PokeWalk Backups`，可通过 `--backup-dir` 指定目录。
原始备份用于故障排查，不能当作 `.pksave` 导入网页，不要公开分享。
不支持的设备、超出上述范围的分区变化、未完成的 v1/v2 导入日志、文件损坏、备份失败都会在写入前拒绝。
只允许向兼容旧存档的新版本更新；此工具不使旧固件具备读取未来存档的能力。

更新中断时不要改用完整安装包或擦除整片 Flash。保持原始备份，重新执行同一更新包。如应用损坏导致提示「当前不是 PokeWalk」，请保留原始备份进一步排查，不要改用完整安装。
如果数据核对失败，工具不会主动重启或自动覆盖存档，需保留备份进一步排查。

首次安装或社区完整安装仍使用 `FoloToy-AI-Passport-full.bin`。完整文件在 NVS 区域
含有空白填充，写入会清空该区域。已有进度必须先备份，安装后通过网页导入恢复。
不能把「同一种游戏」或「存档版本相同」当作完整安装会保留进度的保证。

扩容后备份必须使用支持 v2 容器的网页：刷新在线网页或重新下载离线工具。
旧 `.pksave` 不用转换，保留原文件；V23 新备份包含完整仓库，不能导入旧固件。
开发命令 `restore.py --restore` 不直接操作扩展仓库，请使用网页的导入和恢复流程。
