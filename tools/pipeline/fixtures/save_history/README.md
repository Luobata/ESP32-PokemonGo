# 历史存档结构回归样本

这些 `.bin` 仅为**人工构造的游戏进度 blob**，不包含设备 ID、Wi-Fi 信息、玩家存档或 Flash 镜像，不能直接作为 `.pksave` 导入。每份样本由对应 Git 提交里的真实存档结构和 `party.c` 编码生成，未使用当前 `save_t` 改版本号来替代旧结构。

`manifest.json` 固定来源提交、结构类型、相关源码摘要、字节长度及样本 SHA-256。V5、V11～V15、V17、V18 使用各历史提交的 `save_t`；V6～V10、V16 在可用 Git 历史中没有独立版本的提交，采用当时源码保留的迁移结构，并在 provenance 中明确标注，不能声称是实机导出的备份。

当前 19 份样本覆盖 V5～V18，以及 2026-09-15、09-19、10-03、10-04 的 V17 源码。包含非空队伍、闪光仓库伙伴、图鉴、养成、遭遇、道具、正在进行的训练家对战（含濒死伙伴）、成就、探索、秘境与离线体力时钟；没有该功能的旧版本检查相应默认值。V5～V15 的遭遇填充、早期 V11 的保留字节、V15/V16 的秘境奖励尾部填充特意写入非零值，防止把历史未定义字节当作新字段校验。

生成器：`tools/pipeline/generate_historical_save_fixtures.py`；写入器：`tools/pipeline/fixtures/historical_save_writer.c`。只在维护样本时显式执行，需要完整 Git 历史和 C 编译器。生成环境为小端、64 位整数按 8 字节对齐；生产结构的静态断言、主机迁移测试和 ESP32-C3 固件编译共同检查布局。测试/CI 不运行生成器，只读固定字节，因此浅克隆也可以回归。

检查入口：

```sh
python3 tools/pipeline/verify_save_import_compatibility.py
python3 tools/pipeline/verify_nvs_restore_roundtrip.py
```

第一个执行生产解码、世界状态校验、启动和二次启动；第二个使用 ESP-IDF 的真实 NVS 引擎，在 RAM Flash 隔离环境中构造分区、执行生产 USB 暂存/恢复日志、重启读档、导出后再次导入，并核对独立 NVS 设置键。USB 协议身份校验、覆盖前备份/ACK、网页文件操作与断电故障测试由 AGENTS.md 中其他检查共同覆盖。本测试不等同于真机覆盖导入。

新增格式时追加样本和迁移断言，保留旧文件及其摘要；不要批量覆盖历史样本。若变更了同版本字段含义，也必须增加对应发布来源的样本，不能只更新 manifest 中的版本号。未知新版本、声明版本不一致及当前格式的无效字段仍须拒绝。

V18 在提交 `36a902a` 固定新地区进度布局（4008 字节），新增地区、研究、深层模式、首通、保底与待领道具/闪光伙伴样例。上一公开版本 `0f76077` 的 V17 也已追加，旧 17 份样本未改动。

`../dungeon_history/` 另固定公开版本 `0f76077` 的 V3 秘境（928 字节、非空自有队伍、闪光伙伴、剩余 HP、分岔和强化）。`verify_region_expansion.py` 用生产加载器验证 V3→V4 迁移；真实 NVS 回归验证旧 `run_v3` 随整个备份原样恢复。生成器 `generate_dungeon_history.py` 仅维护时运行，不进入回归。
