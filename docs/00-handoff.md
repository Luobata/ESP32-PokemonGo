**① 截图抓不到任何动画中间态。**
`screen_dump()` 调的是 `s_redraw`，而各页的 `redraw_for_dump`
（如 `play_battle.c` 的 `draw_all()`）是**按当前状态变量重画**，
**不是抓屏幕那一帧**。再加上传输代价（150 KiB 帧 / base64 200 KiB，
即使 USB-CDC 走满也要 ≥2.8 帧的时间）。
所以**开场打字机、八种转场、抖动、闪白 —— 截图一张都抓不到**。
帧级时序要么用宿主对账（`verify_opening.py` 逐帧比状态机），
要么在 tick 里打**串口帧号轨迹**。

**②b 布局不变量现在是编译期断言，不再只是注释。**
`screen.h` 的 `SCREEN_ASSERT_WITHIN_BAND(name, y, h)` 用 `_Static_assert`
检查元素是否跨 80px 横带边界 —— 跨了**编译不过**，并报出元素名。

起因是用户实测发现 P1「饱食/心情那片区域有时先渲一半再出来」：
体能条 y=231..240 跨带 2/3 边界，而**带 3 每拍重画、带 2 每 8 拍重画**，
8 倍频差让同一条条形的上下部分先后出现。
`screen_px` 对越界像素**静默丢弃**，所以两边各画自己那半、谁都不报错。

而 `play_idle.c` 文件头当时就写着「每个元素都不跨横带边界」——
**不变量只活在注释里，没有任何机制检查它**。这是这次的真正教训：
可机械检查的不变量要写成断言。轴距已从 24px 改 22px 修掉跨界。

> 注意：**不是所有跨带都要修**。sprite 有意跨带 0/1，而那两带始终同频重画。
> 断言只加在「要求单带刷新」的元素上 —— 否则会把合法情况也拦下来。
> P2/P3 另有跨带元素目前安全（P2 无 lv_timer、P3 动画只碰带 0/1），
> 见 STATUS 第三节 ⑬。

Gen1 的 back sprite 在低分辨率下看着也像正面 ——
这轮就误把「仍用 back」当成「已改 front」。
数据源要读代码；截图只能证明「画出来了」。
换 sprite 这类改动要**两张图对比 + bbox 度量**（本项目用过 40×32 → 74×66）。

**④ 音频不能靠「欠载计数」判合格。**
S13 曾判 PASS（欠载 0 / 写错误 0 / 样本数与 sim 吻合），
**而用户听不到任何声音** —— `bsp_audio_set_volume` 全项目零调用，
codec 停在硬件默认值。**那些指标量的是「样本写出去了」，不是「有声音」。**

判据是**物理麦克风回采**（ES8311 全双工，`bsp_audio_read` 本来就有）：
`dbg.c` 的 `r` 命令给「静音 RMS vs 播放 RMS」比值。
实测 51 → 3991（**78×**），峰值为 int16 上限的 37~45% 未触顶（clip 0）。
**看这个，不看欠载计数。**

**③ `walk.py --settle` 默认 2.5 秒，验战斗不够。**
战斗每回合 = 抖 4 帧 + hold 6 拍 = 600ms，`BATTLE_MAX_ROUNDS 40`
→ 最坏 **24 秒**。2.5s 只覆盖 4 回合，会截到播放中间态
（`s_done` 仍 false、`world_grant_exp` 还没调）。**验战斗结算用 `--settle 26`。**

详见 [09-device.md](09-device.md)、[../firmware/README.md](../firmware/README.md)。

## 一、这是什么项目

在一台 **ESP32-C3 掌机**上做宝可梦风格的真实世界探索游戏，自用、不分发。

硬约束（见 [01-constitution.md](01-constitution.md)）：

| 项 | 值 | 后果 |
|---|---|---|
| 屏幕 | 240×320 彩色 | 整帧 RGB565 = 150 KB，**装不下**，必须分块横带渲染 |
| 按键 | **只有 A/B/C 三个** | 所有交互的第一约束。取名、翻页、导航都受它限制 |
| SRAM | ~400 KB | 上面那条的原因 |
| flash | 8 MB | 宽裕。资产才用了 149 KB |
| **无 GPS** | | 用 WiFi 环境指纹替代 —— 这是整个项目的技术核心 |
| **无 IMU** | | **步数不可实现**，所以用「移动量」而非步数 |
| 无内置 DAC | | 音频只能 PWM 或 I2S，指向实时 chiptune 合成 |

核心设计取向（[02-sensing.md](02-sensing.md#20)）：
**让时间生产内容，让空间调制内容** —— 任何基于「见到新 BSSID」的指标都会衰减到零，
所以驻留也要有产出（基地按时间排程），出门只是更快（猎场按瞬现 AP）。

| 续航天数 | 扫描频率上限 → 遭遇频率、地点时间分辨率 | **不用电流表** —— `bsp_battery_soc()` 定时采样 |

| 外置 32.768kHz 晶振 | 同上 | 查 sdkconfig 的 RTC 时钟源，或实测漂移 |
| NFC 芯片型号 | 能否用 NFC 对时 | 手机 NFC Tools 读。**BSP 引脚表里没有 NFC** → 倾向静态标签 |
| 口袋 RSSI 基线 | 阈值标定 —— 现在用的是电脑天线数据 | 有设备了，装兜里跑一轮采集 |

固件实现顺序见 [07-roadmap.md](07-roadmap.md) 的 F1~F14。
**F5 是关键一致性检验**：把 `data/raw/*.ndjson` 灌进固件，
它应当算出与 `sim/replay.py` 完全相同的状态序列。

## 六、几条容易忘的项目惯例

- **数值不手填**，从 pret 反汇编取（`data/trainers/parties.asm` 等）
- **三键手势有一个全局占用**：`C 长按`（`BSP_BTN_OK + LONG`）被
  `main.c` 拦截作「退回 demo 菜单」，**不转发给 `nav_key()`** ——
  **任何页面都不能用它**。页面可用的是 `A/B/C 单击`、`A/B 双击`、`A/B 长按`。
  （2026-09-06 踩过：给 P2 安排「C 长按丢弃」，实际那个手势到不了页面。）
- **提示行只能单行、每个 action ≤ 2 字**：`sim/strings.py` 的
  `KEY_HINT_MAX_ACTION = 2`，`check_key_hints()` 会审计宽度（≤232px），
  而 `gen_pages.py` 的 `hint_line()` **无条件拼单行**。
  想表达「单击 X / 双击 Y」这种双语义**表达不出来** ——
  该改的是交互（让一个键只做一件事），不是文案格式。
- **新页面的提示行要进 `KEYS`，别硬写在固件里**。
  P0 开场曾硬写 `"[A]继续 [B]留空 [C]跳过"`，后果是：审计查不到、
  那几个字不在 `strings.charset()` 里、**只靠 `convert_font.py` 扫固件
  字面量兜底才没变空白方框**。兜底哪天简化掉就出事。
- **美术也不手画** —— 与上一条同源，2026-09-06 补：
  手绘的大木博士立绘被用户否决（「太丑、和皮卡丘不是一个风格」）。
  根因在**来源**：宝可梦 sprite 来自初代真实游戏数据
  （`fetch_gen1.py` 取 PokeAPI 的 gray 变体，**colortype=0 / depth=2 的真四阶灰**，
  即 DMG 原生表现），而手绘点阵是平涂色块 —— 不同来源必然不同气质。
  初代原品在 `pret/pokered` 的 **`gfx/trainers/prof.oak.png`**
  （56×56、depth=2、colortype=0，与宝可梦 front sprite 完全同格式）。
  **要新的人物/UI 素材，先去 pokered 找有没有原品**，
  转换走 `convert_sprites.py` 同一条管线（别自己写量化 —— 那是风格一致的保证）。
  注意 `gfx/sprites/oak.png` 是 16×96 行走图 sprite 表，**不是立绘**。
  放大只能**整数倍**（非整数倍插值会糊掉点阵）。
  **且必须跑 `convert_palettes.fill_interior_white`** —— 色号 3 是透明，
  而它同时承担「画布外背景」与「物体内部的白」两种角色；
  不洪泛就会让白大褂/高光透出背景色（2026-09-06 实测：Oak 的 idx3 占 78.7%，
  上屏后整件白大褂消失）。**复用那个函数，不要自己写洪泛** ——
  「内部」必须定义为**与画布边界不连通**，用「被非透明像素包围」
  这种局部判断对凹形轮廓会误判。
- **页面改动要真开浏览器验**，`node --check` 通过不代表画对了
  （栽过：网格渲染成单色、精灵球画成矢量圆、星星形状错；
  这轮又栽一次：三栏布局把「总览」推到折叠线下，assert 失败才发现）
- 提交消息用 `git commit -F 文件`，正文里的 `"<HBB..."` 会被 shell 当命令替换
- 中文名用**任天堂官方译名**（zh_nin），不是动画代理译名
  （徽章是**颜色名**：灰色徽章而非岩石徽章，从英文回译八个全错）
- **字库改完跑 `convert_font.py` 再跑 `inventory_assets.py`** ——
  后者是断言，退出码 0 才算过。光看「字数在涨」不算验证：
  港台字形那次 27% 的字形是错的，而所有统计指标都正常
- **新系统若有上屏文案，必须给它加 `charset()` 并登记进
  `convert_font.py` 的 `SOURCES`** —— 这条漏了三次（S17 漏 29 字、
  S14/S2·S7/S18 漏 16 字、`strings` 自己漏了 `KEYS` 的键名 5 字）。
  注意不只是 `strings.py` 那种集中文案：dataclass 字段默认值、
  函数动态拼的菜单项、失败提示的 `reason` 串全都算
- **PingFang.ttc 必须传 `index=2`**（SC 简体）。默认 index 0 是香港繁体，
  用它渲简体的后果是「鉴」全空 + 142 个字形是港台写法
- **点阵要看 ASCII 预览**。字体没有的字形（`▸ ✦ ♥` PingFang 全无）
  收进字库只会得到隐形符号 —— 改用 `pixelart.py` 算法生成或手绘
- `docs/pages/` 是**生成的**，改文案要改 `sim/strings.py` 再跑 `gen_pages.py`
