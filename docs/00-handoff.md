## 一、这是什么项目

在一台 **ESP32-C3 掌机**上做宝可梦风格的真实世界探索游戏，自用、不分发。

硬约束（见 [01-constitution.md](01-constitution.md)）：

| 项 | 值 | 后果 |
|---|---|---|
| 屏幕 | 240×320 彩色 | 整帧 RGB565 = 150 KB，**装不下**，必须分块横带渲染 |
| 按键 | **只有 A/B/C 三个** | 所有交互的第一约束。取名、翻页、导航都受它限制 |
| SRAM | ~400 KB | 上面那条的原因 |
| flash | 8 MB | 宽裕。资产才用了 149 KB |
| **无 GPS** | | 用 WiFi 环境指纹替代 —— 这是整个项目的技术核心 |
| **无 IMU** | | **步数不可实现**，所以用「移动量」而非步数 |
| 无内置 DAC | | 音频只能 PWM 或 I2S，指向实时 chiptune 合成 |

核心设计取向（[02-sensing.md](02-sensing.md#20)）：
**让时间生产内容，让空间调制内容** —— 任何基于「见到新 BSSID」的指标都会衰减到零，
所以驻留也要有产出（基地按时间排程），出门只是更快（猎场按瞬现 AP）。

## 三、待办（按优先级）

### P0 — 挡住玩法闭环的两件事

**① 等级永不增长 —— 全项目没有经验值机制**

`grep exp / gain_exp / level_up / level +=` 在 `sim/` 下零命中。
主宠从 `run_intro` 拿到 Lv5，30 天跑下来还是 Lv5。

这不是「还没做的功能」，是**已写进设计的机制缺了实现**。六处都假设等级会涨：

| 处 | 假设 |
|---|---|
| [S3 文档](systems/S3-battle.md) | 明确写「练到 Lv30 能回头收拾 ★★★★」，还列了御三家成长曲线表 |
| `strings.py` | P3 文案有「经验」标签、P5 有「等级」 |
| `systems.effective_stat(base, level)` | 按等级算能力值 |
| `systems.wild_level(rarity, pet_level)` | 野怪等级跟主宠联动 |
| `gyms.level_cap(badges)` | 徽章解锁等级上限 |
| S7 的 `evolve_level` | 等级触发的进化条件 |

等级恒定 Lv5 让它们同时失去意义。**要先定经验曲线再实现** ——
打一场给多少、稀有度加权、要不要跟 `level_cap` 联动、升级回不回满 HP，
定错会连带影响战斗胜率、捕获窗口、道馆门槛三条链路。
`auto_battle()` 返回的 `BattleResult` 现在不含经验字段，实现的第一步是给它加。

**② 野外 biome 判不出来 → 八个道馆全部不可达**

`classify_biome` 里 `MIN_APS_FOR_BIOME = 4` 先返回 UNKNOWN，
于是后面的 `if n <= 3: return BIOME_WILD` **数学上不可达**（穷举 n=0~8 验证过）。
三份真实数据 1061 次扫描里野外出现 **0 次**。

第 1 馆（小刚，野外 1h）与第 5 馆（阿桔，野外 8h）永久锁死，
而道馆是线性的 → 一个都打不了。这是第二个「分支存在 ≠ 会执行」。

**缺的是真实户外采集数据**。修法思路清楚（MIN_APS 那道防护不能拆，
它修的是「办公室 17% 扫描误判野外」；区分「真在空旷处」与「室内扫描不好」
只能靠持续性），但我试的两版阈值都是在拿合成数据的编造分布调参：

- 连续 N 次 UNKNOWN → 判不出。户外 AP 数在阈值 4 附近抖动，连续计数反复归零
- 滑动窗口占比 → 参数只能靠调

要做的：用 `tools/collector` 采一份户外数据（公园/街道各半小时）→
看 AP 数分布与 `family_ratio` → 定判据 → 验证真实办公/家数据不被误判成野外。
详见 `sim/orchestrate.py` 顶部「野外 biome 判定」那段。

### P1 — 规格待决

**③ ~~`text_px()` 的半宽假设与字库格式冲突~~ 已解**（2026-09-05）

选了「渲染器按字符类型决定步进」这条路。依据是实测墨迹范围：

    A x=2~11   [ x=6~9   0 x=4~11   % x=1~13

ASCII 字形全落在 x=1~13，**按 8px 步进只切掉右侧空白**，不动任何墨迹。
零字库改动、零格式变更，渲染器多一个 `cp < 0x80` 判断而已。

实现在 `firmware/main/render.c`，自检验两个数（56px / 184px）
与 `sim/strings.py` 的 `text_px()` 逐值相同，真机通过。

**④ 新地点心情加成 +12 偏高**

接进编排层后实测：19.9 小时发现 15 个新地点 → +180 心情，
而同期衰减只有 3.0 × 19.9 = −59.7。心情长期顶在 100 上限。

后果是 S4 的立意被抵消（照料变得没必要），且 S2 的 `catch_window_bonus`
挂在心情上，捕获窗口也长期最宽。该定多少是 S4 的平衡设计问题
（随「今天已发现几个」递减？跟 biome 稀有度挂钩？），见 `gameplay.on_new_place`。

**⑤ 五个系统在完整流程里不记日志**

试玩后台的覆盖标签直接显示（红色 ✗）：S8 闪光、S12 取名、S14 队伍、S17 道馆
（S7 进化已修）。S14 明明在工作（队伍 6 只、仓库 30 只）却无日志 ——
要么该加 `s.say()`，要么确认它本就不该有事件。这是查孤岛的线索，不是结论。

**⑥ `on_reunion()` 零调用**

P5 有「好久不见」文案，但没有触发点。它要「设备离线多久」
（不是「这个地点多久没来」），需要开机时对比上次关机时间 ——
属于 `run_intro` / 存档恢复路径。

**⑦ 商业区访问速率是估的**

第 6 馆要「去商业区 4 次」，按「每周 2~3 次商场」估成 0.4 次/天 → 10 天。
**但真实采集里商业区只占 0.8%，19.9 小时内一次都没确认过访问。**
要用更长的真实数据验证。

**⑧ 交通枢纽等 BLE**

`classify_biome` 的交通枢纽分支要 `ble_count > 10`，而采集工具不输出 BLE、
5 处调用全不传 —— 死代码。ESP32-C3 有 BLE，固件阶段能扫到时它会自动开始工作。
PC 侧若要提前验证，得给 `tools/collector` 加 BLE 扫描。

### P3 — 需要真机

**设备已到手** —— FoloToy AI Passport（ESP32-C3），串口调试已通。
一条命令看硬件事实：`python3 tools/device/monitor.py --info`
（只要 pyserial，不用装 ESP-IDF）。详见 [09-device.md](09-device.md)。

**已结案**（真机启动日志实测）：

| 原待办 | 结论 |
|---|---|
| 音频通路 PWM 还是 I2S | **ES8311 codec + I2S 全双工**，还能录音。原文档「无 DAC 只能 PWM」是错的 |
| 是否有耦合电容 | 有专门的 codec，这条不再是问题 |
| 屏幕型号 | ST7789P3，SPI 40MHz，出厂需反色 |
| 三键够不够用 | BSP 提供 PRESS/CLICK/DOUBLE/LONG 四种事件 → **12 种输入** |
| ~~约 400KB SRAM~~ | **实测可用堆只有 187 KB**。全屏帧缓冲 150KB = 80% 的堆，分块渲染这条更硬了 |

**仍待实测**：

| 项 | 卡住了什么 | 怎么测 |
|---|---|---|
| 续航天数 | 扫描频率上限 → 遭遇频率、地点时间分辨率 | **不用电流表** —— `bsp_battery_soc()` 定时采样 |
| RTC 走时精度 | 状态轴是「小时」级还是「天」级；S10 日切判定 | 深睡 12 小时对比 |
| 外置 32.768kHz 晶振 | 同上 | 查 sdkconfig 的 RTC 时钟源，或实测漂移 |
| NFC 芯片型号 | 能否用 NFC 对时 | 手机 NFC Tools 读。**BSP 引脚表里没有 NFC** → 倾向静态标签 |
| 口袋 RSSI 基线 | 阈值标定 —— 现在用的是电脑天线数据 | 有设备了，装兜里跑一轮采集 |

固件实现顺序见 [07-roadmap.md](07-roadmap.md) 的 F1~F14。
**F5 是关键一致性检验**：把 `data/raw/*.ndjson` 灌进固件，
它应当算出与 `sim/replay.py` 完全相同的状态序列。

## 四、已修掉的缺陷（避免重复踩）

## 六、几条容易忘的项目惯例

- **数值不手填**，从 pret 反汇编取（`data/trainers/parties.asm` 等）
- **页面改动要真开浏览器验**，`node --check` 通过不代表画对了
  （栽过：网格渲染成单色、精灵球画成矢量圆、星星形状错；
  这轮又栽一次：三栏布局把「总览」推到折叠线下，assert 失败才发现）
- 提交消息用 `git commit -F 文件`，正文里的 `"<HBB..."` 会被 shell 当命令替换
- 中文名用**任天堂官方译名**（zh_nin），不是动画代理译名
  （徽章是**颜色名**：灰色徽章而非岩石徽章，从英文回译八个全错）
- **字库改完跑 `convert_font.py` 再跑 `inventory_assets.py`** ——
  后者是断言，退出码 0 才算过。光看「字数在涨」不算验证：
  港台字形那次 27% 的字形是错的，而所有统计指标都正常
- **新系统若有上屏文案，必须给它加 `charset()` 并登记进
  `convert_font.py` 的 `SOURCES`** —— 这条漏了三次（S17 漏 29 字、
  S14/S2·S7/S18 漏 16 字、`strings` 自己漏了 `KEYS` 的键名 5 字）。
  注意不只是 `strings.py` 那种集中文案：dataclass 字段默认值、
  函数动态拼的菜单项、失败提示的 `reason` 串全都算
- **PingFang.ttc 必须传 `index=2`**（SC 简体）。默认 index 0 是香港繁体，
  用它渲简体的后果是「鉴」全空 + 142 个字形是港台写法
- **点阵要看 ASCII 预览**。字体没有的字形（`▸ ✦ ♥` PingFang 全无）
  收进字库只会得到隐形符号 —— 改用 `pixelart.py` 算法生成或手绘
- `docs/pages/` 是**生成的**，改文案要改 `sim/strings.py` 再跑 `gen_pages.py`
