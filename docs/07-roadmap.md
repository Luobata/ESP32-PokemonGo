# 七、推进节奏

整体原则是**感知层验证先行，美术最后动工**。

## 7.0 当前状态：硬件未到，Phase 0 阻塞

需要如实标明的一点：**本文档中形态、数值与内容量级的结论，
几乎全部以 Phase 0 的实测数据为前提。**

硬件到手前，下列问题都还没有答案，任何依赖它们的设计都属于**待定而非已定**。

| 阻塞项 | 卡住了什么设计 |
|---|---|
| 续航天数 | 扫描频率上限，进而是遭遇频率与「地点」的时间分辨率 |
| 三态判别稳定性与转换误报率 | 猎场/基地结构能否成立；若误报高则 [4.1.1](04-gameplay.md#411-猎场与基地) 需要重做 |
| RTC 走时精度 | 状态轴是「小时」级还是「天」级；昼夜上下文能否保留 |
| 口袋 RSSI 基线 | [2.4 的权重曲线](02-sensing.md#24-匹配算法与两级扫描)与匹配阈值，目前全是估算值 |
| 真实环境 AP 密度 | biome 数量，进而是所需美术资产量 |

因此当前阶段的正确做法**不是继续细化设计**，而是把不依赖硬件的工作前置。
这些工作的共同特征是：可以在 PC 上完成、产出物在硬件到手后能直接复用、
**且不会因为实测数据推翻设计而白做**。

## 7.1 硬件到手前可做的四件事

### ① 仿真器与回放框架（价值最高）

这本是[第六章](06-engineering.md)的工作项，但它恰好完全不需要目标硬件 ——
**用笔记本电脑扫 WiFi 就能产出格式相同的数据。**

先用电脑采集家、公司、通勤沿途的真实 AP 数据，落成回放集，
然后在 PC 上把匹配算法、迟滞逻辑、状态机全部调通。
硬件到手时，固件只需替换数据来源。

**额外收益：这批数据能提前回答上表里的两个问题** ——
真实环境 AP 密度、三态判别可分性。

> **已知障碍：macOS 12+ 对 BSSID 有定位权限门禁。**
> 无授权时 `bssid`/`ssid` 全返回 nil，只剩 RSSI 和 channel。
> 已实测本机为 `notDetermined` 状态。
> 解决方式与降级模式见 [tools/collector/README.md](../tools/collector/README.md)。

### ② 素材管线

[5.3](05-art-audio.md#53-素材来源) 已确认以 Tuxemon 的 411 个怪物 YAML 与
DawnLike 精灵图为数据底座。这批转换工作完全在 PC 上进行：

- YAML → 紧凑二进制表
- 精灵图 → 2bpp 四阶灰
- 中文点阵字体子集化
- 按 8MB flash 预算做容量核算

**产出物与硬件无关，且工作量不小，适合现在做。**

### ③ PC 端玩法原型

把养成状态机（三条状态轴的推进与恢复）和遭遇判定逻辑写成纯逻辑程序，
用仿真器的回放数据驱动，在终端里跑。

这能提前暴露调参问题 —— 例如状态下降速率是否合理、
遭遇频率在真实通勤数据下是多少。

**杠杆很大：这些问题在硬件上迭代一轮要一天，在 PC 上是几秒。**

见 [`sim/prototype.py`](../sim/prototype.py)。

### ④ 视觉规范定稿

[5.1](05-art-audio.md#51-视觉规范) 列出的待定项中，
**只有一项真正被硬件阻塞**（240×320 是等比放大留黑边还是全屏重设版式，
这需要上手看实际观感）。

其余 —— 调色板选择、tile 尺寸、精灵尺寸档位、中文点阵字体的 flash 占用核算
—— 都可以现在定，并且可以在 PC 上用模拟器窗口预览。

## 7.2 Phase 0：硬件到手后的第一周

**只做感知层验证，不写任何玩法。**

写一份最小固件，全程不联网、只做被动扫描：

- 每 30 秒记录一次 BSSID 集合（含 RSSI 排序）、SSID 列表、OUI 分布与时间戳
- 工作集放 RTC slow memory，仅在状态转换与每小时提交 flash
- 屏幕显示当前判定状态（家/公司/移动中）、今日转换次数与各态驻留时长

然后**揣在兜里过一周正常生活**，同时实测电流曲线与 RTC 漂移。

### 验证目标

不再问「能识别多少个地点」—— 真实环境下答案就是三四个，这不是需要验证的事。
**要问的是这三态判别是否稳定、以及转换检测有多少误报。**

| 待测项 | 判定标准 |
|---|---|
| **三态判别稳定性** | 家/公司/通勤能否被可靠区分，回到熟悉地点是否稳定命中 |
| **转换检测误报率** | 迟滞两次的规则下，静坐时是否会被误判为「在路上」 |
| **口袋 RSSI 基线** | 装兜里与放桌上的 RSSI 差值有多大，相对排序是否比绝对值稳定 |
| **RTC 走时误差** | 一周累积漂移多少，决定昼夜上下文能否成立 |

此外仍需实测**该扫描占空比下的续航天数**，
并验证两级扫描（0.3 秒确认 + 1.4 秒完整）与自适应占空比能把功耗压到什么程度。

## 7.3 Phase 0.5 与 Phase 1

**Phase 0.5：** 把这周的真实设备数据并入回放集
（此时可以和 PC 采集的数据对比，标定 [2.6 的口袋偏差](02-sensing.md#26-口袋标定一个会坑人的实测陷阱)）。
此后所有平衡性调整都在 PC 上迭代。

**Phase 1：** 设计宪法定稿（一页纸），之后玩法策划才正式开始。

> **Phase 0 之前不要做任何美术。**
>
> 感知层的真实能力决定 biome 数量与属性划分，而这直接决定需要多少美术资产。
> 反向推进会导致大量返工。
>
> （例外是 7.1 ④ 的规范定稿 —— 定规范不等于画素材。）
