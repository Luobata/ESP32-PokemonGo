## 7.1 感知层：四轮实测修正的记录

这一节值得单独留着 —— **每一轮都是真实数据推翻了纸上设计**。

| 轮次 | 发现 | 修法 |
|---|---|---|
| ① | 静坐 20 分钟报 11 次状态转换、30% 误判移动 | 滑动窗口出现率（窗口 4） |
| ② | 窗口平滑把通勤的渐变也压低，沿路建 5 个地点 | 加 AP 新鲜度作第二判据 |
| ③ | 公司 27% 扫描只有 ≤4 个 AP，仍误判 34 次 | AP < 5 时不信距离 |
| ④ | 加了③仍有 15 次，且新鲜度全为 0 | 新鲜度为 0 时否决距离 |

最终三份真实数据全部达标（详见
[2.4.3](02-sensing.md#243-稀疏环境的两条防护公司数据暴露的)）。

第 ④ 轮的洞察值得记住：**「一个新 AP 都没见到」比「指纹变了多少」是更硬的证据** ——
真在移动一定会撞见没见过的 BSSID。这条比窗口平滑更本质，
加上它之后连窗口 1 都从 60% 误判降到 1%。

## 7.2 玩法系统：三处实测暴露的平衡缺陷

同样是跑起来才发现的（详见
[S3-battle.md](systems/S3-battle.md)）：

| 缺陷 | 后果 | 修法 |
|---|---|---|
| 野怪等级跟着主宠涨 | 主宠 Lv40 打 ★★ 照样输 —— **练级毫无意义** | 绝对等级带（★=5 … ★★★★★=45） |
| 种族值不随等级成长 | 等级只是个数字 | `effective_stat = base × (1+Lv/50)` |
| `capture_rate` 直接当像素 | 皮卡丘撞满 200px 上界，球种与养成加成全失效 | `BASE_SCALE = 0.55` |

修完后成长曲线才成立：小火龙→★、火恐龙→★★、喷火龙→★★★★，
而 ★★★★★ 连 Lv45 喷火龙也打不过 —— **传说级需要更多投入，这个留白是有意的**。

## 7.3 Phase 0 剩余部分：硬件到手后的第一周

**只做感知层与硬件验证，不写玩法**（玩法逻辑已在 PC 上验证过）。

写一份最小固件，全程不联网、只做被动扫描：

- 每 30 秒记录 BSSID 集合（含 RSSI 排序）、SSID、OUI、时间戳
- 工作集放 RTC slow memory，仅在状态转换与每小时提交 flash
- 屏幕显示当前判定状态、今日转换次数、各态驻留时长

然后**揣在兜里过一周**，同时实测电流曲线与 RTC 漂移。

### 验证目标

| 待测项 | 判定标准 | 影响 |
|---|---|---|
| **续航天数** | 该占空比下能撑几天 | 决定扫描频率上限 |
| **RTC 走时误差** | 一周累积漂移多少 | 决定 S4 时间尺度、S10 日切判定 |
| **口袋 RSSI 基线** | 装兜里与放桌上的差值 | 重新标定 [2.4](02-sensing.md#24-匹配算法与两级扫描) 的权重曲线 |
| **两级扫描效果** | 0.3s 确认 + 1.4s 完整能省多少 | 验证自适应占空比 |

**PC 侧的算法可以直接搬** —— `sim/sensing.py` 刻意保持在
可用定点整数重写的范围内（无浮点必需、无动态分配、状态量定长）。

### 口袋标定的做法

同一地点、同一时段，各采 20 分钟：

```bash
tools/collector/collect.sh -i 30 -o data/raw/desk.ndjson     # 桌面基线
tools/collector/collect.sh -i 30 -o data/raw/pocket.ndjson   # 装兜里
```

对比两份的 RSSI 分布差值，用它修正 `RSSI_FLOOR` / `RSSI_CEIL`。
更稳的做法是**不依赖绝对值、只用相对排序**（见
[2.6](02-sensing.md#26-口袋标定一个会坑人的实测陷阱)）。

## 7.4 固件实现顺序

硬件到手后按这个顺序，每步都有可验证的产出：

| 步 | 内容 | 验证方式 |
|---|---|---|
| F1 | 点亮屏幕 + 三键输入 | 按键有反应 |
| F2 | 分块横带渲染 + 载入 sprite | 屏幕上出现皮卡丘 |
| F3 | 中文点阵渲染 | 显示「妙蛙种子」 |
| F4 | WiFi 被动扫描 + 落盘 | 串口 dump 出 NDJSON，格式与 PC 侧一致 |
| F5 | 移植 `sensing.py` → 定点整数 | 同一份数据，固件与 PC 算出同样的判定 |
| F6 | 深睡 + RTC + 唤醒 | 实测续航与漂移 |
| F7 | 存档双 buffer + CRC | 拔电测试不丢档 |
| F8 | P1 待机页 + S4 养成 | **最小可玩闭环** |
| F9 | P2/P3/P4 + S1/S2/S3 | 完整收集循环 |
| F10 | P5/P6/P7 + S5/S9/S10 | 全功能 |

**F5 是关键的一致性检验**：把 `data/raw/*.ndjson` 灌进固件，
它应当算出与 `sim/replay.py` 完全相同的状态序列。不一致就说明移植有偏差。

**F8 是第一个「能玩」的里程碑**。它独立于感知层与捕获战斗，
且已经是完整体验 —— Tamagotchi 的空间输入是零，照样能撑几个月。
