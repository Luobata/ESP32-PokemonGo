## 2. gen1.bin —— 物种基础数据表

头部 16 B（`<4sHHII`）+ 151 × 32 B 记录 + 2,456 B 字符串池。
**头部声明的池大小 2,456 与实际尾部长度完全一致**，无截断无冗余。

### 2.1 记录字段（逐字段解出，`<HBBBBBBBBBBBBBBHHHBB8s`）

| 偏移 | 字段 | 实测结果 |
|---:|---|---|
| 0–2 | `name_offset` / `name_len` | slug **151/151 全有**，无重复 |
| 3–4 | `type_primary` / `secondary` | 全部 < 15（初代 15 属性），**无越界** |
| 5 | `biome_mask` | **无一条为 0**（每只至少属一个 biome） |
| 6 | `capture_rate` | — |
| 7–9 | `evolve_trigger` / `to` / `level` | **70 只可进化** |
| 10–14 | 种族值 HP/攻/防/特/速 | **无一条全零**（151/151 已填） |
| 15 | `flags` | 传说 4 只（#144 #145 #146 #150）、幻兽 1 只（#151） |
| 16–19 | `height` dm / `weight` hg | — |
| 20–22 | `zh_offset` / `zh_len` | 中文名 **151/151 全有** |
| 23 | `palette_index` | 低 4 位用 0–9；**高 4 位（预留）全部为 0** |
| 24–31 | `reserved` 8 B | **151 条全部为 `\x00`，未被污染** |

传说 4 只是三圣鸟 + 超梦、幻兽 1 只是梦幻 —— 与初代设定吻合。

### 2.2 交叉自洽

- 中文名共用 **209 个不同汉字**。
- `flags` bit2-3 的 front 尺寸档分布：**40×40 → 48 只，48×48 → 48 只，56×56 → 55 只**
  （48+48+55 = 151）。与 `gen1_front.bin` 三段的实际条目数**逐档相等** ——
  两个独立文件互相印证，说明尺寸档写入与图集分段用的是同一份数据。
- biome 分布（一只可属多个，故合计 > 151）：
  野外 116、住宅区 41、商业区 27、办公区 21、交通枢纽 16。

## 3. gen1_front.bin —— 151 只齐全，无空洞

分段结构：头 8 B（`<4sHH`）+ 3 × 12 B 段头（`<HHII`）+ 段数据。
每项 = 2 B 显式 id + 位图（分段后 id ≠ 段内下标，所以必须显式存 id）。

| 段 | 尺寸 | 只数 | 单张 B | 期望 `(size²×2+7)//8` | 段计 | id 升序 |
|---:|---|---:|---:|---:|---:|---|
| 0 | 40×40 | 48 | 400 | 400 ✅ | 19.2 KB | ✅ |
| 1 | 48×48 | 48 | 576 | 576 ✅ | 27.6 KB | ✅ |
| 2 | 56×56 | 55 | 784 | 784 ✅ | 42.1 KB | ✅ |

- **151 只齐全**：id 集合 = {1..151}，**缺 0、重复 0、越界 0**。
- **空洞 0**：无任何全零条目。（转换失败会留 `bytearray(per)` 占位 ——
  `convert_gen1.py:356` 对 back 就是这么做的 —— 这里一个都没有。）
- **尾部余 0 B**：段头声明的偏移与长度把文件字节**恰好用完**。

## 4. gen1_back.bin —— 尺寸统一

头 16 B（`<4sHHHHI`）：`32×32`，单张 **256 B**（= 32×32×2/8 ✅），**151 张**。

- **尺寸统一 32×32**：头部即定长声明，且 `16 + 151×256 = 38,672` = 文件大小，
  **尾部余 0 B**。
- **空洞 0**：151 张全部有内容。

后三行是**独立于各模块 `charset()` 的旁路校验**：直接遍历 `Gym` dataclass 的
字符串字段、抄 `GymCheck.reason` 与照料结果的字面量取字，用来查各模块的
`charset()` 自己是否漏了某个上屏字段。三条都是 0 缺失，说明覆盖是完整的。

### 7.1 根因回顾：来源登记表是这条链上唯一的单点

`convert_font.py` 的 `SOURCES` 表现已登记七个模块：

```
strings / naming / opening / gyms / party / systems / state
```

清点开始时只有前三个。**漏登记的后果是静默的**：字数统计、文件大小、
`charset.txt` 一致性检查全部正常，只有真机点亮走到那个菜单才看到一片空白 ——
与 `sim/strings.py:9` 自己写的「字库没收的字在屏幕上是一片空白」完全同构。

`sim/` 下七个模块现已全部提供 `charset()`。**新增系统若有上屏文案，
必须同时做两件事**：给模块加 `charset()`、登记进 `SOURCES`。
漏掉任一件都会重现这个缺陷。

### 7.2 建议：把这条差集做成 CI 断言

这个坑在清点期间踩了两次（先 `gyms` 缺 29 字，修完又发现
`party`/`systems`/`state` 缺 16 字）。根本原因是**没有任何自动化检查在守这条不变量**。

建议把「全部上屏文案来源的字符集 − 字库」断言为空集接进 CI。
本报告的 `crosscheck()` 可以直接当这条断言用 —— 它枚举来源时**不依赖
`convert_font.py` 的清单**，所以能查出「模块忘了登记」这一类
`convert_font.py` 自己查不到的问题。

| 时刻 | 字形数 | md5 | 状态 |

清点报出的三个问题及其归宿：

1. **道馆 29 个汉字缺失**（八个馆主名、八个城市名、八个徽章名、四天王、赤红）
   —— 根因是 `gyms` 未登记进 `SOURCES`。**已修**：加了 `gyms.charset()`、
   登记进 `SOURCES`，并把原先五个 import 共享的一个 `except ImportError`
   改成逐模块 try（原写法下任一模块失败会丢掉**全部** UI 字，只打印一行警告）。

2. **「鉴」字形全零** —— 根因是 `ImageFont.truetype(path, size)` 没传 `index`，
   Pillow 默认取 `PingFang.ttc` 的第 0 面 = **PingFang HK（香港繁体）**，
   它不含简体「鉴」。我逐面实测确认：index 2 / 5（PingFang SC）有字形，
   index 0/1/3/4（HK/TC）没有。**已修**：`FONT_CANDIDATES` 改成
   `(路径, 子字体索引, 名称)` 三元组并显式指定 index=2，
   还加了 `SANITY_CHARS = "鉴龙"` 自检 —— 渲不出就换下一个候选字体。

   队友修这个时发现的比我报的更严重：除「鉴」全空之外，
   **另有 142 个字形被渲成港台写法**（「龙」少一横、走之底笔形不同、
   标点繁体居中），合计约 27% 的字库是错的，而字数统计、文件大小、
   缺字差集**全都正常** —— 只有把字形逐个画出来对比才看得见。

3. **`party` / `systems` / `state` 缺 16 字**（`两主仓份会入加坏备存宠库损槽用设`）
   —— 与第 1 项同构：三个模块有上屏文案但既无 `charset()` 也未登记。
   受影响的是「设为主宠」「存入仓库」「加入队伍」「仓库满了」「这只不会进化」
   「主槽 / 备份槽 / 两份都损坏」。**已修**：三个模块各加 `charset()` 并登记进
   `SOURCES`，字库 529 → 545，缺字归零。

4. **`✦` 无字形** —— 我实测 PingFang 全部 6 面都没有 U+2726，换 index 无用。
   **已按「不上屏就不收」处理**：从符号集移除，理由是它只出现在
   `orchestrate.py:327` 的 CLI 日志与 inspector 网页上（`replay.py:90` 同理），
   设备上的闪光标记走 `sim/pixelart.py::star()` 点阵生成。
   这与 `menu_cursor()` 的处理一致（`▸ ▶ ►` 三个符号 PingFang 也全无字形）。

## 8. eye_regions.json —— 覆盖全但可用极少

顶层 `{_meta, regions}`，`regions` 以字符串 id 为键。

| 项 | 实测 |
|---|---|
| 条目数 | **151（id 1–151 全覆盖，缺 0）** |
| 针对 | `sprite=back`，`size=32`（**背面图**，非正面） |
| status 分布 | `hidden` 121、`ambiguous` 29、**`visible` 仅 1** |
| 置信度分布 | `high` 121、`low` 29、`medium` 1 |
| **实际有 boxes 的** | **仅 #137 多边兽，共 1 个框** |
| `_meta.counts` 声明 vs 实测 | **一致** ✅（121/29/1 逐项吻合） |

**这不是格式缺陷** —— `_meta.caveat` 写明：只有 `status=="visible"` 的条目
能驱动眨眼，其余 150 只的 `boxes` 一律留空，避免压暗错误区域。
`_meta` 的手写声明与 `regions` 的实测统计一致，没有漂移。

但要注意实际后果：**眨眼动画对 151 只里的 150 只是无效的**，只有多边兽会眨眼。
这是标注阶段的结论（背影多数看不见眼睛），若与设计预期不符，
需要重做标注而非改代码。

## 11. 解析脚本

[`tools/pipeline/inventory_assets.py`](../tools/pipeline/inventory_assets.py) —— 725 行，零第三方依赖
（仅「空字形成因诊断」一节需要 PIL，缺 PIL 时自动跳过并说明原因）。

设计要点：

- **不复用 `tools/inspector/build.py` 的 loader** —— 那些 loader 已假定格式正确
  （magic 不对就抛异常）。清点需要的是独立重解：按 `convert_*.py` 写死的头部
  布局硬解，再拿解出的数字与文档对账。
- **不只验结构，也验内容** —— `content_check()` 统计每张位图的四阶色号直方图，
  因为长度对、magic 对的纯色块同样能通过结构校验。
- **头部声明 vs 实际字节** —— 每个文件都算 `trailing_bytes`，非 0 即声明与实际不符。
- **空字形分两类归因** —— 「某些 face 有字形」（选错 face，传 index 可修）与
  「所有 face 都没有」（字体不含，须点阵生成或换符号），两者修法完全不同。
  这个区分正是定位「鉴」与「✦」根因的关键。
- **符号集从源码抓取而非抄写** —— 抄一份的后果实测过：队友把 `✦` 移出符号集后，
