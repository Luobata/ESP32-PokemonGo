# 第二世代扩展：251 只伙伴与城都玩法

状态：2026-10-05 设计及代码影响核查，未实现、未打包、未烧录。与 [中期地图/副本扩展](midgame-expansion.md) 配套。目的为延长已有玩家的培养与收集目标，而不是要求重新开档。

## 内容基准

扩展编号 152～251，共新增 100 只，保留原 1～151 编号与个体。美术、基础数据和新增物种学习表以固定版本的 Crystal 数据为基准，逐项记录与本作简化规则的差异。[物种及形态常量](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/constants/pokemon_constants.asm)

保留当前自动选招、无 PP、已学会招式不限四格、独立渠道闪光率及统一经验曲线。暂不引入装备携带、个体值刷取、性格、特性或复杂遗传。遵循该世代属性规则，不从现代资料误导入妖精属性和后续世代进化。

现有游戏已经有 17 属性、分离特攻/特防和金银式伤害核心；任务是补齐物种数据、机制和表现，不应重写已经验证的战斗底层。原作物理/特殊按属性划分，恶为特殊、钢为物理，需和当前兼容编号映射核对。[原作属性定义](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/constants/type_constants.asm)

## 玩家新增的七类目标

| --- | --- | --- |

| 新生态地区 | 栎树林、愤怒之湖、冰雪小径、阿露福遗迹、烧焦塔/铃铛塔、漩涡列岛等主题分批开放 | 每地有探索、事件和主题挑战；与已设计的原野、矿坑、龙谷等共用地区框架 |
| 跨世代进化 | 大钢蛇、巨钳螳螂、刺龙王、叉字蝠、幸福蛋、太阳/ 月亮伊布等 | 仓库里的旧伙伴成为新培养目标，不必全从抓新宠开始 |
| 托管孵蛋 | 探索/研究获得一枚蛋，照料与有效冒险行动推进孵化 | 幼年伙伴和城都初始伙伴具有稳定来源；不再增加“孵化体力” |
| 城都对手 | 城都馆主、研究员和区域精英作为调查挑战，按内容逐步开放 | 新徽章独立登记，不复用关都八枚的 bit；不要求旧玩家重打一遍低等级八馆 |
| 传说调查 | 烧焦塔线索、三兽追踪、双塔/海渊挑战、森林时空调查 | 有长期剧情步骤与固定捕获机会，不混入普通高星抽取 |
| 收集记录 | 关都图鉴、城都图鉴、总图鉴、区域研究与异色收集 | 原有 151 收集成就及已领状态保留，新成就追加，不撤回奖励 |

这些地点是本作借用主题的内容设计，不声称照搬原作地图、遇敌分布或完整城都剧情。早期即可发现咩利羊、乌波等基础伙伴，中后期再发现进化形及珍稀伙伴；不能把全部 100 只安排在 Lv60 后。

## 进化要从单目标改为规则表

现有 `species_t` 只有一个 `evolve_to`，进化触发类型只覆盖等级/道具/交换；无法完整表达多分支、亲密度和昼夜条件。使用声明式进化列表，一个物种可对应多个条件和目标，界面展示具体要求与可选结果。原作确有亲密度、时段和攻防关系分支。[进化/学习规则表](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/data/pokemon/evos_attacks.asm)

本作适配如下，属于设计选择，不冒充原作机制：

- 亲密进化接入当前每只伙伴保存的亲密度，照料和参战均可推进；满足后提示，暂缓不丢资格。
- 太阳/月亮伊布优先使用可信时钟的晨日/夜晚条件；未校时显示时间不可用，并提供研究解锁的明确进化方向替代，不能永远卡住离线玩家。
- 太阳之石、金属膜、王者之证、龙之鳞片、升级数据直接作为消耗式进化道具。图鉴指明来源，在相关地图研究或副本首通给稳定获得机会；无需装备或真实通信。
- 旧进化路径保留：例如蚊香君、呆呆兽、臭臭花、伊布存在不同结果，满足多个条件时先选择再确认，消耗道具与进化原子保存。
- 无畏小子的攻防分支不能照搬当前固定 DV、无能力培养的数值：它可能永远只走同一个结果。采用格斗训练事件选择培养方向，或有明确来源的进化训练选项；不是临时按当前强化状态随机决定。
- 用一张可达性表检查每条新进化边，包括前置伙伴、道具/亲密要求、开放章节与取消恢复。玩家不必查攻略猜为什么不能进化。

## 孵蛋保留发现感，先简化繁殖

第一版做托管蛋和照料孵化，提供皮丘、皮宝宝、宝宝丁、波克比、无畏小子、迷唇娃、电击怪、鸭嘴宝宝等来源。物种及闪光结果在拿到蛋时确定并保存，反复重启、切托管栏不能重抽。孵化是新个体入队/仓库的事务，满仓库时保留蛋及待孵化状态，不丢失。

原作繁殖涉及性别、蛋组及继承等规则；完整复制会新增大量玩家需要理解的条件。本作首版不要求配种、孵化器、遗传招式或个体值，后续若加入配种，应作为自愿的定向获取方式。[原作繁殖实现](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/engine/pokemon/breeding.asm)

性别不用于首版配种，但招式若依赖性别就不能忽略这个维度。迷人等招式需要保存正确的性别/无性别状态及相应判定，或者明确延后开放该招式并保证学习表仍有可用招式；不能给它一个始终无效的占位实现。新增个体字段须版本化，旧伙伴采用稳定的迁移默认规则，重启不能重新随机。

## 战斗、自动选招和动画

当前招式集合为初代 165 招加选定的 26 招，共 191 招；最大调度 ID 为 250。原作招式编号还包括 251（围攻），因此既要检查数量上限，也要检查 ID 范围，不能只添加新物种记录。[原作招式编号](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/constants/move_constants.asm)

优先补能改变配队的机制：雨天/晴天/沙暴、守住/看穿、撒菱/高速旋转、接棒、诅咒、预知未来、反射类招式、锁定与延迟结算。天气属于战斗场地，不能只在招式动画里画雨；对野生、训练家和秘境必须使用相同结算。沙暴等效果要核对该世代规则，不能默认套用后续世代效果。

按“数据 → 战斗效果 → AI 能理解 → 动画/音效 → 可验收场景”一起开放。对于减 PP 等与本作无 PP 规则冲突的招式，单列适配规则；没有实际意义的效果不能装作已经支持，自动 AI 也不能反复选择空效果。经典 TM/HM 招式继续通过等级/成长资格自动加入，不增加主动学习流程。

新增物种最少要覆盖三个特殊验收组：

| 伙伴 | 直接套现有系统的问题 | 需要增加 |
| --- | --- | --- |
| 未知图腾 | 主要依赖觉醒力量；当前不保存原作 DV，无法直接得到完整原作变化 | 明确并持久保存本作的觉醒属性规则、招式效果、原作 A～Z 形态；保留单物种图鉴口径 |
| 图图犬 | 不能仅按物种/等级重新算通用学习表 | 写生记录属于个体，按允许规则自动学习实际观察到的招式，持久保存去重集合，不重新引入四格遗忘 |
| 果然翁 | 反击型招式不适用普通“优先选高伤害”评分 | 根据已发生的战局与可见信息选择反击，不偷看下一招；镜像/免疫/回复循环有明确结束保障 |

这些学习表特例可在原始数据中核对；不能将它们当作“会挣扎就算可玩”。自动 AI 回归同时覆盖反击、连续保护、无限回复、免疫和双方没有直接攻击的局面。[特例学习表](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/data/pokemon/evos_attacks.asm#L2569)

第一世代原有技能资格不能在更换到 Crystal 数据时被悄悄删除。新增物种以固定 Crystal 学习表为基准；旧 151 的已经开放资格保留并核查原有金银适配策略。所有实际开放技能均进入后台验收页，覆盖双方施放、命中/落空/免疫、HUD 叠加、原速和音效。

## 数据、仓库和存档是必做项

| 当前代码情况 | 扩展要求 |
| --- | --- |
| `DEX_SPECIES=151`，四张图鉴位图每张 19 字节 | 251 只每张至少 32 字节；新增部分默认未见，原 151 的见过/捕获/闪光记录保持 |
| `BOX_SPECIES=151` 同时控制仓位数量与物种校验 | 拆为物种上限、仓位容量两个概念；目标至少 300 个仓位，实际容量须通过 RAM/NVS 验证后确定 |
| 仓位计数及 UI 索引部分为 `uint8_t` | 超过 255 仓位时改为明确宽度的新格式，不能发生计数回绕；新增城都/属性/未获得/闪光/进化线筛选 |
| `mon_t` 以 8 位物种号和 12 字节记录持久化 | 251 本身仍能放入 8 位，不能以此断言整体兼容；形态、性别、个体招式等独立版本化，不挤旧 flags/填充 |
| 队伍捕获合并优先比较同种的闪光和等级 | 未知图腾不同形态及个体写生不能被当成较差同种覆盖；确认个体身份、重复收纳和满仓库策略 |
| 战斗/图鉴/进化/名称/动画/来源审计多处硬编码 151 | 建统一物种目录和显式支持集合，运行时、生成器、网页预览与检查脚本同步扩展 |
| 旧 `save_v5_t` 等直接引用当前图鉴/队伍类型 | 先冻结每代真实布局，不能直接改宏导致全部旧结构随新类型变大 |

新增格式必须同时迁移世界存档、秘境运行存档、恢复凭据与特殊个体记录。世界和秘境的进行中战斗绑定规则版本，不能在导入后让旧招式/新字段被误解为损坏。原关都徽章、活动编号、道具编号、已有成就奖励不换号；城都进度追加。

新进化道具会扩大库存。库存嵌在多代存档和奖励凭据中，不能直接增大 `ITEM_COUNT` 后让历史类型也跟着改变。先冻结历史库存类型，再为新格式定义长度/版本与默认值；迁移后原有道具数量及待领凭据保持。

仍执行根目录 `AGENTS.md` 全部发布检查，保留 V5～V17 及届时新增格式的冻结样本。新增 251 边界、152/251 物种、未知图腾形态、图图犬记录、满仓库、进行中秘境和新道具待领奖样本。在线/离线导入均复用设备真实解码与迁移；同设备、布局、CRC/SHA、覆盖前备份和 ACK 保护不能放宽。

## 设备资源的实际约束

核查当前发布应用为 3,145,888 字节，factory 分区 3,407,872 字节，剩 261,984 字节，约 256 KiB。当前 151 只正背面资源共 177,722 字节，出场动画图集 86,583 字节。按当前均值线性估算，新增 100 只仅这两类内容约需 175,036 字节（171 KiB）；这是容量估计，未计入新地图、声音、招式、文字和额外形态，不能称为完整 251 只已装得下。

先做完整数据打包试验，检查图块去重、名称/脚本复用、压缩与解码开销；保持逐只取用的小缓冲，不将全部素材解压到 RAM。NPC、地图也共用图块，关闭调试信息不能代替实际资源预算。

当前 NVS 为 24 KiB，还要容纳世界、队伍、秘境、设置及垃圾回收写入。增加仓位时，测量多份运行时队伍快照的 RAM 和真实 NVS 的最坏写入空间；不能只看序列化文件大小小于分区。

优先保持现有分区位置和布局，继续支持当前只写应用的保档更新包。若压缩后仍必须改分区，这是单独的存储升级项目：完整备份、可回滚迁移、恢复工具和安装路径验证完成后才能发布，不能让现有更新 ZIP 绕过布局检查，也不能声称 8 MB Flash 的空白区域可以随意覆盖。

## 分阶段交付

1. **基础与容量**：冻结旧格式，建立 251 目录、资源清单、进化规则表和获取路径审计；打包完整资源验证容量，但不把未完成机制的物种投放给玩家。
2. **中期地图与第一批城都伙伴**：先实现前述海岛/高塔与稀有奖励，接入城都御三家、咩利羊/乌波等常规进化线，再加入若干旧宠新进化。优先解决 40 级玩家能立刻体验的目标。
3. **机制与收集**：孵蛋、昼夜适配、天气和新自动 AI；逐批完成剩余伙伴、地图与动画，明确展示当前已开放的物种范围，不虚称已经可收齐 251。
4. **特殊伙伴与长期挑战**：未知图腾、图图犬、果然翁先通过专门测试，再投放；接入三兽/双塔/海渊等传说调查、城都挑战和远征高难度。
5. **全图鉴完成门槛**：在无需联机交换、外部活动码或可靠联网时钟的条件下，证明每只已承诺开放的物种都有可达路径；完整 251 只及相应技能、正背面、普通/闪光颜色、出场动作和备份恢复全部通过后，才发布“251 只完整支持”。

优先级：先把新地图和稀有收集的回报做出来，再用第二世代扩展目标。携带装备、复杂繁殖、额外体力、强制每日任务都不是这次扩展成立的前提。
