# 肉鸽副本设计草案

> 2026-09-13 最新实现：P16 已改为自有随行队伍中选择 1～3 只，继承实际等级、自动技能池和闪光外观。下方的 Lv.50 租借方案是早期体验记录，已被替代。见 [自有伙伴验收](../../reports/dungeon-owned-2026-09-13.md)。


状态：已有网页体验版及设备上的独立演示版；下文涉及真实队伍、体能费用和正式奖励的内容仍为后续设计。

## 定位与入口

在「菜单 → 探索」增加「秘境挑战」。保留普通探索的收集、路线训练家的练级、道馆的主线推进；秘境提供每局不同的队伍搭配与连续挑战。沿用A上、B下、C确认、长按B返回；副本中返回不直接退赛，退出需要确认。

只使用全局体能：拟定每局入场20点、局内不再扣费，不新增门票、钻石、秘境币或独立体力。失败不退入场费，但保留已结算的阶段经验与道具。暂离可随时保存，回来续局，不重复扣体能。局内暂停不能通过外部照料或更换仓库成员刷新队伍。

## 首版：常青秘境

拟定第一枚徽章后开放，选已有伙伴中的3只出发。入口展示敌方等级范围、费用、规则与已选阵容。选择一项初始强化，沿8个节点前进；一次游玩时长目标10～15分钟，需实测自动战斗耗时后调整，不强制倒计时。

节点顺序限定为：普通战 → 分岔 → 普通战 → 营地 → 精英战 → 分岔 → 营地 → 首领战。每个分岔在战斗、事件、宝箱中提供两条可预览路线，保证至少两次恢复机会。首版不用地图大图或商店。

普通战以1～2只对手控制时长，精英战2～3只，首领3只。入口已选队伍与初始状态锁定；战斗之间保留HP和异常状态。入场可将局内战斗HP恢复满，代价已包含在入场体能里；饱食、心情及亲密度的既有加成在入场快照，不在长局中因后台计时骤变。

## 局内构筑

战后在3项强化里选择1项，首版约12项。强化只在本局有效，界面可随时查看效果，结束后消失；不变成新的资源。候选根据队伍与已选强化生成，避免三项都无效。同一强化的叠加次数与上限写明。

候选方向（数值待对战模拟）：

- 火系：火系伤害提高；首次造成火系伤害时尝试灼伤，不能无条件穿过免疫。
- 水系：水系招式命中后恢复少量HP，每回合封顶，不能形成永久回血。
- 电系：电系攻击强化，配合麻痹和速度；遵守属性免疫与异常状态规则。
- 异常：对已中毒、灼伤或麻痹的目标增伤，鼓励状态招式配合攻击。
- 接力：主动换宠后的首次伤害提高，每只伙伴每场触发一次，不能反复切换刷增益。
- 坚守：每只伙伴每场首次受到的伤害降低，保留被克制时的危险。
- 暴击：提高暴击机会，但不让伤害无限倍增。
- 续航：每次战斗胜利回复少量HP，不能让全队默认回满。

不增加技能PP、不要求玩家逐回合选招。自动出招AI能识别本局强化，例如异常增伤已成立后更倾向攻击，不反复施加同一种状态。玩家主要决定强化、出场伙伴和换人时机。

营地在「全队少量恢复／救起一只倒下伙伴／获得一次强化」中选择一项。恢复全部属于局内服务，不能带出或转成资源。首版不引入局内招募，避免临时伙伴和正式捕获混淆。

## 挑战来源

首版采用已有属性克制、状态、换宠与队伍搭配。首领具有明确队伍主题，例如草/毒与持续伤害；出战前提示主要属性和一条战术，让玩家有准备。AI只能依据公开战局，不偷看玩家本回合选择；状态、增益、回血和换人都需有触发上限。

普通敌人的等级以入场阵容和难度确定，本局不因玩家获得强化就继续追涨。具体等级偏移、伤害倍率和队伍组合用模拟校准；不能靠敌方超高HP延长对战。沿用伤害技能倾向和现有僵局处理，并增加低伤害/持续回复组合的副本回归。

难度使用已有徽章/联盟进度解锁：第一枚徽章普通、四枚徽章困难、冠军后极限。每档有明确敌人范围与首领奖励；不新增局外天赋点或永久数值树。重复游玩的差异来自敌人组合、分岔事件、强化搭配与首领轮换。

## 与现有系统联动

经验进入现有成长与分享经验流程；永久学招与进化仍由主系统负责。阶段经验战后结算，先存档再播动画，同一节点不能反复领奖。若局内升级改变战斗数据，沿用已有规则并验证HP处理；进化选择在退出秘境后提示，避免中途改写阵容快照。

基础战斗掉落球和养成道具，精英有进化石机会，首领从已有稀有道具池给奖励。按投入体能与耗时比较普通探索、切磋和秘境收益，避免秘境成为唯一最优练级渠道。首次通关可接入已有成就发指定道具，不新增成就货币。

通关后可提供一次奖励捕获，首版复用已有成功/失败捕获规则，不制造必抓到全部稀有宝可梦的捷径。限定为符合当前章节解锁的池；玩家已有的图鉴追踪与主线捕获途径继续有效。

失败保留阶段收益、不扣经验，不额外叠加全局体能处罚。临时强化清除，恢复到主游戏；是否沿用战败心情-5在实现时统一到现有结算，不能每只倒下都扣。

## 实现边界与验证

复用trainer_session的战斗和演出，但将秘境进度独立存储，不能伪装成某位道馆训练家、误发徽章或推进联盟。需要支持可配置敌人队伍与战斗修正；不要复制一套伤害计算或动画引擎。

保存局种子、节点、选路、三只伙伴身份与状态、强化、阶段领奖状态。所有随机结果先确定并保存，重启不会刷新三选一或奖励；所有入场/结算事务应可失败重试。引入新存档版本时保留既有图鉴、仓库、队伍、成就与体能，旧存档迁移后默认没有进行中的秘境。

验收覆盖：八节点全流程、不同构筑、强制换宠、暂停重启、存档失败重试、阶段收益只发一次、进化通知延后、全灭退出、无可用招式与持续回复僵局、普通战/精英/首领各类动画。网页预览与硬件使用同一规则和渲染代码。

首版范围为一个主题、八节点、约十二强化、少量事件、一个主题首领及续局。先验证一次完整循环是否有趣，再扩展主题与困难/极限变体，不同时堆入商店、货币、装备品质与天赋树。

## 首版可玩原型（2026-09-13）

入口：`http://127.0.0.1:8766/dungeon.html`，固件预览页顶部也有入口。启动：`python3 tools/inspector/server.py --port 8766`。

已实现六选三演示队伍（Lv.50）、八个节点、两次路线分支、两次营地、十二项互斥强化、精英和三伙伴首领。战斗沿用原生 C 引擎、绘制、招式与音乐；路线和强化选择暂用网页界面。生命和异常状态跨战斗保留，能力等级按每场战斗重新初始化。营地可以治疗、复苏第一只倒下的伙伴或研究强化。强化在本局结束后消失。

进度独立存于 `.build/dungeon-saves`，浏览器保存当前局标识。刷新后点“继续上次旅程”；服务重启后也能恢复。战斗恢复会重播出场，已结算的生命、随机状态、能力等级不重置。输入带版本号，旧请求不能重复领取强化。声音默认关闭，可手动开启原生战斗音乐。

边界：此版没有烧录设备，没有接入正式体能扣费、真实队伍、真实经验及道具奖励；奖励数值仅用于体验结算展示。页面外的营地和路线暂不播放音乐。正式接入仍采用唯一全局体能，不新增探索点数。当前敌人和强化数量用于验证循环，平衡性需要试玩反馈，不视为最终数值。

验证：`python3 tools/pipeline/verify_dungeon_prototype.py`。三个固定种子完成八节点通关，检查原生战斗快照恢复、生命与随机状态保留、旧版本输入拒绝、奖励不可重复领取。另有手动浏览器选队、战斗、强化、岔路以及服务重启后恢复验收。


## 设备体验版（2026-09-13）

入口改为「菜单 → 秘境」。六选三 Lv.50 演示队伍，选满第三位后开局；A/B 上下、C 确认、长按 B 返回。战斗内 C 打开战术菜单，长按 B 进入认输确认。营地与强化界面长按 B 返回秘境入口，不清除进度。入口可以继续、新开一局、查看本局强化或返回菜单。

规则和页面已移植到 `dungeon.c` / `play_dungeon.c`，复用现有训练家战斗展示。局内进度以单独 NVS 命名空间 `pw_dungeon`、键 `run_v1` 存储，每次战斗动作和路线选择提交后再更新内存；重启从「秘境 → 继续旅程」恢复。新开局只有选满三位且保存成功才覆盖之前的体验局。不会调用正式世界的经验、道具或挑战结算，也不扣正式体能。牛奶回复在体验战斗中禁用，恢复依靠营地与局内强化。

设备页面可在固件同源预览的 P16 验收。原来的独立 HTML 体验入口仍保留；两个原型各自保存进度，随机序列不互通。正式接入前还需要统一配置表与数值，接入真实队伍/费用/奖励。

验证：`verify_dungeon_device.py` 操作原生页面跑过全部八个节点到首领结算，检查各阶段全量绘制与增量绘制一致，验证正式队伍、背包及徽章未改变。设备构建通过。烧录及真机结果另见本次烧录报告。
