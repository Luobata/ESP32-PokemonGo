# S3 自动战斗

不做招式/PP/状态异常，用自动结算 + 三种张力手段把战斗压进几秒，并让「先打再抓」成为真策略。

## 输入 / 输出

| 方向 | 来源 / 目标 | 字段 |
|---|---|---|
| 入 | S1 队列的 `Encounter` | `species_id`、`type_name` |
| 入 | `assets/gen1.bin` | `type_primary`(off 3)、`type_secondary`(off 4)、`hp`/`attack`/`defense`/`special`/`speed`(off 10~14) |
| 入 | `sim/gameplay.py` 的 `PetState` | `type_name`、`ability_factor`（消沉时 0.6） |
| 出 | S2 捕获 | 野怪剩余 HP 比例 → 捕获窗口加宽 |
| 出 | `PetState` | `stamina` 扣减 |
| 出 | S10 成绩 | 战斗次数、胜负 |

不改野怪的持久化状态 —— 野怪 HP 只活在这一次会话里。

## 核心逻辑

按 `speed` 定先后，逐回合互相扣 HP，直到一方归零或回合上限（建议 8 回合）。
单次伤害：

```
damage = base(attack, defense) × type_multiplier × ability_factor
```

`ability_factor` 直接取 `PetState.ability_factor`（`sim/gameplay.py`）——
消沉时 0.6，绝不清零。

**三件事制造张力，全部零素材成本：**

| 手段 | 实现 | 复用 |
|---|---|---|
| 属性相克可见 | 倍率 ≥2 时打出「效果绝佳！」并整体闪白 | `sim/effects.py` 的 `flash_sequence()` |
| HP 条逐步扣减 | 每回合分几帧扣，配合受击横向抖动 | `sim/effects.py` 的 `shake_sequence()` |
| 战后捕获变易 | 野怪 HP 越低，S2 的判定窗口越宽 | 见 [S2-capture.md](S2-capture.md) |

第三条是关键：**它让「先打再抓」成为真策略**，而不只是原版的复刻习惯。

### 初代相克表的四条特有差异

**必须按初代实现，不能抄现代表。** 实测差异正好四条：

| 攻 → 守 | 初代 | 现代 | 说明 |
|---|---|---|---|
| 幽灵 → 超能 | **0%** | 200% | 初代著名 bug。表里写的是「效果绝佳」，代码里查的是「无效」 |
| 毒 → 虫 | **200%** | 50% | |
| 虫 → 毒 | **200%** | 50% | |
| 冰 → 火 | **100%** | 50% | 初代冰打火不吃亏 |

幽灵→超能 = 0% 这条**要保留而不是修掉**：初代情怀项目里它是特征不是缺陷，
而且它顺带解释了为什么初代耿鬼线要靠毒属性打天下。

## 数据结构

15×15 半字节表，**113 字节**（225 个 nibble，向上取整）：

```
type_chart.bin
   头部无（编译期常量数组，直接进 rodata）
   索引: idx = attacker * 15 + defender        // 0 ~ 224
   取值: byte = table[idx >> 1]
         nib  = (idx & 1) ? (byte & 0x0F) : (byte >> 4)
   编码: 0 = 0%   1 = 50%   2 = 100%   3 = 200%
   总量: (225 + 1) / 2 = 113 B
```

属性下标即 `sim/gameplay.py` 的 `TYPES` 列表顺序
（一般=0 火=1 水=2 电=3 草=4 冰=5 格斗=6 毒=7 地面=8 飞行=9 超能=10 虫=11 岩石=12 幽灵=13 龙=14）
—— 与 `gen1.bin` 的 `type_primary` 字段编码保持同一套下标，不做二次映射。

双属性守方取两个倍率之积（`type_secondary == 0xFF` 时只算主属性）。
nibble 只用了 4 个值中的 4 个，2 bit 就够，但半字节对齐让取值是一次移位 ——
省下的 56 字节不值得换成位运算复杂度。

## 与三键约束的关系

对应 **P3 遭遇详情 / 战斗页**：**A 捕获 / B 战斗 / C 逃跑**。

战斗一旦开始就是自动结算，**过程中不接受输入** —— 这是三键约束下的正确取向：
玩家的决策发生在按 B 之前（打不打、带谁出门），不发生在回合里。
战斗结束回到 P3，此时「A 捕获」的窗口已经变宽。

HP 条重绘只影响两条固定横带，抖动是整体偏移，都不需要整帧缓冲。

## 边界情况

1. **主宠与野怪同属性且互相 100%** —— 按 `speed` 定先后，仍会结束；回合上限兜底判平（双方均不扣球、不改图鉴）。
2. **倍率为 0**（如幽灵打超能）—— 伤害为 0 而非负数，且不打「效果绝佳」。若双方互相 0%，8 回合后判平。
3. **主宠消沉** —— `ability_factor` 0.6 会显著拉长战斗；回合上限使其必然收敛为平局，而不是卡死。
4. **战斗中掉电** —— 野怪 HP 不落盘，重启后该遭遇回到未战斗状态。与 S2 同样的取向：宁可白送，不能扣了体能又没结果。
5. **野怪 HP 打到 0** —— 初代野怪不会「死」，判为逃跑并从 S1 队列移除。**这是一个真实的取舍**：打太狠就抓不到了，与「先打再抓」形成上限。


## 实测暴露的三处平衡缺陷（已修）

设计落地到真实数据后，三处问题只有跑起来才会暴露：

### ① 野怪等级跟着主宠涨 → 练级毫无意义

初版 `wild_level()` 用 `pet_level + delta`，于是主宠 Lv40 打 ★★ 照样输
（对手也涨到 Lv39）。**玩家的成长必须能兑现成战力**，否则养成线与
战斗线脱钩。

改为**绝对等级带**：

| 稀有度 | 野怪等级 |
|---|---|
| ★ | 5 |
| ★★ | 12 |
| ★★★ | 20 |
| ★★★★ | 30 |
| ★★★★★ | 45 |

「打不过」于是变成**暂时**状态 —— 练到 Lv30 能回头收拾 ★★★★。

### ② 种族值不随等级成长 → 等级只是个数字

伤害公式里等级只出现在 `(2×Lv/5+2)`，双方一起涨就抵消。加
`effective_stat(base, level) = base × (1 + level/50)`，Lv50 时翻倍，
与原版量级接近。

修完后的成长曲线（火系御三家）：

| 主宠 | 能打过 |
|---|---|
| 小火龙（种族值 249） | ★ |
| 火恐龙（325） | ★ ★★ |
| 喷火龙（425） | ★ ★★ ★★★ ★★★★ |

★★★★★ 连 Lv45 喷火龙也打不过 —— **传说级需要更多投入，这个留白是有意的**。

### ③ 伤害公式分母配的是原版等级曲线

原式分母 50 让 Lv12 打 Lv10 只有 3 伤害/回合、要 46 回合。压到 25 后
战斗落在 5~15 回合，符合 30 秒会话预算，也让 HP 条的逐步扣减看得出变化。
