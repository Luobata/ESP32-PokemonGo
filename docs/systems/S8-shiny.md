# S8 闪光

极低概率遇到配色不同的个体，作为长期收集目标。

## 初代没有闪光，但这不构成障碍

闪光是二代（金银）引入的机制，初代 RBY 完全没有。所以严格意义上这一条
**偏离了原汁原味**，是本项目为「长期驱动力」主动加的。

之所以判断它值得加：初代的收集目标只有 151 只，全收集完就没有新目标了。
而闪光提供了**一个永不枯竭的追逐对象**，且成本几乎为零。

## 零素材成本

关键事实：**闪光的本质就是换调色板，位图完全相同。**

实测二代皮卡丘（`generation-ii/crystal`）：

| 版本 | 调色板 |
|---|---|
| 普通 | `(0,0,0) (214,49,0) (239,214,41) (255,255,255)` |
| 闪光 | `(0,0,0) (165,16,90) (255,140,0) (255,255,255)` |

位图一字节不差 —— 只有中间两色变了。

因此闪光在本项目的开销是：

| 项 | 大小 |
|---|---|
| 10 套闪光配色 | 10 × 4 色 × RGB565(2B) = **80 字节** |
| 每只个体的闪光标记 | 1 bit（存在遭遇记录与图鉴里） |

## 闪光配色怎么来的

初代没有官方闪光配色，所以按规则生成（见
[`tools/pipeline/convert_palettes.py`](../../tools/pipeline/convert_palettes.py)
的 `shiny_variant()`）：

```
色相旋转 140°，饱和度 × 1.25 + 0.08
最暗档（亮度 < 40）与最亮档（> 240）保持不动
```

**为什么是 140° 而不是 180°**：完全反相会让暖色变冷色，看起来像坏图。
140° 能明显区分，又保留原本的冷暖倾向。

**为什么两端不动**：最暗那档通常是轮廓线（近黑 `#191010`），最亮那档是
背景（纯白，且渲染时当透明）。动它们会破坏轮廓与透明判定。

实测皮卡丘：黄 `#d6a500 #ffe673` → 青 `#00c0d6 #3ce1ff`，区分明显。

## 概率与判定

**判定时机是遭遇生成时**，而非捕获时 —— 玩家应当在看到 sprite 的瞬间
就知道自己遇到了什么。

复用 [`sim/gameplay.py`](../../sim/gameplay.py) 的 `spawn_seed()` 保证确定性：

```
shiny_roll = hash32(f"{bssid}|{time_bucket}|shiny") % SHINY_DENOM
is_shiny   = shiny_roll == 0
```

用独立的 salt（`|shiny`）而非复用 spawn_seed 的低位，是为了让闪光判定
与种类判定统计独立 —— 否则某些种类会永远不闪光。

| 参数 | 值 | 依据 |
|---|---|---|
| `SHINY_DENOM` | **512** | 二代原版是 1/8192，但那是按「每次遭遇」算的，而原版一天能遇几百只。本项目一天遭遇 10~30 次，8192 意味着**平均一年才见一只** —— 太稀薄了。512 对应约两三周一只 |
| 稀有度加成 | ★★★★★ 的怪 `DENOM/2` | 稀有 × 闪光的双重稀有，值得给点倾斜 |

⏳ **待 Phase 0 验证**：`SHINY_DENOM` 依赖真实遭遇频率。若实测遭遇远多于
30 次/天，这个值要调大。

## 表现

闪光不只是换色，还要有「被发现」的仪式感：

| 场景 | 表现 |
|---|---|
| 遭遇入场 | 在 `zoom_in_sequence()` 之后追加一次 `flash_sequence()` —— 复用现有动效，零新代码 |
| 遭遇列表（P2） | 名字后加 `✦` 标记 |
| 图鉴（P6） | 已捕获闪光的格子用闪光配色渲染 |
| 捕获成功 | 额外一次全屏闪白 |

## 数据结构

闪光标记不需要独立存储，挂在现有结构上：

```
遭遇记录（S1 队列，8 字节/条）
  ...
  flags: bit0 = is_shiny

图鉴位图（S5）
  已见:     19 字节（151 bit）
  已捕:     19 字节
  闪光已捕: 19 字节   ← 新增，让「闪光图鉴」成为独立收集目标
```

多加 19 字节换一整套平行收集目标，这个交换很划算。

## 与三键约束的关系

**不需要新页面。** 闪光是既有页面上的一个视觉差异 + 一个图鉴维度。
P6 图鉴可以用 B 键在「普通/闪光」两个视图间切换。

## 边界情况

| 情况 | 处理 |
|---|---|
| 闪光怪捕获失败逃跑 | **记入「已见闪光」但不记「已捕」** —— 遗憾感是这个机制的一部分 |
| 同一 AP 同一时段重复计算 | `spawn_seed` 是确定性的，重算结果一致，不会因为重启而变 |
| 闪光配色与普通配色亮度分布不同 | `shiny_variant()` 只改色相饱和度、不改亮度，所以 2bpp 的四档分布不变 —— 动效（闪白/压暗）对两者行为一致 |
| 玩家全收集 151 只后 | 闪光图鉴接管长期目标。这正是加这个机制的理由 |
| 闪光标记丢失（存档损坏） | 由 S6 的 CRC 保护。闪光已捕位图属于不可再生数据，与养成数据同级 |
