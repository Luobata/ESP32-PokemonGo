# S12 昵称

给主宠起名。实现见 [`sim/naming.py`](../../sim/naming.py)，
界面见 [P8 取名](../pages/P8-naming.md)。

## 12.1 为什么不做自由取名

这是**算出来的结论**，不是妥协。

三键设备上从字库里逐字选字：

```
字库 420 字，B 键循环切字 → 平均按 210 次选中 1 个字
取 4 字昵称 ≈ 840 次按键
```

而会话预算是 30 秒（[04-gameplay.md](../04-gameplay.md)）。
就算只开放 32 个常用字备选，仍要 64 次按键。

原版 GB 有十字键 + A/B + 完整假名表 —— 那是另一种输入条件，
在三键无触摸设备上不能照搬。

## 12.2 方案：预设候选 + 1 字节

24 个预设昵称，分四组：

| 组 | 候选 | 选词取向 |
|---|---|---|
| 叠字 | 小家伙、豆豆、果果、乖乖、团子、糯米、饭团、肉丸 | 最像宠物名，放最前（默认停这里） |
| 属性 | 闪电、火苗、水滴、叶子、石头、毛球 | 与主宠属性对上时格外贴切 |
| 单字 | 风、云、星、宝 | 短名在状态栏最省位置 |
| 称号 | 大王、队长、老大、阿宝、元气、伙计 | 给养到高等级的用 |

分组不只是分类 —— B 键循环时同组相邻，玩家能感到「翻到下一组了」，
比按拼音排更好用。

## 12.3 三键与按键代价

| 键 | 动作 |
|---|---|
| **A** | 确认 |
| **B** | 下一个 |
| **C** | 上一个 |

C 键给「上一个」是这里最值钱的一个决定：24 个候选里转错一步，
单向循环要再绕 23 次。双向后最坏按键从 **25 次降到 13 次**。

## 12.4 存储：默认不占字节

```
nickname_idx  1 字节   0~23 = 候选索引，0xFF = 没起过名
```

`0xFF` 时显示**物种中文名**（gen1.bin 里已有）。于是：

- 不改名的玩家：**额外花 0 字节**（那 1 字节存的是 0xFF）
- 改过名的：1 字节

对比另两个方案：

| 方案 | 字节 | 取名代价 |
|---|---|---|
| UTF-8 12 字节 | 12 B | 840 次按键 |
| 字库索引 4×u16 | 8 B | 840 次按键 |
| **预设索引** | **1 B** | **13 次** |

回落到物种名还有个副作用是好的：**「不改名」成了一个完全合理的选择**，
而不是屏幕上顶着个占位符。

## 12.5 字库代价

24 个昵称用 37 个汉字，加取名页 UI 用字，字库从 346 增到 420 字
（12.3 KB → 14.0 KB）。8MB 里的零头。

字符集由 [`sim/naming.py`](../../sim/naming.py) 的 `charset()` 导出，
[`convert_font.py`](../../tools/pipeline/convert_font.py) 直接取 ——
**没有第二份清单**，改昵称不会漏收字。

## 12.6 边界情况

1. **存档损坏读到任意字节** —— `display_name()` 与 `group_of()` 对越界值
   都回落到「未命名」。两者必须一致，否则会出现「名字显示皮卡丘、
   组显示 ?」这种自相矛盾的界面。
2. **改名时从哪开始** —— `NamePicker(current=...)` 光标停在当前昵称上，
   不是从 0 开始。改名的人通常想微调而非重选。
3. **进化后昵称保留** —— 昵称属于这只主宠而不是这个物种。
   妙蛙种子叫「豆豆」，进化成妙蛙草还是「豆豆」。
