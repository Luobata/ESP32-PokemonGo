# S5 图鉴

两个 151 bit 位图记录已见与已捕，未捕获显示为全暗剪影 —— 静态、可翻页、零素材成本。

## 输入 / 输出

| 方向 | 来源 / 目标 | 字段 |
|---|---|---|
| 入 | S1 遭遇累积 | 遭遇入队时置「已见」位 |
| 入 | S2 捕获判定 | 捕获成功时置「已捕」位 |
| 入 | `assets/gen1.bin` | `name_offset`/`name_len`、属性、种族值、`height`/`weight` |
| 入 | `assets/gen1_front.bin` | front sprite（40/48/56 三档，按 `flags` bit2-3 定档） |
| 出 | S10 成绩 | 已见数 / 已捕数 / 完成度 |
| 出 | S6 存档 | 三个位图共 57 字节 |

位是**单向置位**，从不清除 —— 图鉴是记录，不是当前状态。

## 核心逻辑

只有三个操作，全是位运算：

```c
seen_set(id)     bitmap_seen[(id-1) >> 3] |=  (1 << ((id-1) & 7))
caught_test(id)  bitmap_caught[(id-1) >> 3] & (1 << ((id-1) & 7))
count()          popcount 遍历 19 字节
```

`id - 1` 是因为 `species_id` 是 1~151，位下标是 0~150。

**未捕获的显示方式是本系统最划算的设计**：不做额外剪影素材，
直接把 front sprite 用 `sim/effects.py` 的灰阶映射表压成全暗 ——
`Transform(shade_map=(0, 0, 0, 3))`。

原理见 `sim/effects.py` 的 `render()`：shade 3（最亮）当透明跳过不画，
其余三档全部映射到 0（最暗）。于是轮廓保留、内部细节全黑，**零素材成本**
拿到剪影。已见未捕用这个映射，已捕用 `IDENTITY`；已捕且闪光的用
[S8](S8-shiny.md) 的闪光配色 —— 三种渲染状态对应三个位图。

未见过的种直接画一个「?」占位，不读 sprite。

**每页 20 只、8 页**（151 只，末页 11 只）。页内 4×5 网格，
每格放 40×40 的档位 sprite 缩到统一尺寸即可 —— 复用 `render()` 的
整数分数缩放（`scale_num`/`scale_den`），不需要预生成缩略图。

## 数据结构

```
dex_seen          19 B    151 bit，bit i = species_id (i+1) 已见
dex_caught        19 B    同上，已捕
dex_shiny_caught  19 B    同上，闪光已捕（S8-shiny.md 新增）
                  ────
                  57 B
```

151 bit 向上取整 = 19 字节，末字节高 7 位未用（151 = 18×8 + 7，
即 byte[18] 只用 bit0~bit6）。**这 7 个空位必须恒为 0** ——
否则 popcount 出来的完成度会超过 151。三个位图同一约束。

三个位图形成严格的包含关系：`shiny_caught ⊆ caught ⊆ seen`。
这是免费的一致性校验，S6 启动时可以直接查（见「边界情况」）。

不存「首次遭遇时间」「遭遇地点」这类元数据：那会让每只 4~8 字节、
总量涨到 600~1200 字节，而图鉴的核心价值是「有没有」而非「哪时哪地」。
「哪时哪地」的那一份归 [S10 成绩](S10-records.md) 的每日摘要，
地点记忆归 `sim/sensing.py` 的 `PlaceMemory`（8 槽 LRU）。

## 与三键约束的关系

对应 **P6 图鉴页**：**A 详情 / B 翻页 / C 返回**。

B 键单向翻页（8 页循环回第 1 页）—— 三键下不做双向翻页，
8 页循环最多按 7 次到目标，成本可接受，且省掉一个键。

A 进入详情页显示 `gen1.bin` 里的属性、种族值、身高体重与大图 front sprite。
详情页内 A 键退回列表。

图鉴是这套硬件**最擅长表现**的部分 —— 静态、无动画、翻页时整屏重绘一次即可，
不需要连续帧（[04-gameplay.md#45](../04-gameplay.md#45-图鉴)）。
因此 08-systems.md 建议它作为主界面的一级入口（P1 的 B 键）而非二级菜单。

## 边界情况

1. **`species_id` 越界**（0 或 >151）—— 必须在置位前校验。`(id-1) >> 3` 对 id=0 会算出 `-1 >> 3`，在 C 里是未定义/写坏相邻字节，直接损坏存档。
2. **已捕但未见 / 闪光已捕但未捕** —— 逻辑上不可能（捕获前必先遭遇），但存档损坏后可能出现。校验规则：`caught & ~seen` 与 `shiny_caught & ~caught` 都必须为全 0；不满足则用 `seen |= caught`、`caught |= shiny_caught` 修复而非拒绝存档。
3. **末字节高 7 位非 0** —— 存档校验时对三个位图强制清零，否则完成度显示 >151/151。
4. **完成度 151/151** —— 不应触发任何特殊状态清零；S10 记一次成就即止。闪光图鉴是独立的第二条 151/151 目标。
5. **翻到末页** —— 第 8 页只有 11 只，后 9 格必须画空白而不是读 `species_id` 152~160 的越界数据。
