# S23 · 原版动画数据对齐核查

2026-09-09 用户指出冲浪及受击反馈差异，核查确认不是完整金银动画移植：

- 图元管线从固定的 `pret/pokecrystal@7a7881d0d62e0ddbd82dcf10e7116807487ac651` 提取若干 OAM 合成帧，能证明图元来源，不能证明整招演出一致。
- 招式效果/学习资料按 `pret/pokegold@656583c939d30f920a316177311a502dd222b57c` 核查，动画图元来源却是水晶；没有全面证明二者图形相同。
- `battle_fx.c` 的轨迹、配色、节奏和通用状态反馈是本项目适配。此前冲浪57没有独立派发，落到水属性通用水枪图元，丢失整个浪面和背景波动。
- 受击只有位移，没有原作敌方受击的隐藏/显示循环。

## 原作证据与本轮修复

[金银动画脚本](https://github.com/pret/pokegold/blob/656583c939d30f920a316177311a502dd222b57c/data/moves/animations.asm) 的 `BattleAnim_Surf` 使用 BUBBLE 图形、SURF 背景效果和 SURF 动画对象，循环等待32帧四次，再通知对象下落并等待56帧。

[动画对象函数](https://github.com/pret/pokegold/blob/656583c939d30f920a316177311a502dd222b57c/engine/battle_anims/functions.asm) 的 `BattleAnimFunction_Surf` 逐步抬升浪面，进入等待态后下降；[背景函数](https://github.com/pret/pokegold/blob/656583c939d30f920a316177311a502dd222b57c/engine/battle_anims/bg_effects.asm) 操作滚动和正弦波表。

本轮增加浪面上升→停留→下降，绘制范围覆盖战斗区域并保护HUD。36个硬件帧、每帧90ms，包含2个干净收尾帧；波形和调色仍为240×320布局适配，没有宣称逐像素模拟GB背景滚动。

原作 `BattleAnim_EnemyDamage` 隐藏5帧/显示5帧、循环三次；`BattleAnim_PlayerDamage` 则是屏幕纵向震动，并不是同一段闪烁脚本。本轮采用目标隐藏/显示各90ms、循环三次，统一用于我方和对方的伤害反馈，这是当前项目的双侧反馈设计。攻击方、姓名和血条不闪；未命中、无伤害、蓄力、自身效果不触发。野战、训练家对战和招式验收共用这一实现。

## 全量清单与后续范围

`tools/pipeline/audit_animation_alignment.py` 按原作指针表匹配全部191招，记录直接背景命令、子调用和当前动画类型。结果见 `reports/evidence/animation-alignment-2026-09-09/audit.json`。

其中105招直接使用背景效果；这个数量不展开子调用，也不意味着105招都存在相同缺陷。当前**没有任何招式获得完整原作逐帧等价认证**；指定动作与属性/状态共用动作均标注为适配。验收页区分“当前硬件实现验收”和“原作还原度核查”。

此前全招图元、遮挡、方向、清屏、6112次同源像素检查仍有价值，但只验证实现自身以及Web/硬件同源，不验证与原作帧序列相等。后续如逐招提升还原度，必须同时核对对象函数、帧集、背景效果、调色、轨迹、等待/循环、声音，以及独立的受击阶段，不能只增加一张图或换一个派发名称。
