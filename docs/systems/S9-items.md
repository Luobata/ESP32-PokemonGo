# S9 道具

球种与消耗品。**刻意做到最小** —— 只保留能产生决策的部分。

## 先回答「是否有必要」

你在需求里留了这个余地，我的判断是：**必要，但只需要 4 种道具。**

理由是道具在这个项目里承担一个不可替代的职责 ——
**把探索的产出转化成捕获的输入**。没有它，探索与捕获之间就断开了：

```
出门 → 遭遇 → 捕获        ← 没有道具时，探索只提供"遭遇机会"
出门 → 遭遇 → 掉落球 ─┐
                      ├→ 捕获   ← 有道具时，探索还提供"捕获资源"
        照料 → 消耗浆果┘
```

但道具很容易失控成一整套背包/合成/商店系统，那与
[30 秒会话](../01-constitution.md#12-由约束推导出的核心形态)和三键约束都冲突。
所以下面这份清单是**上限，不是起点**。

## 四种道具

| 道具 | 作用 | 获取 | 上限 |
|---|---|---|---|
| **精灵球** | 捕获窗口 ×1.0 | 遭遇后必掉 1~2 个 | 99 |
| **超级球** | 窗口 ×1.5 | 稀有度 ★★★+ 遭遇掉落 | 20 |
| **高级球** | 窗口 ×2.0 | 稀有度 ★★★★★ 或新地点首次访问 | 5 |
| **浆果** | 喂食（`PetState.feed()`） | 驻留时按时间产出 | 20 |

**没有的**：药水（自动战斗不需要治疗）、进化石（见下）、商店、合成、
背包页面（数量直接显示在用到它的页面上）。

上限存在的意义是**逼出决策**：高级球只有 5 个，用不用在这只身上是个真选择。
若上限太高，道具就退化成纯数字。

## 三种球的存在理由

三种而非一种，是因为
[S2 捕获](S2-capture.md)的时机判定需要一个「除了手速之外的变量」——
否则捕获纯粹考验反应，与养成、探索都不咬合。

而球种正好把三条线接起来：

| 变量 | 来源 | 玩家能做什么 |
|---|---|---|
| 基础窗口 | `catch_rate`（种族固有） | 无法改变，只能接受 |
| ×1.0 / 1.5 / 2.0 | 球种（探索产出） | **决定用哪个** |
| ×`catch_window_bonus` | 心情（养成产出） | 提前照料好主宠 |

三者相乘，于是「攒着高级球等稀有怪」「出门前先把主宠喂好」都成了有效策略。

## 进化石怎么处理

初代有 14 只靠道具进化（水/火/雷/叶/月之石）。但**做成收集品会很难受** ——
玩家会卡在「没有雷之石所以皮卡丘不能进化」上，而设备没有商店可买。

**决定：不做进化石道具，改为条件进化。** 详见
[S7 进化](S7-evolution.md)。道具进化的那 14 只改用
「亲密度 + 探索值 + 对应 biome 驻留时长」作为条件 ——
比如雷之石系改成「在办公区累计驻留 N 小时」（呼应
[OUI 语义](../03-spawning.md#32-ssid-与-oui-是被低估的语义金矿)里
企业级 AP → 电系的映射）。

这样进化条件与探索行为绑定，而不是与运气绑定。

## 掉落规则

复用 [`sim/gameplay.py`](../../sim/gameplay.py) 的 `Encounter.rarity`：

```
遭遇结束（无论捕获成功与否）
  → 精灵球 +1，若 rarity >= 3 再 +1
  → rarity >= 3     : 超级球 +1
  → rarity == 5     : 高级球 +1
  → 首次访问新地点  : 高级球 +1（复用 SensingResult.is_new_place）

驻留时（基地）
  → 每 BASE_SPAWN_INTERVAL(4h) 浆果 +1
```

**为什么失败也掉球**：否则玩家会陷入「球不够 → 不敢投 → 更没球」的死锁。
掉落是探索的报酬，不是捕获的报酬。

⏳ **待 Phase 0 验证**：掉落速率依赖真实遭遇频率。若实测遭遇远多于 30 次/天，
球会溢出上限（那也不算坏 —— 上限本身就是软约束）。

## 数据结构

四个字节，塞进 [S6 存档](S6-save.md)：

```
offset  size  field
0       1     poke_ball    0~99
1       1     great_ball   0~20
2       1     ultra_ball   0~5
3       1     berry        0~20
                           = 4 字节
```

不需要背包结构 —— 道具种类固定，直接定长数组。

## 与三键约束的关系

**不需要独立的背包页面。** 数量显示在用到它的地方：

| 页面 | 显示 | 操作 |
|---|---|---|
| [P4 捕获](../pages/P4-capture.md) | `球: 精灵球 ×12` | **B 键循环切换球种** |
| [P5 照料](../pages/P5-care.md) | `喂食  浆果 ×5` | A 键执行时消耗 |

这是刻意的：**独立背包页面会多两次按键**（进入、退出），
而 30 秒会话里每次按键都很贵。

## 边界情况

| 情况 | 处理 |
|---|---|
| 球全用光 | P3 的「A 捕获」变灰，只能战斗或逃跑。**不做「保底球」** —— 没球是探索不足的自然后果，而掉落规则保证不会永久卡死 |
| 数量达上限 | 静默不增，不提示（提示会打断 30 秒节奏） |
| 浆果为 0 时喂食 | A 键在该项上变灰，光标可以跳过 |
| 存档里数量超出上限（数据损坏） | 读取时 clamp 到上限，不报错 |
| 切换球种时该球为 0 | B 键循环时跳过数量为 0 的球种 —— 避免玩家切到空球再发现不能投 |
