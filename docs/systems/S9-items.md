## 胜利掉落

仅在战斗胜利后结算掉落。捕获成功、捕获失败、逃跑、普通遭遇入队及地点驻留本身不发放道具。

| 对手稀有度 | 掉落概率 |
|---|---:|
| ★ | 25% |
| ★★ | 35% |
| ★★★ | 45% |
| ★★★★ | 55% |
| ★★★★★ | 65% |

每次胜利最多掉落一种道具：精灵球为 2–3 个，其余为 1 个。抽中道具的权重随稀有度变化，高星提高高级球、特殊球、进化石与机器的权重；大师球仅在五星的权重表中出现，权重为 1。完整权重表在 `items_roll_loot()`，不可把“掉落概率”理解为任一具体道具的概率。

`items_loot_seed(uid, ts, species, rarity)` 生成独立种子，不推进战斗 RNG。`world_battle_loot_uid()` 对同一胜利会话只结算一次：没有掉落也记录 `loot_checked`；重复调用返回同一结果。库存不足以容纳全部奖励时只加入剩余容量，返回实际入包 `quantity` 和 `full` 标记。保存失败不发布库存或 once 标记，重试仍抽到同一结果。

## 页面与操作

| 页面 | 使用方式 |
|---|---|
| P10 背包 | 从 P5 进入；四行一页，按球、进化、养成分组。B 前进、长 B 后退，A 使用，C 回到 P5；显示数量、容量和效果说明 |
| P4 捕获 | B 循环选择有库存的球；投球时消费一球。球仅在此页面使用，背包内选择球会提示前往捕获页 |
| P5 照料 | 喂食消费树果；休息与玩耍继续免费。免费进化只接受自然 LEVEL 路线 |
| P3 战斗结果 | 显示实际胜利掉落或满额结果；保存失败需要重试结算 |

空库存不提供免费替代品。道具不适用、等级不足、伙伴已更换、仍在活动对战或存储不可用时，使用接口返回明确状态，库存不变。背包可查看零库存道具。

## 保存与事务

`inventory_t` 是 19 项 `uint16_t` 数组，共 38 B。V6 存档为 2336 B，保留 V5 的 2296 B 前缀及填充，在末尾追加库存。有效 V5 在内存补入初始包，下一次成功保存写成 V6；迁移失败时保留原档。未知版本、异常长度、非法队伍/队列或超过容量的库存会禁写保档，不静默裁剪或清档。

公共接口：

| 接口 | 事务边界 |
|---|---|
| `world_inventory_snapshot(out)` | 状态锁内复制完整库存 |
| `world_item_use(expected_species, item_id, out)` | 重新检查队首与库存；将扣道具、养成或进化、party/dex 变化一次保存后发布 |
| `world_battle_loot_uid(uid, out)` | 保存实际入包结果后发布掉落 once 标记 |
| `world_capture_ball_spend_uid(uid, ball, session)` | 扣球、首次移出待处理队列、投球会话一并保存；失败不消耗胜后最后捕获机会 |
| `world_capture_uid(uid, mon)` | 捕获成功后的收容保存；party/dex 和活动目标在成功后更新 |

投球消费与捕获收容是两次提交。如果球已消费且判定成功，但收容保存失败，P4 保留这次成功结果，允许单独重试收容，不再扣球，也不能当作普通捕获失败执行反击。

道具事务先建立候选快照，NVS 成功后才发布。库存、养成和队伍写路径按保存锁→状态锁排序；保存期间的照料/探索变更等待，图鉴已见标记可合并，避免并发更新被旧快照覆盖。活动战斗只存在 RAM，其目标在首次行动时已持久移出队列，重启不会重放同一胜利掉落。

## 验证

`tools/pipeline/verify_items.py --negative` 直接链接实际 `items/world/save/assets/party/evolution`，覆盖 102 个场景及 5 个源码负向，包含真实 V5 迁移、所有石/通讯路线、三种 NVS 失败、八种球、掉落 once、容量和并发保存。原 starter 67 项和 encounter lifecycle 10 项继续通过。详细证据见 [道具核心验收](../../reports/items-core-2026-09-08.md)；物理设备构建和页面验收单独记录。
