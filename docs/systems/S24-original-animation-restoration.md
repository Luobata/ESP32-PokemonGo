# S24 · 全招式原版动画还原

目标是当前游戏全部191招的金银原版演出，不以“每招都有动画”作为完成标准。今后新增招式也采用同一标准。血条、姓名和精灵都可以在演出中被覆盖、闪烁或背景效果影响，结束后必须恢复；底部消息窗保持可读。

## 已完成的基础修正

- 取消所有招式效果的HUD区域裁切。野战与训练家战统一在双方精灵、姓名、HP之后绘制特效，消息窗之前绘制；每帧从干净背景重建三个战斗区band，避免残影。
- 冲浪覆盖完整240×240战斗区，包括双方HUD；不再有两块硬裁切白区。现有波形、色带和时序仍是适配，不能标记为原版还原。
- 特效图元管线改为固定 `pret/pokegold@656583c939d30f920a316177311a502dd222b57c`。45个已有合成图元与旧版像素完全相同，因此此次更换来源本身没有改变这45张图的外观。
- 后台播放长度改由实际C回合返回，不再将所有招式固定循环36帧。比如撞击20帧、冲浪36帧、未命中20帧。这仍是当前适配实现的时长，不是原作时长。
- 全191招建立原作脚本依赖表，展开局部跳转、循环、子调用及分支，保留源行号和参数。107招涉及背景效果，入口对象涉及60种运动回调、39种背景效果。对象函数内部继续切换的回调不包含在60这个统计中；这些数量不表示已移植。
- 验收页逐招展示原作脚本、对象/运动/背景依赖及源码链接。所有招式仍标记为原作脚本未完整移植。

生成及检查：

```sh
python3 tools/pipeline/convert_battle_fx.py --src /tmp/pokewalk-gold-review --check
python3 tools/pipeline/catalog_gold_animations.py --source /tmp/pokewalk-gold-review --check

```

依赖目录为 `tools/inspector/move-animation-sources.json`，保留原作分支而非只抽取默认路径；来源文件逐一校验Git blob。它是核查资料，不是已经接入固件的脚本执行器。不会因为目录覆盖191招而把191招标记为还原完成。

## 剩余工作与验收标准

| 部分 | 必须完成 | 当前状态 |
| --- | --- | --- |
| 动画脚本执行 | wait、loop、call/ret、条件分支、对象增删及状态切换，保持原作顺序 | 只有源码依赖目录，固件仍是自定义阶段 |
| 对象图形与运动 | 完整帧集、原点、翻转、优先级、轨迹和回调中的后续切换 | 45个选取图元；绝大多数原作回调未移植 |
| 背景与调色 | 波浪/滚屏、画面闪色、精灵遮罩及变形，正确影响HUD/精灵 | 已允许覆盖HUD；原作背景引擎未移植 |
| 时间轴 | 以原作帧推进逻辑，显示采样不改变事件顺序；回合之间可增加停顿 | 当前仍为90ms适配阶段 |
| 受击与声音 | 敌方三闪、我方原作震屏的区别；按原作事件触发对应声音 | 双侧统一闪烁，音效为现有系统；尚未完整还原 |
| 逐招原作比对 | 双侧、命中/未中、蓄力/释放、多段、状态招式；录屏检查阶段与锚点 | 尚无任何招式获得完整原作等价验收 |

不继续通过增加“通用属性动画”填满还原清单。实现应以原作脚本执行和共享背景/对象能力为核心，再逐招修正特殊分支；整招还原必须有原作对照证据。当前像素回归仅保证Web与硬件共用渲染、自身清屏正确，不能作为原作还原测试。
