# S10 成绩与排行

把探索行为沉淀成可回看的记录。

## 先解决一个结构性问题：单机没有对手

你要的是「成绩系统 + 排行榜」。但本项目当前是
**自用单机、无联网、[BLE 交换已延后](../04-gameplay.md#44-交换与对战)** ——
没有别的玩家，排行榜跟谁排？

三种解法，我选第三种：

| 方案 | 问题 |
|---|---|
| 联网上传排行 | 违反[离线优先](../02-sensing.md#28-隐私与合规)，且 BSSID 属位置关联数据，上传即涉合规 |
| BLE 相遇时交换成绩 | 需要第二台设备。可以做，但现在做等于做了个用不上的功能 |
| **与自己的历史比** | ✅ 采用 —— 单机就成立，且这才是这个设备真正的玩法 |

所以这里的「排行榜」是**个人纪录榜**：今天 vs 历史最好、本周 vs 上周、
连续天数。这不是妥协 —— Tamagotchi 从来没有排行榜，靠的就是
「我养了多久」这一件事。

## 三类记录

### ① 单项纪录（历史最好）

| 纪录 | 字段 | 为什么值得记 |
|---|---|---|
| 单日遭遇最多 | u16 + 日期 u32 | 「那天出门走了好久」 |
| 单日移动量最高 | u16 + 日期 | 与遭遇不同 —— 可能遇得少但走得远 |
| 单日新地点最多 | u8 + 日期 | 探索性最强的一天 |
| 最长连续照料天数 | u16 | 养成线的核心纪录 |
| 最长连续出门天数 | u16 | 探索线的核心纪录 |
| 最高亲密度 | u8 | 即使主宠换了也留着 |
| 最稀有捕获 | species u8 + rarity u8 + 是否闪光 | 「我抓到过一只闪光快龙」 |

### ② 累计统计（只增不减）

| 统计 | 字段 |
|---|---|
| 总遭遇数 | u32 |
| 总捕获数 | u32 |
| 总移动量事件 | u32 |
| 总游戏天数 | u16 |
| 各 biome 遭遇分布 | 5 × u16 |

biome 分布那一项有个额外价值：它会**告诉玩家自己的生活形态** ——
「你 78% 的遭遇发生在住宅区」这句话本身就是个有意思的反馈。

### ③ 近期趋势（滚动窗口）

保留最近 **14 天**的每日摘要，用于「本周 vs 上周」对比：

```
每日摘要 6 字节 × 14 = 84 字节
  日期偏移  u16   （相对首次启动的天数）
  遭遇数    u8
  捕获数    u8
  移动量    u8
  新地点    u8
```

14 天而非 30 天：够做周对比，又不占太多。而且
[存档总量](S6-save.md)要控制在 1KB 量级。

## 数据结构

```
offset  size  field
0       2     单日遭遇最多
2       4     ↑ 发生日期
6       2     单日移动量最高
8       4     ↑ 发生日期
12      1     单日新地点最多
13      4     ↑ 发生日期
17      2     最长连续照料天数
19      2     最长连续出门天数
21      1     最高亲密度
22      1     最稀有捕获 species
23      1     ↑ rarity + 闪光标记(bit7)
24      4     总遭遇数
28      4     总捕获数
32      4     总移动量事件
36      2     总游戏天数
38      10    各 biome 遭遇分布（5 × u16）
48      84    近期 14 日摘要
                              = 132 字节
```

## 核心逻辑

纪录更新在**日切时**统一做，而不是每次事件都比对：

```
检测到日期变化（复用 PetState.advance() 里已有的时间推进）
  → 把昨日累计值与各项纪录比对，破纪录则更新
  → 昨日摘要写入 14 天环形缓冲
  → 清零当日计数器
```

日切做而非实时做的理由：**省 flash 写入**。纪录只在日切时可能变，
实时比对不会更准，只会多写。这与
[2.4 的 flash 磨损策略](../02-sensing.md#flash-磨损)一致。

连续天数的判定需要小心：

```
连续出门 = 昨日 motion_events > 0
连续照料 = 昨日至少执行过一次 feed/play/rest
中断则归零，但**历史最长值保留**
```

⏳ **待 Phase 0 验证**：所有阈值都依赖真实遭遇频率与 RTC 精度。
特别是「日切」判定 —— 若
[RTC 漂移严重](../02-sensing.md#25-无连接带来的时间问题)，
日期边界会不准，连续天数可能误判。**这是 S10 唯一的硬依赖。**

## 破纪录的表现

纪录本身不产生玩法，**被看见才产生**。所以：

| 时机 | 表现 |
|---|---|
| 日切时破纪录 | 下次点亮屏幕，[P1 待机](../pages/P1-idle.md)顶部出现一行提示 |
| 查看成绩页 | P7，见下 |
| 连续天数里程碑（7/30/100 天） | 一次性提示 + 主宠心情加成 |

里程碑给心情加成是刻意的 —— 它让「坚持」这件事有机制上的回报，
而不只是一个数字。

## 与三键约束的关系

新增 [P7 成绩页](../pages/P7-records.md)，从 P1 进入。

但这里有个三键预算问题：**P1 的三个键已经占满了**（A 照料 / B 图鉴 / C 遭遇）。

解法：**P7 挂在 P6 图鉴之后** —— 图鉴页按 B 翻页，翻到最后一页再按 B
进入成绩页。理由是图鉴与成绩都属于「回看类」内容，玩家的心智模型接近，
而且这两个都不是高频操作。

```
P1 ──B──→ P6 图鉴 ──B(末页)──→ P7 成绩 ──C──→ P1
```

## 边界情况

| 情况 | 处理 |
|---|---|
| 首次启动（无历史） | 所有纪录为 0，显示「还没有记录」而不是一堆 0 |
| RTC 漂移导致日期回退 | 日期只允许前进。回退时按「同一天」处理，不清零计数器 |
| 连续 14 天没开机 | 摘要缓冲全部过期，连续天数归零但历史最长值保留 |
| 主宠更换 | 最高亲密度**保留**（那是玩家的成绩，不是宠物的） |
| u16 溢出（总遭遇 > 65535） | 累计值用 u32，单日值用 u16 —— 单日 6 万次遭遇不可能发生 |
| 数据损坏 | 由 S6 的 CRC 保护。成绩不可再生，与养成数据同级 |

## 若将来有第二台设备

BLE 相遇时可以交换成绩摘要，那时「排行榜」才有真正的对手。
数据结构已经为此留了余地 —— 132 字节的成绩块整体可以塞进一次 BLE 传输。

但**现在不实现**，理由同
[4.4 交换](../04-gameplay.md#44-交换与对战)：单机场景没有对象。
