# 三、地点属性与刷新机制

属性分布不需要知道玩家在地球何处，只需要知道**「这里和别处不一样」** ——
而电磁环境天然携带场所语义。

这里的关键设计决策是：**不要先做「识别这是公园还是商场」的场景分类，
而要先做更底层的一层。**

## 3.1 微观层：每个路由器就是一个刷新点

不先定义地点再往里塞怪，而是直接把每个 BSSID 当成独立刷新点：

```
seed      = hash(BSSID ^ time_bucket)         // time_bucket = 小时/半小时
spawn     = table[seed % N]                   // 出什么
type_bias = semantic(OUI, SSID, authmode)     // 属性倾向
distance  = f(RSSI)                           // 雷达上离你多远
```

好处是一串的：

**跨设备天然一致。** 两人站在一起看到同一批 BSSID，算出同一批怪，
不需要服务器和同步 —— **共享世界白送**。

**密度自动正确。** 市中心一次扫到 40 个 AP、郊区扫到 3 个。
这个梯度与原版城乡差异完全同构，**一行代码都不用写**。

**稀有度可直接挂在 AP 属性上。** 罕见 OUI、隐藏 SSID、企业级 WPA-Enterprise、
信号极弱只能偶尔扫到的 AP，天然就是稀有刷新点。
而玩家开始追着奇怪的路由器跑这件事本身就很对味。

## 3.2 SSID 与 OUI 是被低估的语义金矿

扫描返回的 `wifi_ap_record_t` 里有 SSID、BSSID、RSSI、channel、authmode。
前两个字段的信息密度被严重低估了。

**OUI（BSSID 前三字节）可直接查厂商**，而厂商强烈暗示场所类型：

| OUI / 特征 | 暗示场所 | 可映射属性 |
|---|---|---|
| 锐捷 / H3C / 华为企业 / Aruba / Cisco | 园区、写字楼、学校 | 钢、超能 |
| TP-Link / 小米 / 水星 / 迅捷 | 住宅 | 一般、妖精 |
| 运营商网关（CMCC / ChinaNet 系） | 民用宽带、公共热点 | 电 |
| 手机热点（Apple / 三星 OUI 且短命） | 人流聚集 | 格斗、超能 |

**SSID 文本更直白，它就是人类写的地名。** `xx小学`、`Starbucks`、`xx地铁`、
`xx医院` —— 直接关键词匹配就能拿到强语义。

而且**同一 SSID 对应大量 BSSID = 大型统一部署**（商场、机场、校园），
这个信号极强，能一眼区分「一栋楼里的几十个路由」和「一片住宅区的几十个路由」。

`authmode` 也有用：Open = 公共商业场所，WPA2-Enterprise = 机构/校园，
WPA2-PSK = 住宅/小店。

> **注意：AP 的 BSSID 是稳定的**，客户端 MAC 随机化不影响这套方案。

实现见 [`sim/gameplay.py`](../sim/gameplay.py) 的 `OUI_SEMANTICS` 与 `ssid_semantics()`。

## 3.3 宏观层：biome 由聚合统计决定

在微观层之上，用**整个扫描结果的聚合统计**决定这一片区域的整体属性分布：

| 特征 | 计算 | 指向 |
|---|---|---|
| AP 密度 | 可见 BSSID 数 | 低=野外/公园，高=市区 |
| 企业 OUI 占比 | OUI 分类比例 | 高=办公/园区 |
| SSID 聚合度 | max(同 SSID 的 BSSID 数) | 高=商场/机场/校园 |
| 开放网络占比 | authmode==OPEN 比例 | 高=商业公共区 |
| BLE 设备密度 | BLE 扫描计数 | 高=人多（耳机、手环、信标） |
| AP 集合流失率 | 相邻扫描的 Jaccard 距离 | 高=移动中/交通枢纽 |

这几个数丢进**一棵手调决策树或几百参数的小 MLP 就够了**，
C3 跑得动，不需要引入真正的 ML 框架。

> **硬限制：ESP32-C3 只有 2.4GHz，扫不到 5GHz。**
> 现代写字楼里那些 5G-only 的 AP 完全看不见 —— 那种地方在设备眼里会显得比实际稀疏。
> 这个偏差得在阈值里补偿掉。

## 3.4 声学是第二根轴

射频有个根本盲区：**它看不见自然环境。**
公园和荒地在射频上都是「没什么 AP」，但玩法上应当完全不同。

声学正好补这一刀，且**不需要做真正的音频分类**，几个频带能量比就能分开：

| 声学特征 | 环境 | 属性 |
|---|---|---|
| 低频持续轰鸣 | 车流/道路 | 一般、钢 |
| 高频宽带 + 间歇啁啾 | 鸟鸣/树叶 | 草、虫、飞行 |
| 稳定宽带白噪 | 流水/喷泉 | **水** |
| 混响重 + 中频人声团 + 音乐 | 商场室内 | 电、火 |
| 极安静 | 夜晚/室内 | 幽灵、恶 |

**射频密度 × 声学环境两轴交叉，属性表就出来了：**
低 AP + 鸟鸣 = 真公园（草/虫），低 AP + 安静 = 荒地/深夜（恶/幽灵），
高 AP + 混响 = 商场（电/钢）。比单轴精细得多。

## 3.5 水系：一个诚实的难题

射频看不见水，声学也只有贴着水边才听得到。因此建议**不要硬解，
让水系成为稀缺解锁而非常规 biome**：

1. 声学检测到持续水声 → 临时开启限时窗口（几分钟）
2. NFC 标签铺在水族馆、公园、景区 → 官方水系点位
3. 玩家众包标注 + BLE 相遇时传播共识 → 民间水系点位

**这不是妥协 —— 稀缺本身就是好设计。传说级 biome 本就应该难找。**

## 3.6 一致性：这块不做好整个体验就崩了

同一个地方每次去必须给出同样的属性，否则玩家感知到的只是随机噪声，
**世界感会立刻消失**。三条硬规则：

**① 首次分类后冻结。** 地点第一次判定完 biome 就写进 flash，之后不再重算。
世界是被**发现**的，不是每次重新掷骰。

**② 迟滞 + 时间投票。** 切换 biome 需连续 N 次扫描都指向新类别，单次异常不生效。

**③ 刷新用确定性 PRNG，不用 `rand()`。** `hash(BSSID, time_bucket)`
保证任何设备任何时刻重算结果一致。

第三条还有个副作用很香：**玩家可以预测。**
「这个 AP 每天下午三点出火系」—— 一旦规律可被发现，
社区会自发做攻略、排表、蹲点。**原版的巢穴文化正是这么长出来的。**
