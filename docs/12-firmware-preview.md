# 固件同源预览

最新页面样式与 151 种正背图核验见 [统一金银界面与宝可梦素材](13-game-ui-and-art.md)；本文下方早期构建号和截图是当时的验收记录。

2026-09-07：P0–P6、P9 可以直接在浏览器运行固件的页面绘制代码。P7 成绩、P8 取名在固件中尚未实现，只能查看设计稿。

启动：

```bash
./tools/inspector/serve.sh --port 8766
# 浏览器：http://127.0.0.1:8766/firmware.html
```

也可以只启动同源预览，不构建其余数据分析面板：

```bash
/usr/bin/python3 tools/inspector/server.py --port 8766
```

需要本机 C 编译器；原生预览服务只使用 Python 标准库。其余 inspector 面板构建还需要已有的 fontTools。源码或资产变化后点击「载入场景」会重新编译 C；修改 Python 服务本身需要重启服务。

## 实际调用链

```text
浏览器的页面选择 / A B C / 时钟步进
  → 本地 server.py → 独立 native 进程
  → 固件 nav.c / play_*.c / battle.c / battle_fx.c / battle_hud.c
  → 固件 assets.c / render.c / screen.c
  → LCD transport 替身接收实际 RGB565BE 字节
  → 浏览器解码 + Canvas.putImageData
```

八页的坐标、字体点阵、透明色、整数缩放、技能图元、横带裁剪和 SPI 色序来自实际固件代码。浏览器不再另外计算布局或绘制字体。80px 辅助线是独立的 CSS 叠层，不进入原始 Canvas，也不进入保存的 PNG。

宿主保留生产 `screen.c` 的单条 240×80 缓冲和字节交换，LCD 替身在生产代码发出 DMA 等待命令后才消费指针。全屏输出缓冲只存在于开发机；没有给 ESP32 增加全屏缓冲。

程序按 C 源码、头文件、7 个实际资产文件和宿主适配器的 SHA-256 编译到 `.build/firmware-preview/`。每个浏览器会话有独立状态；右下方显示当前构建编号，重新载入场景才切换到最新构建。

预览默认实时运行，A/B/C 触发的转场与动画会自动推进。原先默认停在 0ms，P2 按 A 后转场定时器无法运行，期间又锁住后续按键，表现为按钮无效。现在需要逐帧检查时明确点击「暂停」；「单步 60ms」和「检查横带重绘」也会先暂停。手动暂停跨切页、载入场景保留；标签页隐藏时停钟，返回后按原状态继续。暂停提示会说明转场需要继续运行或单步推进。

## 验证与边界

```bash
/usr/bin/python3 tools/pipeline/verify_firmware_preview.py
node tools/pipeline/verify_firmware_clock.js
/usr/bin/python3 tools/pipeline/verify_battle_layout.py
/usr/bin/python3 tools/inspector/build.py
/usr/bin/python3 tools/pipeline/verify_sim_pages.py
```

新增验证直接运行八页和真实导航、按键、定时器回调，比较局部刷新保留的画面与同一时刻的整页重绘，覆盖对战、捕获和转场。P4 在绘制时读取时钟，因此比较使用最后一次推屏的时间，避免把两次刷新之间的时间差误报为残影。删除 DMA 屏障的临时副本必须失败。浏览器实际使用的 RGB565 解码器还会对全部 65,536 个色值核对。

本轮最终验证共 848 次局部/整页对照；删除宠物所在脏带绘制的临时副本也必须检出残影。P2 的 B 长按丢弃已通过真实页面验证。`verify_web_coords.py` 作为兼容入口转调这条实际渲染门禁：原来比较两份坐标的迁移表已退休，不再把历史 JS 参考稿的坐标当作固件权威；它不用于证明布局没有重叠。

浏览器 Canvas 的逐页读回记录见 `reports/browser-firmware-parity-2026-09-07.json`。7 页加 8 个金银对战状态共 15 帧与独立 native 进程的 RGBA SHA-256 完全一致；320/835/1280px 窗口分别保持 1/1/2 倍整数缩放、没有横向溢出。这份证据覆盖逻辑像素和字节传递，不代表已经验收实际 LCD 的刷新耗时、DMA 中断、色彩校准或物理显示。

上述文件保留的是敌方上移之前的构建。追加修复的浏览器按键流程、暂停/单步和两帧 Canvas 对账见 `reports/preview-followup-2026-09-07.json`，构建为 `0019a1c61cb1dea5f36e`。另用独立原资产解码核对 151 只敌方精灵，共 2,355,600 个 RGB565 像素完全一致；16 只的透明源画布虽超出屏幕右边，实体像素仍完整保留。尺寸、素材哈希与截图见 `reports/evidence/firmware-preview-2026-09-07/aligned-layout.json`。

世界状态由确定性测试场景提供，保留页面依赖的队列、养成、捕获和经验操作，代替 WiFi 扫描、NVS、音频、后台任务与真实时钟。这些服务不能由预览代替真机验收。测试场景不会读写硬件存档。

原「页面模拟器」保留为 JS 参考稿和美术设计稿。它的 `sim/` 剧本与实际固件的随机源、交互状态、时间轴并不完全一致；共享两个元素不能证明整页同构。整页渲染验收以「固件同源预览」为准。

## 本轮技能接线

战斗结果增加稳定的 `move_id` / `move_type`，表现读取该结果，不改变伤害、命中率或学习表。共享 `battle_fx.c` 使用真实 GSC OAM 图元，按本项目的短时节奏重排；不宣称仿真原作时序。未命中不画伤害特效；最后两个空帧把位移和叠加效果清干净。

技能阶段固定重绘前三条横带，消息区只在换回合时重绘。最长每回合 18 × 60ms，40 回合上限约 43.2 秒；真机完整结算观察应留出余量，例如 `walk.py --settle 46`，不能继续按旧的 24 秒上限判断。

现有 99 招全部有表现，46 个 ID 定向映射，其他按 15 个属性使用共享效果。46 个映射不代表 46 套独立动画；本轮没有新增伤害、状态或 PP 机制。35 张固定来源的 GSC OAM 图元共 3372B，原图转换可复现。敌方上移后的构图通过 45,984 个相位案例和八项负向检查，覆盖双方、不同可见尺寸、落空、尾帧、HUD 遮挡、位移同步和顶部效果裁剪。精灵与效果共用按可见轮廓限制后的位移，大体型精灵不会向左侵入状态区。

## 金银对战布局

P3 已恢复原版 HP 前缀、空条黑底线、野生方端帽和我方阶梯端帽；原版框 1 构成完整消息窗，经验条也使用原始 tiles。所有组件在 `battle_hud.c` 中共享，原品素材来自固定的 `pret/pokecrystal` commit，构建与运行无需本地源码副本。详见 `reports/page-layout-2026-09-07.md` 的来源与像素差分证据。

白色背景与整数 2 倍图块对应原版呈现规则。240px 屏幕采用原函数已支持的可变 HP 条长度：4 个填充 tile，加标签/端帽共 112×16；保持原版 48px 归一化的三色阈值及非零 HP 最少 1 个源像素。不是将原版整块拉伸到 1.5 倍。

敌方状态位于左上，front 精灵以整数 2 倍放在右侧。根据截图反馈，已从下缘 y160 改为可见轮廓顶边 y30，与 HP 行对齐；可见右缘统一 x232，不让源素材透明留白造成上下错位。保留全部源像素，只在进场时扫描一次轮廓。主宠背图位于左下，状态从 x112 开始，血条与数值右缘 x232。HP 数字 y208、EXP tile 行 y224 分离。底部消息窗 240×80，文字安全边界 x12..228，三行 y256/274/292；结算两端文字最小净空 32px。新增提示用字已随正常固件构建补入字库。

追加修复后的 ESP-IDF 构建通过，应用 `PokeWalk.bin` 为 0x175cc0 字节，低于 3MB app 分区。既有的 1MB recovery 分区容不下应用的警告仍在；没有改分区或刷写设备。

P1 的四条进度条也已统一 x80..232，为最长的“今日行程”保留 64px 标签列和 8px 净空。

## 照料与图鉴的正面图

P5 普通照料和进化前后都使用 `assets_front_sprite` 返回的实际尺寸。40/48/56px 正面图按整数 2 倍居中放在右侧 112×112 区域（x120、y54），与左侧动作、下方状态条分开。每次照料或进化帧重绘全部横带，避免大尺寸精灵跨带后留残影。

P6 保留 5×4、每页 20 只、共 8 页的分页规则。正面素材通过共享 C 渲染器最近邻取样为 32px 缩略图，图片与编号居中；已捕获用彩色，见过未捕获用同一正面图的单色剪影，未见过只显示编号。缩略图会省略部分源像素以适应小格，照料和对战仍使用完整素材的整数放大。浏览器继续显示 C 输出，没有另画这两页。
