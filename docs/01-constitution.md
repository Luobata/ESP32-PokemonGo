# 一、设计宪法（L0 约束层）

这不是一项待办任务，而是所有参与者都要背下来的边界。

这类项目最常见的失败方式是：策划做出了一个很好的游戏，然后发现电池撑不住、
三个键点不动、flash 塞不下。**因此硬件约束必须在策划落笔之前定稿。**

## 1.1 硬约束清单

| 约束 | 内容 | 对设计的直接影响 |
|---|---|---|
| **电池** | 500mAh；WiFi 扫描峰值约 200~300mA 脉冲式，TFT 背光常亮数十 mA | **屏幕不能常亮，游戏不能实时** —— 这是最重要的一条 |
| **射频频段** | 仅 2.4GHz，扫不到 5GHz | 5G-only 部署的现代写字楼在设备眼中异常「稀疏」，阈值须补偿 |
| **音频通路** | **ES8311 codec，I2S 全双工**（MCLK/BCLK/WS 共用，DOUT 播放 + DIN 录音） | 播采样音频可行；实时 chiptune 仍是首选（省 flash），但不再是唯一选择 |
| **显示带宽** | 240×320×16bit ≈ 150KB/帧，SPI 传输受限 | 大色块 + 局部重绘 + 低帧率，不做骨骼动画 |
| **输入** | 3 键，无触摸。**BSP 提供四种事件**：PRESS / CLICK / DOUBLE / LONG | 菜单必须线性化；但 3 键 × 4 事件 = **12 种输入**，比「只有三个键」宽裕得多 |
| **算力与内存** | ESP32-C3FH8X：单核 RISC-V 160MHz，**实测可用堆 ~187KB**（物理 400KB SRAM 扣掉固件静态占用），8MB 片内 flash，**无 PSRAM** | 扫描/音频/渲染必须错峰；**无法整帧缓冲**，必须分块渲染 |

### 型号读出的事实

`ESP32-C3FH8X` 的命名可直接拆解：

- **FH8** = 8MB flash，且 `H` 表示 flash 封装在芯片内部
- **X** = 单核 RISC-V

C3 系列本身不支持外接 PSRAM，所以**约 400KB SRAM 就是全部可用内存**。

**但 400KB 是物理总量，不是可用量。** 真机启动日志实测：

```
heap_init: At 3FCB1B30 len 0000E4D0 ( 57 KiB): RAM
heap_init: At 3FCC0000 len 0001C710 (113 KiB): Retention RAM
heap_init: At 3FCDC710 len 0000294C ( 10 KiB): Retention RAM
heap_init: At 50000020 len 00001FB8 (  7 KiB): RTCRAM
                                     ─────────
                                      187 KiB  可动态分配
```

而且那是**跑一个已有玩法时**的余量（LVGL + WiFi 栈已初始化）。
全屏 16bit 帧缓冲需要 150KB —— 占掉可用堆的 **80%**，而不是原先估的三分之一。
「不能先在内存里画好再推屏」这条结论不仅成立，而且比原来更硬：
必须逐条横带分块渲染，**全屏转场特效可以彻底放弃**。

## 1.2 由约束推导出的核心形态

电池预算直接决定了玩法形态，这件事比美术风格重要得多。结论是：

> **设备揣在兜里，后台低频扫描、静默累积事件；
> 玩家偶尔掏出来，在 30 秒内处理完一批。**

形态上更接近 Tamagotchi 与宝可梦步行者，而不是掌机。

这听起来像妥协，实际是白捡的好处：

- 美术不需要连续动画，只需要**打开瞬间的高光时刻**
- 不需要实时战斗系统，回合制或自动结算就够
- 玩家一天摸设备五次、每次 30 秒，比一天连续玩 40 分钟更适合这个品类
- 三个键的操作压力大幅下降

**这条定下来，玩法层和表现层的设计空间立刻收窄一半 —— 这是好事。**

## 1.3 已确认与待实测

### 硬件事实的权威来源

**目标机确定为 FoloToy AI Passport**（<https://github.com/FoloToy/ai-passport>）。
它的规格与本项目的硬约束几乎逐条吻合 —— 240×320、三键、ESP32-C3、8MB、无 PSRAM ——
所以不是「移植到一台凑合的板子」，而是这台板子本来就是这个形态。

事实优先级（照抄上游 AGENTS.md 的约定，避免两边打架）：

    产品规格与实测 → components/bsp/include/bsp_pins.h → BSP 头文件与实现
    → 硬件指南 → README/demo

`bsp_pins.h` 是**单一事实来源**。本节下面的表若与它冲突，以它为准。

### 已结案（★ = 由 AI Passport 的 BSP 新确认）

| 项 | 结论 |
|---|---|
| **IMU** | **确认无。** 官方规格表以「里面装了什么」为题穷举了全部器件（彩屏、按键、麦克风、扬声器、Wi-Fi、蓝牙、被动 NFC），其中不含任何传感器。传感器一向是卖点，有则不会漏写。**步数统计因此不可实现** |
| **flash / PSRAM** | 8MB 片内 flash，无 PSRAM（从型号 FH8X 与 C3 平台特性确认） |
| ★ **屏幕型号** | ST7789P3，240×320，4-line SPI，`SPI2_HOST`，**PCLK 40MHz**，出厂需反色（无条件发 `0x21 INVON`）。复位脚未接 MCU，走 SWRESET 软复位 |
| ★ **背光** | GPIO21，LEDC PWM 调光（10-bit，5kHz）—— **可编程调暗**，续航策略多一个手段 |
| ★ **按键电路** | 三键**共用一个 ADC 引脚**（GPIO0 / ADC1_CH0），靠分压电阻区分：上 0mV / 下 ~300mV / 确定 ~595mV / 松开 3300mV。不能改用内部上拉（约 45kΩ 精度差，三档会挤到 0~154mV 并随温漂重叠） |
| ★ **按键事件** | BSP 提供 PRESS / CLICK / DOUBLE / LONG **四种**。这推翻了「三键 = 三种输入」的隐含假设 |
| ★ **音频通路** | **ES8311 codec + I2S 全双工**（MCLK=6 BCLK=5 WS=3 DOUT=2 DIN=4）。不是 PWM，也不是「无 DAC 只能硬凑」—— 有专门的编解码芯片，还能录音 |
| ★ **电量计** | CW2017（I2C 0x63），`bsp_battery_soc()` 直接读百分比。**续航实测不再需要外接电流表** |
| ★ **分区布局** | app 上限 **3MB** @0x10000；`cardid` @0x356000；`recovery` @0x700000（永久，上键长按 5 秒进入）。这三条是小程序 BLE 安装的**强制契约**，不能改 |
| ★ **工具链** | ESP-IDF **5.5.3**，UI 用 LVGL（非线程安全，跨任务访问要 `bsp_lvgl_lock()`） |

资产占用核对：我们现有 6 个 bin 合计 **158.8 KB = app 分区的 5.2%**，
再加固件本体（估 1.2MB）仍有大量余量。

### 待实测（★ = AI Passport 让它变得可测）

| 待确认项 | 为什么关键 | 怎么测 |
|---|---|---|
| ★ **不同扫描占空比下的续航天数** | 决定扫描频率上限，进而决定「地点」的时间分辨率与遭遇频率 | **`bsp_battery_soc()` 定时采样即可**，不用拆机接表 |
| **外置 32.768kHz 晶振是否存在** | 决定深睡走时精度，进而决定养成线的时间尺度能做到「小时」级还是只能「天」级 | 烧最小固件深睡 12 小时对比时间；或查 `sdkconfig.defaults` 的 RTC 时钟源 |
| **NFC 是静态标签还是 I2C 动态标签** | 决定 NFC 能否承载真正的双向交互，而非仅身份识别 | 手机 NFC Tools 贴一下读型号。NT3H21xx / ST25DV 是动态标签。**注意 BSP 里没有 NFC 相关引脚**，倾向静态标签 |
| ★ **口袋 RSSI 基线** | 阈值标定 —— 现在用的是电脑天线数据 | 有设备了，装兜里跑一轮采集与桌面对比 |
| **麦克风采样率与 ADC 通路** | 决定声波数据传输能否跑通、超声频段（>18kHz）能否使用 | I2S DIN 已接（GPIO4），实测采样率上限 |

「被动式 NFC」这个措辞本身很含糊。若只是静态标签，则设备能被手机读写、但它自己读不了别的标签，
两台设备互贴也不可能（都是被动侧）—— 这条要死心。
**BSP 引脚表里确实没有 NFC**，这加强了「静态标签」的判断。

## 1.4 这些约束如何塑造了设计

值得单独指出的是：**约束在这个项目里不止是限制，还是风格来源与机制来源。**

| 约束 | 表面是限制 | 实际带来了什么 |
|---|---|---|
| 屏幕不能常亮 | 做不了实时游戏 | 逼出了 Tamagotchi 式的「后台累积 + 短会话」形态，而这更适合随身设备 |
| ~~无内置 DAC~~ **有 ES8311 codec** | ~~播不了采样音频~~ | 原推导「只能 chiptune」**是错的** —— 实际有专门的编解码芯片且能录音。但结论仍成立：chiptune 合成几乎不占 flash，与像素美术天然统一，所以仍是首选而非唯一选择 |
| 显示带宽受限 | 做不了流畅动画 | 「大色块 + 低帧率」恰好是 DMG 时代的原生表达方式 |
| 无 IMU | 做不了计步 | 逼出了「移动量」指标，反而**摇不出来**，比步数更抗作弊 |
| 无 GPS | 做不了地图玩法 | 逼出了 WiFi 指纹，而它在室内往往**比 GPS 更准**，且天生离线、隐私更好 |

最后一行尤其值得记住：**没有 GPS 不是这个项目的缺陷，而是它区别于原版的起点。**
