# 二、感知层：用环境指纹替代 GPS（L1）

GPS 只是实现手段。真正撑起该品类的是**地点身份、地点差异、移动激励**三件事，
而经纬度对「地点身份」只是充分不必要条件 —— 需要的是**场所指纹**，不是坐标。

感知层的真实能力决定玩法的上限，**因此必须先测出它能到什么程度，再定玩法**。
反向推进是最贵的错误。

> **两条贯穿本章的前提，与直觉相反但很关键。**
>
> **其一，扫描不需要连接 WiFi。** `esp_wifi_scan_start()` 在 STA 模式下工作，
> 不需要关联、不需要密码、不需要连上任何 AP —— 只要射频开着就能收到周围 AP 的 beacon。
> 因此整套方案在全程不联网的携带场景下完全成立。隐藏 SSID 也照样可用：
> beacon 里 SSID 字段为空但 BSSID 仍在，而指纹靠的正是 BSSID。
>
> **其二，真实使用中环境是静态的。** 绝大多数时间只在家、公司、通勤之间循环，
> AP 集合极少变化。这两条共同决定了本章的设计取向。

## 2.0 核心取向：WiFi 是上下文开关，不是内容生产者

初版设计假设**空间充裕**（城市有几百个 AP），因而让空间生产内容 ——
把探索值挂在「新见 BSSID 数」上。

**这个设计在真实使用场景下是错的**，因为它会衰减到零：
第一周你发现完所有东西，第五周设备就变成砖头。
**任何会衰减到零的指标都不能作为长期驱动力。**

真实情况是**空间稀缺、时间充裕**（三个地点 × 24 小时 × 7 天）。因此正确的取向是：

> **让时间生产内容，让空间调制内容。**

具体说：刷新事件按**时间**排程，地点只决定**出什么味道**。
这样即使一整天窝在家里，设备也在产出事件；出门只是换了产出的种类。
**设备永远不会没东西可看。**

Tamagotchi 的空间输入是零，照样能撑几个月 —— 这条路是验证过的。

## 2.1 五条感知通道

| 通道 | 能力 | 局限 |
|---|---|---|
| **WiFi 指纹**（主力） | 离线方案下，一个地点 = 最强 N 个 BSSID 的哈希集合，靠加权重合度匹配；也可把 BSSID 列表交给地理定位 API 换取真实经纬度，室内精度往往优于 GPS | 离线方案不知道自己在地球何处，只知道「回到了几号地点」；郊区 AP 稀疏时退化 |
| **WiFi 环境流失率** | 相邻扫描 BSSID 集合的 Jaccard 距离判断移动 | 无 IMU 时这是唯一的移动信号源 |
| **BLE** | 扫描附近玩家设备实现社交层（这是 GPS 给不了的）；部署 BLE 信标做定点站 | RSSI 测距很脏，只能分近/中/远三档。FTM 米级测距属待验证方向 |
| **NFC** | 视芯片类型而定，可做贴手机打卡/交换/对时，由手机 App 当联网桥梁 | 两台设备互贴不可能，都是被动侧 |
| **麦克风 / 扬声器** | 声波近场数据通道完成面对面交换；麦克风兼作环境传感器（见 [03](03-spawning.md#34-声学是第二根轴)） | 受环境噪声影响，需要物理上在一起 |

**硬件事实：规格表未列出 IMU，因此没有加速度计就无法统计步数** ——
这一点无法用算法绕过，WiFi 与麦克风都不能反推出步数。
移动量只能靠射频环境变化来估计（见 2.2 与 [04-gameplay.md](04-gameplay.md#412-移动量而非步数)），
其单位不是「步」而是「移动事件」。

## 2.2 稀疏环境下仍然可再生的信号

环境静态并不意味着无信号可用。关键是把指标从**「发现」换成「节律」** ——
转换次数、驻留时长、离开时长、时段与地点的组合，这些每天都会刷新，**永远不会衰减到零**。

| 信号 | 静态环境下的表现 | 可再生 |
|---|---|---|
| 地点身份 | 家与公司哪怕各只有 3 个 AP 也极易区分。答案只有三四个，但判别可靠性很高 | — |
| **驻留时长** | 家 20:00–08:00、公司 10:00–19:00、通勤各半小时 —— 这就是一份日节律 | 每天 |
| **状态转换** | 家→通勤→公司，一天两到四次。对 30 秒会话完全够用 | 每天 |
| **同地点昼夜指纹** | 家里凌晨三点与晚上八点的可见 AP 集不同（邻居设备开关、人回家），**三个地点白送变六到九个上下文** | 每天 |
| **久别重逢** | 三天没去过某地，回去给加成。奖励真实生活节律而非刻意乱走 | 永久 |
| **RSSI 微抖动** | 坐着不动与走到厨房，RSSI 可测量地变化。**不需要任何新 AP 就能在单一地点内部拿到额外分辨率** | 永久 |

## 2.3 降级阶梯

按实际环境从下往上选，越靠下越鲁棒。

| 层级 | 做法 | 代价与收益 |
|---|---|---|
| **A · 地点集合** | 不建指纹数据库，只维护 8 槽 LRU，每槽为 top-5 BSSID 哈希；匹配不上即「没去过的地方」，触发特殊事件 | 存储 8 × 64 = 512 字节 |
| **B · 单比特移动判定** | 相邻扫描的加权 Jaccard 距离过阈值即「在路上」 | **完全不需要数据库，极其鲁棒**。且「通勤中」本身就是一个 biome —— 路成了一个地方 |
| **C · 驻留累积** | 用「在各地点待了多久」「今天转换了几次」替代「见了多少新 AP」 | 表盘永远在动，不会衰减 |
| **D · 昼夜上下文** | 把「夜里的家」与「白天的家」当两个不同上下文 | 地点数免费翻倍，但依赖绝对时间（见 2.5） |

最坏情况是完全不出门（居家办公、单一地点），此时 WiFi 只剩 RSSI 微抖动这一点微弱的
「活着」信号，项目退化为纯 Tamagotchi —— **而这也没问题，它照样成立。**

## 2.4 匹配算法与两级扫描

稀疏环境要改一处：**AP 少的时候一个 AP 掉线占比很大**，等权 Jaccard 会误判。
因此按 RSSI 加权，让最强的两三个 AP 当锚点。

```
w(rssi) = clamp((rssi + 100) / 60, 0, 1)   // -100dBm→0, -40dBm→1
sig     = { (hash32(bssid), w) }  取 top-8

score(A,B) = Σ min(wA,wB) / Σ max(wA,wB)   // 加权 Jaccard, [0,1]
             ↑ 交集             ↑ 并集

match:      score >= 0.35 → 命中该槽
transition: 需连续 2 次扫描一致才确认（迟滞，防单次异常）
```

实现见 [`sim/sensing.py`](../sim/sensing.py)。

### 两级扫描

**扫描开销比直觉大。** 被动扫描要在每个信道停留超过一个 beacon 间隔（典型 100ms），
2.4GHz 十三个信道意味着一次全扫约 **1.4 秒射频全开**；按 30 秒一次算占空比约 4.7%，
这是个不小的数。

优化的关键洞察是：**做指纹不需要看全，需要看得一致。**

| 级别 | 范围 | 问的问题 | 用在何时 |
|---|---|---|---|
| **确认扫描**（便宜） | 仅 1/6/11 三个主信道，约 0.3 秒 | 我还在原地吗 —— 只要看到锚点 AP 就够 | 驻留时 |
| **完整扫描**（贵） | 十三信道全扫，约 1.4 秒 | 我在哪 | 锚点丢失时、每小时一次 |

配合自适应占空比（驻留退到 5 分钟一次，检测到 churn 加速到 30 秒），功耗能压下来不少。

> **一个诚实的张力：信道裁剪与稀疏问题会打架。**
> 家里只有 3 个 AP 时只扫 1/6/11 可能只剩 1 个，指纹就崩了。
> 因此规则必须是 **AP 数少时强制全扫，只在 AP 密集时才敢裁剪** —— 城里省电，家里不省。

### flash 磨损

**把工作集放在 RTC slow memory**（C3 有 8KB），只在状态转换时与每小时提交 flash。
连续几周每 30 秒扫一次，若每次都写 flash 磨损会很难看；
512 字节的地点表放 RTC RAM 刚好，深睡也不丢。

## 2.5 无连接带来的时间问题

不维持关联省下大量电（无需跟 beacon、无需 DHCP 与保活，纯扫描只在扫描窗口开射频后
立刻回深睡），但代价是**没有 NTP，设备不知道现在几点**。

这一条直接打在养成线上 —— [04 的三条状态轴](04-gameplay.md#432-状态轴与时间流逝)
与 2.3 的昼夜上下文都需要时间基准。

ESP32-C3 深睡时用 RTC 慢速时钟。**若板上没有外置 32.768kHz 晶振**
（成本敏感的设计通常省掉，需先确认），走的是内部 RC 振荡器，温漂很大，
一天误差可能到分钟级，几周后昼夜完全错位。

| 对时方案 | 做法 | 评价 |
|---|---|---|
| 烧写时对时 | 串口刷固件时写入当前时间 | 只对一次，之后一路漂 |
| NFC 贴手机对时 | 手机 App 往动态标签写当前时间戳 | 需确认 NFC 为 I2C 动态标签；但正好给 NFC 找到了真活儿 |
| **只在家连一次** | 预置家中 WiFi 凭据，回家自动连、只为 NTP、连完即断 | **推荐。** 不违反「不主动连接」—— 无需任何操作，且降级优雅（连不上就用旧时间） |

**一个可以缓解此问题的事实：养成状态只需要「过了多久」，不需要「现在几点」。**
饱食与体能可以只用相对时长，漂移无所谓；只有昼夜上下文需要绝对时间。
若对时方案都不理想，砍掉昼夜上下文即可，代价是地点数不能免费翻倍。

## 2.6 口袋标定：一个会坑人的实测陷阱

设备在**兜里**，而人体对 2.4GHz 衰减好几 dB，因此口袋中测到的 RSSI 会
**系统性偏低且更抖**。后果是**桌面上标定的阈值装进兜里就不准了**，
2.4 那条权重曲线必须用真实口袋数据重新标定。

更稳的做法是**不依赖 RSSI 绝对值，只用相对排序** ——
「最强的三个 AP 是谁」比「它们各是多少 dBm」鲁棒得多，对遮挡几乎免疫。
建议指纹匹配按排序进行，RSSI 绝对值只用于雷达距离显示这类容错高的地方。

## 2.7 抗作弊：这是无 GPS 方案的隐性优势

GPS 在移动激励上其实做得很烂 —— 漂移、代步车、飞人挂长期困扰原版。

而 WiFi 环境新鲜度**摇不出来**：计步器可以绑在电风扇上，
但没人能在自己家里摇出一百个新路由器。
这个指标比 GPS 里程更贴合「去新地方」的真实意图，也更难作弊。

## 2.8 隐私与合规

BSSID 属于位置关联数据。**本地哈希存储风险很低，一旦上传就涉及合规。**

这构成离线优先方案的额外优势，也是架构选型时应当计入的权重。
本项目的所有地点数据都以 32 位哈希形式存储，不保留原始 BSSID。
