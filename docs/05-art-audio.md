# 五、美术与音频（L3）

方向已定：**直接复刻初代 Game Boy 体感的像素风格。**

这与硬件约束高度契合 —— 低分辨率、大色块、低帧率、无骨骼动画，
恰好是 DMG 时代的原生表达方式。**约束在这里不是限制而是风格来源。**

## 5.1 视觉规范

需要在动工前定稿的规范：

| 项 | 说明 | 现在能定吗 |
|---|---|---|
| 调色板 | 严格 4 级灰阶的 DMG 复古，或 GBC 式有限彩色 | ✅ 能定 |
| tile 尺寸与网格 | 8×8 或 16×16 | ✅ 能定 |
| 精灵尺寸档位 | 主宠 / 野怪 / 图标各几档 | ✅ 能定 |
| 中文点阵字体 | 取舍与 flash 占用核算（这是 8MB 预算里的大头） | ✅ 能定 |
| **240×320 版式** | 等比放大留黑边（体感更纯）vs 全屏重设版式（信息量更大） | ❌ **需上手看观感** |

最后一项是**唯一真正被硬件阻塞**的。注意屏幕比例与 GB 原生的 160×144 并不相同：
240×320 是 3:4 竖屏，而 GB 是 10:9 横屏 —— 这不是简单的缩放关系，
等比放大会留下相当大的黑边。

### 渲染约束

由 [1.1](01-constitution.md#11-硬约束清单) 推出的硬性限制：

- **无法整帧缓冲**（150KB 帧 vs 400KB SRAM），必须**分块横带渲染**
- 全屏转场特效基本放弃
- 动画按「大色块 + 局部重绘 + 低帧率」设计，不做骨骼动画

## 5.2 音频路线

因 ESP32-C3 **无内置 DAC**（区别于经典 ESP32），音频路线指向**实时 chiptune 合成**
而非采样播放。这条路几乎不占 flash，且与像素美术在风格上天然统一。

### 已核实的库与许可

| 库 | 许可 | 说明 |
|---|---|---|
| **libxmp** | MIT | 最干净的 tracker 播放选择 |
| gbsplay | GPL v1+ | GB 音频播放 |
| cardputer-studio | MIT | ESP32-S3 groovebox，可参考 |
| PixelRoot32-APU | MIT | NES 风格 APU 核，可参考 |
| ~~ChiptunesOnAnS3~~ | **GPL-3.0** | **会传染固件，避开** |

两个需要注意的事实：

**目前不存在成熟的 ESP32 XM/MOD/VGM 播放器。** 移植 libxmp 在许可上干净，
但 flash 与 RAM 是否装得下**尚未验证** —— 400KB SRAM 是很紧的。

**Furnace Tracker 没有 MCU 原生导出格式**（只有 VGM、ZSM、TIunA、SAP-R 和音频文件），
其许可为 GPLv2+，且构建时启用 ASIO SDK 会使产物变成 GPLv3。

### 推荐路径

**CC0 预渲染音频 + 自己手写的极简 APU**，而不是引入 GPL-3.0 的现成固件方案。

## 5.3 素材来源

本项目**仅供自用、不分发**，因此**几乎所有许可义务都不触发** ——
CC 系列许可、GPL 的开源要求、署名义务，触发条件都是「分发」。
自己烧进设备自己玩，法律上属于私人使用。

**以下清单因此只按实用性排序，而不按许可宽松度排序。**

| 素材源 | 内容 | 实用性评价 |
|---|---|---|
| **PokeAPI + PokeAPI/sprites** | 初代 151 只的数据与 front/back sprite | **已采用。** 见下 |
| ~~Tuxemon~~ | 411 个原创怪物 | 已弃用 —— 与宝可梦零重叠，做情怀用不上 |
| Kenney.nl | 通用像素素材 | UI 元素补充用 |
| OGA「CC0 - Retro Music」 | 8-bit 音乐合集 | 音频首选，预渲染直接用 |

### 已采用：初代 151 只（PokeAPI）

**项目定位改为初代情怀**，因此数据源从 Tuxemon 换成了初代关都图鉴。
（Tuxemon 是完全原创的怪物集，与宝可梦零重叠 —— 做情怀用不上。）

已完成的转换（详见 [tools/pipeline/README.md](../tools/pipeline/README.md)）：

| 项 | 实测 |
|---|---|
| 数据 151/151 | 5.4 KB（含种族值、进化链、capture_rate、habitat） |
| front sprite（原生 40/48/56 三档） | 88.2 KB |
| back sprite @32×32 | 37.8 KB |
| **合计** | **131 KB，占 flash 1.60%** |

两个实测要点：**用 `gray` 变体**（depth=2、colortype=0、无 PLTE，真 4 级灰阶），
它的灰度值 0~3 就是 DMG 的 2bpp，转换零有损；默认路径是 SGB/GBC 的彩色版。
**front 尺寸不固定**（40/48/56 三档，按 5×5/6×6/7×7 tile 存），
必须按原生尺寸存 —— 统一缩到 40×40 会把超梦、卡比兽压小 30%。

**双视图刚好够用。** 原版每只只有 front 和 back，没有多角度、没有 shiny：
遭遇与图鉴用 front，主宠待机用 back（视角天然对 —— 你在它身后）。

这项工作完全在 PC 上进行，**不需要目标硬件**。

## 5.4 如果将来想分发

当前范围（自用、不分发）下本节不适用，保留在此仅作为**将来改变主意时的检查清单**。
**一旦分发，下列约束立刻全部生效**，而且有些是回头改不掉的。

### 现在这个方案，分发风险是不可缓解的

**项目已改用初代宝可梦的真实数据、名字与 sprite。这意味着「自研世界观」
那条 IP 保护线已经主动放弃了** —— 这是为情怀做的取舍，在自用范围内没有问题。

但要清楚代价：**这条不像许可义务那样可以事后合规，它是回头改不掉的。**

| 风险项 | 说明 |
|---|---|
| 角色与名字 | 宝可梦的角色设计与名称是任天堂的知识产权 |
| **商标** | 「Pikachu」这类名称**同时受商标保护** —— 独立于著作权的另一项主张 |
| sprite | 原版 sprite 是受著作权保护的具体表达（与「GB 风格」不同） |
| 数据 | 种族值、进化链、capture_rate 属于游戏数据，法律地位比 sprite 模糊，但不构成安全区 |

任天堂执法活跃：Pokémon Essentials 于 2024 年被下架，2015 与 2025 年均有 DMCA 记录。
**非商用与开源都不能缓解 —— 公开发布反而扩大分发范围。**

相比之下**「Game Boy 视觉风格」本身是可以自由模仿的** ——
四阶灰调色板、8×8 tile、低分辨率属于思想/风格与功能性约束，不在著作权范围内。
本项目也不涉及 ROM 提取：数据取自 PokeAPI，sprite 取自 PokeAPI/sprites 仓库。

> **结论：这个版本不要分发。**
>
> 如果将来真想分享或开源，唯一可行的路是**换掉全部宝可梦内容** ——
> 换成原创或 CC 授权的怪物集（如 Tuxemon）。而由于数值、进化链、
> 属性系统都与初代绑定，这基本等于重做素材层。
>
> 换句话说：**现在这个选择是单向的。** 这没关系 —— 你的目标就是自己玩。

这些**图像**须以 CC BY-SA 附署名发布，但固件源码可保持闭源 ——
二者属聚合而非派生关系。
