## 实现范围

- `firmware/main/battle_fx.c/.h`：无状态相位求值、攻击/闪避/受击位移、图元投射与叠加。全部整数运算，不申请内存，不新增固件帧缓冲。
- `firmware/main/battle.h/.c`：回合记录新增 `move_id`、`move_type`，保留实际选招结果供渲染派发。选招、伤害、HP、命中、PP与附加效果规则没有改变。
- `firmware/main/CMakeLists.txt`：编入 `battle_fx.c`。
- 主代理在 `play_battle.c` 接入这三个 API：`battle_fx_frames()`、`battle_fx_pose()`、`battle_fx_draw_band()`，并在每次相位变更重画舞台三个横带。

每拍 60 ms，每招共 12/14/16/18 拍，即 **720–1080 ms 的项目压缩节奏**。末两拍位移和图元均为空，负责清理上一相位。按 40 回合上限，最慢组合可达 43.2 秒；这是播放预算变化，不是伤害平衡变化。动画并非 GSC 原脚本逐帧仿真，不应称为“原作 1:1”。

像素守卫限定在 `y=40..159` 的舞台及 `x<104, y=160..235` 的主宠区域，保护右侧 HUD 和底部消息。主宠向右位移预算直接取共享布局中的“名牌左边界 − sprite 右边界”，当前最大 8 px；actor 与 overlay 读取同一份位移。未命中没有伤害图元，仅保留攻击/闪避动作；免疫的目标不受击抖动。

## 素材

新增 `tools/pipeline/convert_battle_fx.py`，从固定的 pret/pokecrystal 提交 `7a7881d0d62e0ddbd82dcf10e7116807487ac651` 读取 PNG、framesets 与 OAM 数据，按真实 tile 偏移、位置及水平/垂直镜像组装图元，保留四档像素索引。输入字节必须与固定 Git tree 一致。

产物为 **35 张 OAM 图元，3372 B 像素数据**，直接编入 `battle_fx_assets.h`；`assets/battle_fx_sources.json` 保存每个源文件和输出图元的 SHA-256。包括 HIT/PALM/KICK、CUT、火、水、冰、叶、岩石、闪电、星星、针/角、舌、泡泡与吸收球等。这里保存的是原作图元；位置、轨迹、组合节奏与属性调色板是本项目的改编。

```bash
python3 tools/pipeline/convert_battle_fx.py --src /tmp/pokecrystal --check
```

- 99 招 × 双方攻击 × 40/48/56 前视尺寸，合计 **25498 个相位案例**；所有招式都有可见像素，15 属性回退的最终像素序列互不相同。

- 在临时副本中故意加入“未命中仍画伤害”和“结束后残留位姿”两个缺陷，测试均失败并报告对应原因；未改动工作区源码来做变异。

主代理接线后另跑实际页面的 844 次增量重画与完整重画比较、65536 种 RGB565 解码对账、删除 DMA 屏障的反向检查，均通过。本子任务也在 native 预览中实走皮卡丘对小拉达战斗，对连续 18 个实际页面相位检查增量/完整帧相等，并读图确认电击已经进入生产页面。证据：[电击相位](evidence/battle-fx-native-electric-08.png)。

这些证据覆盖了实际 C 页面和宿主上的内存/像素行为，**没有代替 ESP32 烧录后显示时序与耗时测量**。最终 IDF build、浏览器 Canvas 对账以及后续布局调整由主代理统一收口。

## 原 JS 设计稿的纠错与未扩展项

`template.html` 的动画注册区已修复撞击、水枪、吸血、乱击、落石、连环巴掌、飞叶快刀、念力共 8 项 wait 问题，并把紧束来源更正为 Wrap。再次从 ID 追踪 pret 动画调用/循环，26 项登记的 wait 合计错误为 0；具体轨迹仍是设计稿近似，不因此升级为原作逐帧等价。

核查发现的 16 招物理/特殊分类问题、11 个被普通 power 过滤掉的特殊伤害招、PP/状态/吸血回血/多次命中等机制均未改动。新样式改善的是现有技能的可见表现，没有借动画扩充战斗规则。
