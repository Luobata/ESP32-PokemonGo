# 捕虫调查投球延迟与可见位置误判修复

本次依据社区反馈检查捕虫调查 P18。基础为主分支 `1d1710f8392df3c6709ca4522027b900ab12c632`；修复在 `codex/bug-survey-capture` 工作区，尚未提交或发布。

## 已复现的问题

- 普通捕获页已经处理 `PRESS`，捕虫调查仍只处理 `CLICK`，需要等松手和单击分类。BSP 的单击判定窗口配置为 180 ms，按住时间还会叠加。
- 捕虫调查的判定读取处理输入时的新时钟，没有使用 LCD 上最后呈现的指针。旧可执行文件实测：最后显示的位置在蓝区，随后 `CLICK` 却判失败；`PRESS` 本身不触发投球。
- 50 ms 的指针更新重画整屏 16 条带。原设备三次完整重绘为 42.033、42.527、41.275 ms。它们是绘制成本，不能当作动画 FPS。
- 先行修正输入与局部刷新后，真机仍测到投球前同步存档造成约 315 ms 的回调间隔。最终版本将该事务移到球飞出后的开球静止姿态，避免按下后先等待存档。

## 最终行为

1. 选中“投球”时按下 C 即锁定最后显示的位置并开始飞球；同一次手势的后续 `CLICK` 被消费。其他菜单仍用单击确认。
2. 同一帧所有条带使用同一个指针采样。蓝区两端与判定的包含边界一致；截图、唤醒重绘只重放该采样，不暗中改变判定。
3. 指针移动只提交覆盖捕获条的两条 20 行条带，文字和精灵不随指针重画。
4. 到原有开球静止姿态才同步提交事务。保存期间暂停演出时钟，恢复后继续吸入、落地、摇球与结果，不跳过动作。捕获判定仍使用按下时的采样。提交前中断不会扣球或发伙伴；提交失败显示错误、恢复路线音乐并允许新按键重试，不会因迟到的 CLICK 自动重试。
5. 保留原捕获公式、球种加成、三次机会和动作时间映射。没有把每帧时长加长来降低捕获难度，也没有异步借用世界事务工作区。

## 回归

- `verify_activity_capture_timing.py` 使用生产页面、导航、捕获算法和活动事务。覆盖 8 种球、1152 组位置/手势/保存延迟组合、蓝区端点、跨带一致性、失败重试、提交前中断与完整演出。旧可执行文件作为负对照；证据见 [timing.json](evidence/bug-survey-capture-2026-10-25/timing.json)。
- 模拟保存耗时为 0 / 180 / 400 / 2000 ms。按键处理本身不等待保存；总演出仅在静止提交处增加相应等待，约 9.15 秒出现结果、13.15 秒结束成功演出（另加事务耗时）。这些是宿主时钟测试，不是真机 NVS 延迟。
- 活动 UI、活动失败/重启事务、普通捕获与完整战斗时间线通过。宿主时钟适配器同时修复“保存耗时后倒退到旧定时器到期时间”的测试缺陷，以保证延迟注入可信。
- V5～V32 固定样本、USB 导入故障与预备份、双银行故障、真实 NVS 连续保存/GC/重挂载回归通过。仍为 V32 / 39,976 B 世界记录与格式 4 / 72 KiB 备份，没有结构、编号、分区或历史样本变化。
- 目标栈检查：活动页面最大单函数帧 288 B；RTC 使用 7,864 B、余 328 B；IRAM 79,360 B。新增状态为页面内瞬时标记和指针时间，不增加导入堆缓冲区。详见 [checks.json](evidence/bug-survey-capture-2026-10-25/checks.json)。

## 真机记录

同一台 AI Passport / ESP32-C3，亮度 100%，音频开启、Wi-Fi 扫描运行。原档与基线为 123 个伙伴；测试中结算过一只临时捕获的独角虫，最终版本采样时为 124 个，测试后从原备份还原。原始备份、完整原应用及串口日志保存在忽略目录 `.device-backup/bug-survey-20261025/`，公开证据不含设备身份或网络扫描数据。

最终应用为 3,228,432 B，SHA-256 `7b257c3436a23f9c46ef535a841b701443e97fa2a19e189048f63315c9509588`。只写应用区；受保护数据区逐字节回读一致，没有改动分区表。

- 最终固件连续三组指针采样，分别在约 10.1 秒中呈现 199 / 199 / 198 帧，约 19.63 / 19.68 / 19.64 FPS。每帧恰为两条带，平均绘制 6.58～6.67 ms、最大 9.312 ms；帧间隔 P95 桶上界均为 56 ms，最大 57.780 ms。`late` 仍保留全部超过 50 ms 的轻微调度偏差，没有删除样本。
- 最终固件完成三次实际投球，两次成功、一次失败，均能回到后续选择。捕获整窗含飞球、开球静止提交、摇晃等待、结果静止及退出后界面，不将其 LCD 提交次数称为连续动画 FPS。事务所在回调最长约 283～288 ms，发生在已经显示的静止球姿态；飞球开始不再等它，后续动作时钟不消耗这段时间。
- Wi-Fi 扫描持续运行；捕获期间音频统计未报告供数超时或通道错误，最大供数间隔 42.011 ms。观察到的最小内部堆 9,748 B、最大连续块 9,216 B；LVGL / 定时器 / 调试 / 音频任务所报栈余量分别为 4,924 / 3,544 / 1,624 / 1,976 B。不能把这些观测值当作所有存档规模的最坏值。

原版完整重绘与最终局部刷新的样本见 [hardware.json](evidence/bug-survey-capture-2026-10-25/hardware.json)。原版活动页没有正常循环采样入口，因此没有伪造“修改前实际 FPS”。

测试结束将持久化亮度由 100 调为 90（引脚读回 89），导入最初备份：覆盖前备份和磁盘回读完成，72 KiB 上传、暂存与匹配目标构建的重启回执通过，亮度恢复 100。再次导出后使用生产解码器比较，伙伴及技能策略、经验、图鉴、道具、成就、地区、挑战、活动、故事和雷达/地图进度一致。临时增加的伙伴及测试消耗均已回退，恢复为原 123 个伙伴、Lv.58 / 298,368 经验、三个遭遇，设备回到待机页。导入期间收到三组完整 Wi-Fi 扫描记录。见 [USB 回归](evidence/bug-survey-capture-2026-10-25/usb-roundtrip.json) 和 [语义比较](evidence/bug-survey-capture-2026-10-25/save-comparison.txt)。
