# 三语言、队伍闪光标志与配网改进

本批从公开版 `868a3f2` 开始，纳入此前尚未发布的配网改动。英文已按用户追加要求一并完成。发布仍更新原项目 234 / pokewalk，保留暴鲤龙封面和四张附图。最终发布回执见文末。

## 交付范围

- 「菜单 → 选项 → 语言」切换简体中文、繁體中文、English。菜单、剧情、系统提示、伙伴/招式名和设备配网页同步切换。中文官方/怀旧译名独立保留，切回中文继续使用原选择。繁体为固定 OpenCC 1.1.9 加游戏语境转换，不宣称某地区官方译名完全复刻。
- 英文 2,261 项文案、251 伙伴名和 251 招式名；使用固定来源像素 ASCII 字形。剧情、调查、背包等长文按词换行，保留推理信息；英文文字更多时阅读演出相应增长，仍可 C 完成当前文字。没有更改战斗、捕获的动作采样时钟。
- 六个物理队伍槽各自显示闪光 ★，普通伙伴没有标志。英文真机检查发现的狭窄状态位改为 `Lead`，照料/亮度说明缩短，避免截断。
- 配网期间 AP 独占，暂停旧网络重连及后台扫描；最多两个客户端，显示实际数量。先回 HTTP 确认，再等待四秒关闭热点并连接目标网络。只有取得 IP 后才保存凭据；缺网络、认证失败、连接中断、热点启动失败分别提示。
- 挑战页体能说明从旧“两小时”修正为“一小时”，恢复算法没有改变。

`http://192.168.4.1` 是设备临时热点里的配网页，不是开发机地址，也不能替换成 GitHub 站点。先连接设备当前 PW- 热点，使用 HTTP 访问。用户的“拒绝接入”反馈缺少手机/路由器和日志，本次修复可确认的风险路径，未宣称已复现该用户的特定根因。

## 存档、USB 与资源

世界格式仍为 V32 / 39,976 B，6 + 753 个体，原分区、72 KiB 格式 4 备份及历史 V5～V32 固定样本不变。只新增独立 NVS `pokewalk/language`（0/1/2）；旧档缺少该键时默认简体，写入失败不切换语言。CLI 直接恢复仍限制同设备/同构建，扩展仓库限制不变。

验证过程中两次导入超时均未覆盖原存档：初版一次停在 31,232 B 附近且与自动熄屏重合；禁止熄屏后的候选又一次停在 68,608 B。后者证明不能把所有超时都归因于熄屏。没有串口总线抓包，不能断言这两次究竟丢在数据还是回执。SDK 默认 USB 控制台存在有限缓冲和发送等待边界，可见 [官方 USB Serial/JTAG 文档](https://docs.espressif.com/projects/esp-idf/en/v5.5/esp32c3/api-guides/usb-serial-jtag-console.html)；它说明风险边界，不是本次具体丢失位置的证明。

实际修复：

1. 发送、等待预备份 ACK、接收、暂存期间暂停自动熄屏，取消后恢复原策略。
2. 已从 stdin 读出的字节在界面锁暂时不可用时保留，不能静默丢弃。
3. 新网页在传输停顿后用 `RPOS` 查询设备已提交偏移；只在匹配会话/请求、预备份 ACK 后的接收状态响应。只补发最后未确认块，或继续已确认位置；迟到 POS 不覆盖真实 NEXT 进度。连续重试最多三次，失败保留真实错误。没有放宽顺序、CRC、暂存内容、构建绑定或重启回执检查。

旧文件不需要编辑。新容错要升级固件并刷新网页/重新下载离线包；旧工具仍能读格式 4，但没有此恢复逻辑。devbox 按用户此前明确指示暂缓，本次使用 GitHub Pages 和 Release 离线包。

最终应用来自 `48b59fc3012b7031e50454bca9b1af09d557e9e3`；之后仅网页、测试及记录更新。应用 **3,381,200 B**，factory 剩余 **26,672 B**；完整包 **3,446,736 B**，未超过 8 MiB。应用 SHA-256 `e99ecc75c53befccab6dc3a38592776240ed89b55a6d3f5e0b464b0ec4f14f20`；完整包 `33e1b02cd7683bd72e77d82e0ed49442efcc44e9f4aef91dc322d7e8152cc994`。完整安装仍会覆盖 NVS，不能标注保档；优先使用严格回读保护数据分区的 USB 更新包。

字库、英文索引和词库放 Flash，无新增大块导入堆/栈缓存。RTC 使用 7,864 B、剩余 328 B；IRAM 79,360 B。目标最大单函数栈：language 48 B、settings 32 B、formatter 160 B、game_ui 592 B、USB 协议 688 B、dbg 256 B、Wi-Fi 752 B。目标栈检查通过不等于运行时堆已覆盖所有组合。

## 自动化检查

本地原始 62 项记录中的两个独立链接驱动遗漏新依赖，修复后分别重跑通过；保留原失败结果及通过日志，不覆盖为一次全绿。历史固定样本保持原字节。最终 CI 链接见发布记录。

- 真实生产解码、V5～V32 迁移、共享 Wi-Fi/其他命名空间占用、759 个体稠密技能策略、双银行/守卫引用、连续 NVS GC、故障注入/重挂载、USB 预备份 ACK 和覆盖恢复通过。满仓为宿主/隔离真实 NVS，非用户设备满仓实测。
- 英文 2,261 文案/251 物种/251 招式、129 个格式化容量、95 ASCII 字形；繁体 2,962 文案/18,203 字形查询及四阶段设置故障；ASan/UBSan 失败即退出。
- 21 个页面两种新增语言 1,221 次条带/整屏检查；英文 25 个剧情场景 857 次检查、17 个调查现场 976 次检查。与独立旧程序比较 251 物种/17 页面共 2,361 次检查，唯一额外允许差异为挑战页说明“2→1”的明确像素区域。照料/队伍完整周期另有 6,957 次局部重绘比较。
- 生产 USB 协议/界面 86.4 秒接收过程中不熄屏，取消后恢复；读出字节遇锁失败的负向对照可捕获旧缺陷。生产 C/网页分别模拟丢 RDATA、丢 NEXT、迟到 POS、非法位置/ID、无 ACK 查询及重试上限。
- 额外旧脚本 `verify_screen_idle_pages.py` 仍假定开场用 A 推进，在独立修改前基线也同点失败（实际当前操作为 C），非本批新增回归。没有将该脚本记为通过；当前输入/场景节奏/剧情/USB idle 检查另行通过。
- Linux CI 曾拦截两项测试诊断：单行 stub 缩进及故意无效 printf 宽度被 GCC 常量传播提前报错。测试探针改成 volatile 函数指针，生产格式校验不削弱。

## 真机与性能口径

同一 ESP32-C3、125 个实际伙伴、静音、音量设置 55%、亮度基线 100%。修改前应用与私人备份单独保存。`j` 为三次完整重绘，`J/K` 为正常循环 LCD 提交统计；不把完整重绘倒数叫 FPS，也不把 20 行条带当一帧。

| 场景 | 公开基线 | 三语言初版候选 | 说明 |
| --- | --- | --- | --- |
| 简体选项完整重绘中位数 | 40.589 ms | 41.509 ms | 同语言约 +2.3% |
| 繁体/英文选项完整重绘 | 无 | 44.949 / 48.369 ms | 新语言新增文本开销，不冒充同条件基线 |
| 照料，约 10 秒 | 21 次姿态提交 | SC/TC/EN 各 21 次 | 定时器 P95 88 ms，含设计静止阶段 |
| 队伍，约 10 秒 | 28 次姿态提交 | SC/TC/EN 各 28 次 | 定时器 P95 88 ms |
| 待机，约 10 秒 | 40 次提交 | 41 次左右 | P95 256 ms，目标 250 ms |

照料/队伍动作之间有停顿，帧间 P95 的 `4294967295` 只表示超出 504 ms 桶，不是实际毫秒数或卡顿结论。最大间隔仍约 2.02/1.22 秒，需结合未变化的姿态和 80 ms 回调判断。英文初版绘制最大成本照料 21.765 ms、队伍 13.306 ms，低于回调周期。

初版真机 AP 单客户端：Mac 连接设备热点，实际 GET 返回 200，英文表单完整，提交不存在的测试网络返回 200/313 B ACK，之后恢复 Mac 原网络。AP 开启时 free 9,264 B / minimum 9,080 B / largest 8,704 B。两台同时接入、实际手机/路由器成功校时及扬声器有声实听未测；两客户端事件与各种断连原因使用模拟。全程遵从用户要求静音，不将静音结果说成无爆音或音乐实听验收。

串口截图曾缺带，解析器拒绝了不完整数据；改进测试端读取后重新抓取完整图，没有将缺失字节补黑。私人热点密码、MAC、Wi-Fi 日志、原始 NVS/.pksave 不提交。

## 最终验收与发布

最终固件已用严格保档包烧录，应用与保护分区回读一致。真实 AP 开启后在同次启动中执行导入：主动丢弃 8,192 B 处 RDATA 和 16,384 B 处 NEXT，设备分别回报实际偏移，100.3 秒完整上传、暂存与重启匹配回执成功。此前失败尝试后的预备份与原档经生产解码比对，各项核心进度保持。

最终英文页再次采样：选项完整重绘中位数 49.668 ms；照料 21 次 / 9.975 s，队伍 28 次 / 10.033 s，二者回调 P95 88 ms；待机 41 次 / 10.134 s，P95 256 ms。亮度为导入后的 40%（驱动量化查询为 39%），因此该补测与亮度 100% 的原始基线分别记录。英文 `Lead` 和照料提示已在完整真机截图中确认无截断。

旧公开版备份在最终固件中覆盖恢复成功（上传 92.7 秒，无需续传），实际亮度 40%→100%，无语言键→简体，伙伴等级经验未变。另抽查野生出场、捕获指针及投球开头：指针 250 次 / 10.083 秒（约 24.79 FPS），P95 48 ms，单帧绘制最大 9.046 ms。投球开头含落盘暂停，最长提交间隔 324 ms，不能把该样本写成每帧恒定或全动画无停顿；没有作为原版完整时长的替代验证。当前只完成这次抽查，不宣称全部短动画三轮真机覆盖。

最终同构建导出再导入成功，上传 92.7 秒；同次启动先开关真实 AP，接收期间最低内部空闲堆 8,040 B，采样时最大连续块 16,384 B；dbg / timer / LVGL 栈余量分别 1,736 / 3,544 / 4,924 B。没有借用大堆缓冲。

再次导出后，生产解码逐项确认 125 个伙伴、技能策略、等级/经验、图鉴、遭遇、道具、挑战/秘境及城都各活动进度与原备份一致；包含捕获验收产生的临时变化也已还原。最终为简体、亮度 100%、静音、音量设置 55%。
