# 选宠、居中与捕捉规则跟进

本轮新增真实固件 P9 初始伙伴页，修正底部提示及精灵透明留白造成的偏移，替换精灵球素材，并调整 P3/P4 捕捉流程。浏览器仍运行实际 C 页面、字体、素材与 RGB565 输出。

## 可见行为

- P0 正常结束或跳过 → P9。可选妙蛙种子、小火龙、杰尼龟、皮卡丘；A 确认，B/C 前后循环。保存成功才进入 P1。已有存档不重新领取。
- `game_ui_footer` 不再固定画在 (12,296)。新公共函数按真实字形墨迹计算横纵居中；P1 背面、P5 正面与 P6 缩略图补偿原始透明留白，保留原图点阵和既有缩放比例。图鉴编号也按实际墨迹居中。
- 三种球采用固定 Crystal 源的真实球体、OAM 组合与红/蓝/黄配色。原版三球同形异色，成功后保留闭球。来源与独立逐像素对照见 `assets/ball_sources.json` 和 `reports/evidence/balls-original-2026-09-07/result.json`。
- 战前/战中投球失败：回同一场战斗，先执行野怪一次反击，反击动画完成前锁住绕过输入；随后继续自动战斗。血量、行动顺序、随机数状态按遭遇 uid/时间保留。
- 战胜后：只剩一次实际投球机会；取消尚未投出的球可以返回，投出后换球、连按、返回均不能恢复机会。失败立即按 uid 移除遭遇，成功只入队/点亮图鉴一次。战败后不能继续投球。

预览的页面下拉框现在载入对应的新测试场景，避免捕获结束后沿用失效的遭遇 uid，导致切到对战页又退回列表；游戏内 A/B/C 导航仍保留状态。

## 验证

固件同源预览构建：`788d5f7752742418ba6c`。

- 浏览器实际点击四种选宠、战前失败反击、战后成功/失败及列表移除；16 帧 Canvas RGBA 与相同输入的 C 渲染共 1228800 像素对照，零差异。证据 `browser-parity.json`。
- `verify_ui_centering.py`：612 项实际 C 画面检查，覆盖 151 只正面/背面在相应页面的可见居中、图鉴编号和公共页脚，两侧留白最多相差 1 px。
- `verify_starter_preview.py`：四种选择、完整/跳过开场、C 环绕、失败重试、全部页面导航守卫、已有主宠不重领、P9 HTTP 映射。
- `verify_starter.py --sanitize`：67 项实际 world/save/party/encounter 检查；模拟 NVS 与 RTOS，覆盖重启、保存失败、提交后发布、旧档保护及 uid/时间旁表。ASan/UBSan 通过，未擦除 NVS。V5 结构仍为 2296 B。
- `verify_capture_flow.py --negative`：6 个实际 C 业务流程、244 次横带/全屏一致性检查；4 个破坏版本被测试捕获，包括跳过反击、解除动画锁、重置战斗、失败未出队。
- `verify_firmware_preview.py`：8 个实际页面，921 次横带/全屏检查，65536 种 RGB565 解码对照，DMA/漏刷横带的负向检查通过。
- 球素材：原源码 gfx 优化工具 + OAM 拼图与 PNG/4 项 UI 数据对照零差异；3 套调色板零差异；真实 C 渲染 460800 像素零差异，ASan/UBSan 通过。
- `verify_firmware_clock.js`：9 项输入/时钟/场景检查与 5 项破坏版本检查通过。
- ESP32-C3 固件构建通过，主固件 0x183fb0 B，适配 3 MB 主应用分区。仍有原先 1 MB recovery 分区容不下主程序的警告；本轮未烧录。
