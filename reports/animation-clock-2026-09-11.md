# 招式动画时钟修复

固定来源的原作执行轨迹按 59.7275 Hz 提取、45 ms 显示采样。764 个案例的时长差最多 44.20 ms，未发现素材时长整体倍率错误。冲浪原作 3.181 s / 轨迹 3.195 s，喷射火焰 2.645 s / 2.655 s，破坏光线 1.088 s / 1.125 s（均仅主动画，不含受击及回合间停顿）。

实际问题：moves.html 每完成一次 HTTP 渲染才加一帧，请求慢时显著降速；firmware.html 每次请求固定推进 60 ms，却在响应完成后再等 60 ms，传输耗时累计造成慢放。野战／训练家 C 也按回调次数加帧，显示任务超时会拉长演出。

修复：招式验收页按 performance.now 累计实际时间，延迟时跳过错过的显示采样；完整预览按实际经过时间推进模拟时钟。暂停、隐藏、场景重载重置时钟，不补播暂停时间。野战和训练家招式按单次招式开始时间选帧，跨过受击点仍只触发一次音效，同时将野战音效触发点对齐共享受击点。保留原有回合间停顿、成长演出和原作素材。训练家熄屏期间冻结招式计时。

验证：实际 moves.js 延迟、暂停、重播及负向变异通过；firmware.js 14 组时钟检查、5 组负向检查通过，按键 6 组回归通过。实际训练家渲染模拟一次 270 ms 阻塞，与正常推进后逐像素相同、回合数相同；经验与结算 580 次像素检查通过。ESP-IDF 构建通过。证据见 evidence/animation-clock-2026-09-11。
