# 官方固件更新对照：2026-09-15

审查基线：PokeWalk `d25dc4f`，官方 main `cd73a8a6f1f95e010bfd83a08e2b915e38408308`。本次为源码审查与移植建议，未修改固件、烧录设备或测量功耗。官方 Changelog 有历史规则残留，分区判断以当前 CSV 和验证器为准。

## 建议优先实施

### 1. 音频真正停时钟，并校验休眠状态

本地 `firmware/components/bsp/src/bsp_audio.c:101` 在 close 后立即 enable TX/RX。这本来是解决下一次 open 的状态问题，但使 I2S 在整个静音/熄屏期间仍可能运行。`sfx.c` 每 25ms 查询一次状态，熄屏遇敌提示仍可以临时开启声音。

移植官方的强制 ES8311 休眠序列、寄存器回读、有限重试与 I2S disable；把 enable 移到真正恢复播放之前。REG45 从当前的 0x00 改为上游休眠用 0x01，关闭 BCLK/LRCK 内部上拉。采用 9 月 15 日修正后的 REG0E 掩码：只检查有效的低七位，避免把 0x7F 回读误判为失败。

保留本地开机静音、用户音量、单一播放任务和熄屏遇敌提示；不能直接用上游默认音量或启动音频流程覆盖本地功能。失败状态必须允许重试，不能仅依赖 sleeping 标志跳过上一次失败的校验。恢复失败后应重新停时钟，避免半唤醒状态。

依据：[官方音频实现](https://github.com/FoloToy/ai-passport/blob/cd73a8a6f1f95e010bfd83a08e2b915e38408308/components/bsp/src/bsp_audio.c)、[回读掩码修复](https://github.com/FoloToy/ai-passport/commit/12f684d69a9672aa911585d72992ae5e3ffa384f)。

### 2. BSP 初始化失败完整回滚

本地屏幕初始化的部分命令忽略返回码；s_panel 创建后即使后续失败，再次 init 也可能被当成成功。SPI 总线 / panel IO 创建后的失败路径没有完整释放。音频 ctrl、data、codec、GPIO 接口和 I2S 通道的失败路径也有同类问题。

借鉴上游独立 ready 状态、检查每一步、按依赖逆序释放、允许重试的处理。共享 I2C 仍由 BSP 唯一持有，不因一个音频初始化失败而删除电量计仍在使用的总线。

依据：[官方显示初始化](https://github.com/FoloToy/ai-passport/blob/cd73a8a6f1f95e010bfd83a08e2b915e38408308/components/bsp/src/bsp_display.c)。

### 3. 熄屏期间降低后台唤醒频率

我们已有面板 DISPOFF / SLPIN、背光 PWM 停止、唤醒重绘，显示层面的基础优化已经具备。但 MCU 仍工作，Wi-Fi 每 30 秒扫描，声音任务仍每 25ms 轮询；当前未启用 CONFIG_PM_ENABLE。

建议先让闲置声音任务等待事件，保留静音切换、遇敌提示和唤醒通知。随后依据已有静止/移动判断自适应调整 Wi-Fi 扫描频率；例如静止时逐步延长，变化后恢复。具体间隔属于待测参数，需要对照电流和遇敌延迟确定，不宣称固定续航提升。游戏后台养成仍按实际时间结算，不能因减少轮询漏发体能。

这属于结合我们游戏设计的优化建议，不是官方本次已提供的游戏策略。

## 深度睡眠应独立设计

官方 demo 的 light sleep 是两秒定时唤醒，deep sleep 是五秒后定时重启；没有承诺三键唤醒。三键共用 ADC 分压，不能把普通按键识别直接等同于深睡唤醒能力。

因此保留当前短期熄屏的按键唤醒和后台遇敌。后续若加“长期休眠”，应保存当前进度、停止后台任务和无线活动，再按 CW2017 → ES8311 → I2S 引脚 → 共享 I2C → 显示与引脚保持的顺序关闭。深睡准备后的引脚释放接口不适合普通页面熄屏，官方也是通过重启恢复。

CW2017 的新休眠接口适合这一阶段。当前本地电池 profile 与最新官方一致，无需更换。电量计不能直接接到每次 60 秒熄屏：上游新增的是休眠接口，还需设计运行中恢复和电量有效性。深睡中没有持续 Wi-Fi 扫描，因此不能同时承诺保持现有遇敌体验。

依据：[官方低功耗 demo](https://github.com/FoloToy/ai-passport/blob/cd73a8a6f1f95e010bfd83a08e2b915e38408308/main/demo_low_power.c)、[电量计实现](https://github.com/FoloToy/ai-passport/blob/cd73a8a6f1f95e010bfd83a08e2b915e38408308/components/bsp/src/bsp_battery.c)。

## 分区容量：有收益，但保留现有数据地址

当前应用 3,137,808 字节，3 MiB 分区剩 7,920 字节（约 7.7 KiB）。官方默认只保留 NVS、PHY、factory，factory 从 0x10000 占到 8 MiB 末尾；当前验证器也改为通用边界、重叠和实际应用大小校验。旧 Changelog 提到的 cardid 保护并不反映当前 CSV。

不能直接替换为官方表：本地的 cardid、save_restore、wifi_config、recovery 会落入其应用空间。建议先评估将现有 factory 从 0x300000 扩至 0x340000（增加 256 KiB，结束于 0x350000，仍早于 cardid 0x356000），其余数据地址完全不动。同步更新旧版固定 3 MiB 校验器，并叠加本项目数据保护检查；需验证社区安装流程接受自定义新布局。此处只提出候选方案，未变更分区或移除 recovery。

更长期的大资源扩容再设计独立资源区，不能把官方“允许自定义 8 MB 布局”理解成可以覆盖设备已有数据。

依据：[官方分区](https://github.com/FoloToy/ai-passport/blob/cd73a8a6f1f95e010bfd83a08e2b915e38408308/partitions.csv)、[当前验证器](https://github.com/FoloToy/ai-passport/blob/cd73a8a6f1f95e010bfd83a08e2b915e38408308/tools/verify_firmware.py)。

## 生命周期与发布流程

保留我们独立的游戏导航和常驻 world/sfx 服务，不套用 demo 在页面退出时停止整个无线服务的策略。可借鉴 stop 完成握手、停止失败不销毁页面资源、启动失败回滚的做法。

目前仓库的 GitHub Actions 只有存档管理站点发布；建议补固件 PR 构建及核心 C 回归，在发布时归档构建摘要、对应源码 commit、数据布局与测试范围。继续由发布阶段统一维护版本说明，区分已实现、设计中、未完成实机测试。上游通用模板的文档语言/目录规则不必整体搬入已有游戏项目。

## 移植后的验收要求

- 播放 → 静音 → 解除静音，以及熄屏 → 唤醒：连续多轮，没有爆音、无声或采样率错误。
- 静音开机和未播放过就熄屏均保持低功耗状态；熄屏遇敌提示播放完再次休眠。
- ES8311 有效位回读、I2C 写读失败、部分 I2S 停止失败、恢复失败允许重试。
- 显示/音频逐阶段初始化失败后资源释放且下一次可成功初始化。
- 旧存档、秘境中途、体能恢复和 USB 备份导入不回退。
- 同一设备、同样电源条件下比较亮屏/熄屏/静音/遇敌提示的电流，记录最低值与周期平均值；USB 调试连接对测量的影响单列。
