# 技能数据、动画与硬件接线核查（2026-09-07）

> 以下是技能实现前的核查基线，包含当时的缺陷数与建议。后续已接入共享 C 技能渲染并修正 8 项 wait；当前完成情况见 [技能实现报告](battle-fx-implementation-2026-09-07.md)。诊断 JSON 保留核查时的原始数据，没有用修复后的数字覆盖历史证据。

**结论：技能数值已经接入固件，但 web 的技能动画还没有接入固件。** 当前的 26 项专属动画注册和 15 项属性兜底只属于 JS 设计预览，不能当作真机的技能效果数量。优先把已有动画接入共享渲染链路，再扩充专属动画；本报告没有修改业务代码、模板或现有资产，也没有操作设备或浏览器。

本次以工作区实物为准：读取 `moves.bin`、学习表、模板动画注册、固件战斗与渲染实现，并核对 pret 源码。`docs/_review-moves.md` 和 handoff 中的历史数字有多处已经过期。并行工作中的公共文件可能继续变化，诊断 JSON 记录了当次模板和二进制的 SHA-256。

## 2. web 到硬件断在哪里

现有链路：

```text
moves.bin → assets_known_moves / known_moves → battle_run / auto_battle
    固件：battle_round_t（招名、伤害、HP、miss）→ play_battle.c → 统一 shake
    web ：sim 导出的 rounds → fxSpec → MOVE_FX / TYPE_FX → p3G / fxOverlay
```

- `firmware/main/battle.h` 的 `battle_round_t` 只有招式中文名指针与长度，没有 `move_id`、属性、效果种类或动画参数。`move_t` 原本有 ID/属性，但回合记录没有保留它们。
- `play_battle.c` 每回合按固定 600 ms 播放：命中 4 × 60 ms 抖动 + 停留，未命中保留停留时间。`draw_band()` 没有技能图元层。web 则按每个 `dur` 以 10 fps 建不同长度的时间线；时钟也不共享。
- 专属动画只在 JS 的 `p3G()` 中调用，其他设计方向不调用 `fxOverlay()`。新加入的固件同源预览是否覆盖动画，需要以实际固件接线另行验收，不能从 G 页面反推。
- `GSC_GFX`、`MOVE_FX`、`TYPE_FX`、段内求值和图元解释器都内嵌在 `template.html`。`build.py` 仅从 `moves.bin` 导出招名→属性；CMake 没有嵌入这些技能图元，`ui.bin` 的转换清单也没有它们。

**建议共享边界：** 回合结果保留稳定的 `move_id` 和必要参数；动画只读结果。用同一份已核对的动画配方与图元资产，由共享 C 求值器按相同相位绘制，web 消费相同求值结果。位移、叠加、擦除和跨带刷新必须一起接，不能只共享注册表名字。

## 3. “时长已全按 asm 实值”仍不成立

使用已经存在的 `/tmp/pokecrystal`，其 remote 为 `https://github.com/pret/pokecrystal.git`，工作树干净，提交为 `7a7881d0d62e0ddbd82dcf10e7116807487ac651`。还从官方 raw URL 读回了动画源码：与本地逐字节相同，133738 B，SHA-256 为 `3e8c0e82a8807342862970304fb879bf7c4ad2364675c3af2f5af356b11d07e3`。

诊断脚本从招式 ID 对应的动画表入口出发，处理别名、调用和有限循环，计算实际执行的 `anim_wait` 参数总和（参数分支取 0）。**这是脚本 wait 求和，不是 Game Boy 运行时逐帧仿真。** 对 26 项注册，8 项记录值不符：

| 招式 | 注册注释/段表值 | 源码 wait 合计 | 原因 |
|---|---:|---:|---|
| 撞击 #33 | 12 | 25 | 漏掉被调用的目标准备与显示恢复，共 13 |
| 水枪 #55 | 104 | 114 | 漏掉两个子调用，共 10 |
| 吸血 #141 | 122 | 176 | 引用了 Absorb（吸取 #71）；实际是 LeechLife |
| 乱击 #31 | 32 | 48 | 引用了 FurySwipes（乱抓 #154）；实际是 FuryAttack |
| 落石 #88 | 106 | 104 | 5 块石头之间只有 4 次 wait 2 |
| 连环巴掌 #3 | 42 | 单次 14 | 42 是额外硬定三次；回合记录没有命中次数 |
| 飞叶快刀 #75 | 170 | 168 | 10 个 incobj 之间只有 9 次 wait 2 |
| 念力 #93 | 128 | 138 | 漏掉两个子调用，共 10 |

其中飞叶快刀取整后的 10 fps 时长仍是 28，但段内时间比例仍然不符。连环巴掌若保留三连观感，应标明是项目改编，并在效果参数中表达次数，不能称原脚本单次时长。

还有第三个名字映射需纠正：`紧束` #35 实际对应 `Wrap`，注册注释写了 `Bind`（绑紧 #20）。两者 wait 总和相同，但图元序列有差异，所以单测总时长抓不到这类错配。

原作 `anim_wait` 接受小于 `$d0` 的值，并非固定“2/4/8/16/32/96 六档”。注册表和 UI 中这句描述也应修正。来源：[固定版本动画表](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/data/moves/animations.asm)、[动画宏](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/macros/scripts/battle_anims.asm)。

## 4. 素材来源真实，但提取与渲染仍有缺口

模板中的主要技能素材为 fire、water、leaf、bubble、cut、powder、wave、rocks、bolt，合计 23 个裁切帧、4928 像素；另有 explosion tile 0 组成电击核心球。源头可以对应到 pret/pokecrystal 的 battle_anims PNG。它们只以 JS 字符串形式存在，缺少可重跑的技能素材转换脚本、源提交/裁切区域/调色板索引清单和固件产物。

本次按透明轮廓核对这 23 个裁切帧，都能在对应原 PNG 中找到匹配；这能支持“轮廓来自原图”，**不能支持完整 OAM 帧组装和色阶逐像素一致**。例如 fire 第一个 8×8 裁片中，源图 (6,7) 为灰度 170，而模板把它和邻近灰度 85 一样记为 `2`，内部色阶已经合并。旧 handoff 的 rocks 抖动色阶损失属于同类问题。

此外，下列仍为模板中的几何构造：HIT 命中星、针、舌、球、风线、吸取粒子、绑带；多个招式共享这些原语。原仓库已有 `hit.png`、`horn.png`、`whip.png`、`rope.png`、`objects.png` 等真实资产，可优先从它们按 OAM 定义提取。对外应区分“原图裁片”和“原作完整效果”。

一处容易在扩招时放大的渲染问题：蓄力剪影缩放写死为 `atkR.s/32` 或 `atkR.s/40`，但实际 back 可以是 48，front 为 40/48/56。以 48/56 的 front 为攻击者时，剪影会比目标框再放大 20%/40%；这与主渲染取实际源尺寸的逻辑分叉。建议共享动画测试同时覆盖这些源尺寸。

## 5. 技能“效果”在玩法层也被简化了

目前 C/Python 都按威力、命中、属性、本属性加成和物理/特殊算伤害。PP 虽然入库但不消耗；没有招式优先度、吸血回血、多次命中次数、反伤、自爆退场、状态异常等附加效果。`reserved` 2 B 在 99 招中全为零。动画里的吸取粒子或三连打击不会产生对应的玩法结算。若用户所说的效果还包含这些机制，需要单独安排规则实现，而不是继续给 JS 加动效标记。

本次还发现了一个既有数据问题：`fetch_gen1.py` 还原了属性/威力等历史值，却直接保留现代 `damage_class`，C/Python 再按该值选择攻防数值。**16/99 招与项目宣称的初代物特分类不同**，包括火焰拳、冰冻拳、雷电拳、起风、藤鞭、飞叶快刀、高速星星等。初代依据属性区分物理/特殊，见 [pokered 伤害取值](https://github.com/pret/pokered/blob/a1a22aaf84d1675bcdbaeb194592379d586d838e/engine/battle/core.asm#L4041) 和 [属性常量](https://github.com/pret/pokered/blob/a1a22aaf84d1675bcdbaeb194592379d586d838e/constants/type_constants.asm)。这是两端共同读取同一份错误数据，现有 C/Python 一致性检查不一定发现。应在扩规则前修复数据口径并检查战斗平衡变化。

旧评审的“排除了 66 变化招”也不准确：现有原始缓存中，66 个排除项是 **55 个变化招 + 11 个伤害类招**。后者包括音爆、地球上投、龙之怒、黑夜魔影、反拳、愤怒门牙及一击必杀等，因没有普通威力值一起被过滤掉了。应将范围写成“99 个普通威力招”，扩充这些招时补对应伤害规则，不能给它们随意填一个 power。

## 6. 建议按这一批收口

**先用已有四招完成双端闭环：撞击、电击、水枪、落石。** 四招分别覆盖角色位移、图元叠加/调色板、逐行变形、跨带移动与场景抖动；能发现只验证静态名牌/HP 条时看不到的缺口。沿途修复上述错名、wait 口径和源尺寸依赖。

闭环条件：同一资产、同一回合快照、同一逻辑相位，两端 RGB565 像素相同；分别验证主宠/野怪攻击、命中/未命中、动画结束清理。增量重画应等于目标相位的完整重画，不能留尾迹或半幅抖动。最后需实际设备确认推屏时序与耗时；PC 对账只能证明渲染算法。

**渲染通过后，新增下面 8 个可达招式的专属效果，注册数从 26 到 34。** 数值表不需要先扩到 165。

| 招式 | 选择理由 | 原作实现入口 |
|---|---|---|
| 高速星星 #129 | 主宠皮卡丘 Lv26 解锁，当前只是一般系撞击兜底 | `Swift`，OBJECTS 星星弹道 |
| 打雷 #87 | 主宠皮卡丘 Lv43 解锁，与电击形成明显差异 | `Thunder`，左右中三组闪电 |
| 吸取 #71 | 已有吸血错引的脚本应归回正确 ID | `Absorb`，CHARGE 吸收轨迹 |
| 乱抓 #154 | 已有乱击错引的脚本应归回正确 ID | `FurySwipes`，CUT 左/右分支 |
