# 道具核心与存档事务验收 · 2026-09-08

本组已完成 `items.c/h`、V6 存档与 `world` 道具事务。19 类道具使用有限库存；掉落、投球消费、养成和进化在候选快照保存成功后才发布到运行状态。保存失败保留原库存与效果，支持安全重试。页面、捕获球倍率、预览宿主镜像和设备构建由根任务及页面代理整合。

## 道具规则

| 范围 | 道具 | 单项容量 |
|---|---|---|
| ID 0–3 | 精灵球、超级球、高级球、大师球 | 99、30、20、1 |
| ID 4–7 | 速度球、沉重球、等级球、友友球 | 各 20 |
| ID 8–12 | 火之石、水之石、雷之石、叶之石、月之石 | 各 9 |
| ID 13–14 | 通讯机器、成长机器 | 各 5 |
| ID 15–18 | 树果、活力根、哞哞牛奶、开心饼干 | 各 30 |

新游戏和有效 V5 档迁移获得同一初始包：12 精灵球、3 超级球、1 高级球、2 树果、2 牛奶，其余为零。迁移后的库存消费会写入 V6，再次开机不会重新补发。

- 树果：饱食 +30、心情 +5；P5 喂食及兼容 `world_feed()` 均消费树果。
- 活力根：体能 +70、心情 −5。这个增量按根任务最新决定高于免费休息 +48。
- 牛奶：饱食 +20、体能 +25。
- 开心饼干：心情 +25、亲密 +2。
- 所有轴限制在 0–100；完全没有正向收益时不消费道具，避免只受活力根负作用。
- 五石覆盖 16 条第一代路线，包含伊布的三种石头分支。通讯机器覆盖 `64→65、67→68、75→76、93→94`。
- 自然 LEVEL 进化保留原亲密/探索条件且免费。成长机器是在达到原进化等级后跳过这两项条件的捷径。ITEM 和 TRADE 不能通过旧的免费进化入口绕过消费。
- 进化保留等级、EXP、HP、闪光标记、昵称与探索值，更新队首物种和图鉴，延续既有心情 +15 奖励。

20 条石/通讯目标由检查程序独立解析固定 [pret/pokecrystal 7a7881d](https://github.com/pret/pokecrystal/blob/7a7881d0d62e0ddbd82dcf10e7116807487ac651/data/pokemon/evos_attacks.asm) 的原始进化表、物种常量与指针表，再与实际 `items_apply()` 枚举结果比较。容量、掉落权重、机器捷径及养成增量是项目玩法，不宣称原作数值复刻。

## 事务接口与存档

`items_info()` 提供名称、说明、类别；`items_capacity()` 是容量唯一来源；`world_inventory_snapshot()` 返回锁内值拷贝。

`world_item_use(expected_species, item_id, out)` 在锁内重新核对队首、库存、适用目标和门槛。先形成 party/dex/养成/库存候选，NVS 成功后发布。陈旧物种、空库存、无收益、未达等级、存储不可用或仍有活动战斗均返回明确状态，失败不产生消费。`world_evolve_leader()` 使用相同候选保存方式，且只接受自然 LEVEL 路线。

V6 为 **2336 B**，完整保留 V5 的 **2296 B** 前缀及其尾部填充，新增 38 B 库存和末尾对齐。静态断言固定旧尺寸及新字段偏移。`save_read_status()` 对有效 V5 返回 `SAVE_READ_MIGRATED`，只在内存补入初始包；后续成功保存写 V6。未知版本、错误长度、超出各项容量的库存和已有异常队伍/遭遇保护继续拒绝覆盖，测试中没有调用擦除。

修改库存/队伍/养成的路径统一使用 `s_save_lock → s_lock` 次序；NVS I/O 期间释放状态锁以保持只读快照可用。后台照料/探索变更等待保存锁，图鉴“已见”可并发更新；发布事务时只合并自己的目标变化，后到的已见标记保留并继续标脏。

## 胜利掉落与捕获

稀有度 1–5 的掉落概率为 **25/35/45/55/65%**。每次最多一种，精灵球一次 2–3 个，其他一种 1 个；高星提高高级球、特殊球、石和机器的权重，大师球仅在五星低权重出现。纯函数 `items_loot_seed(uid, ts, species, rarity)` 与 `items_roll_loot()` 使用独立随机流，不读取或推进战斗 RNG。

`world_battle_loot_uid()` 仅处理已胜利的活动会话。无掉落也设置 `loot_checked`；重复查询返回同一次结果，陈旧页面会话无法清掉该标记。返回的 `quantity` 是实际入包数，`full` 表示容量不足，满额不溢出。保存失败不标已处理，重试仍得到相同抽取结果。活动遭遇已在开战时持久移出队列，重启不会重新领取同一战斗。

`world_capture_ball_spend_uid()` 将扣一球、首次脱离待处理队列和候选投球会话一并保存。空库存、目标/HP/RNG/回合状态变化、保存失败均拒绝发布。胜后最终机会在这次提交成功才被消耗；失败仍能重试。

捕获成功的收容是另一次事务：`world_capture_uid()` 保存失败时保留原 party/dex 和活动目标，已扣的一球保持已扣；同一个成功结果可以单独重试收容而不再消费球。根任务负责 P4 在此情况下持有成功结果并显示保存重试，不能误判为捕获失败。

- `verify_items.py --negative`：**102 个实际 C 场景，ASan/UBSan 通过**。直接链接真实 assets/items/world/save/party/evolution 等代码与真实资产，只替换 RTOS/NVS/时钟/设备边界。
- 覆盖 V5→V6 一次补发、19 项非法库存拒写、20 条石/通讯路线、成长机器与自然通道、三种 NVS 失败点、一次掉落、满额、八种球消费、最终机会、第二次收容失败重试、pthread 并发照料与图鉴合并。
- **5 个私有源码负向**全部被拒绝：删除掉落 once、忽略保存失败、石头绕过消费、去掉容量裁剪、每次读 V6 重发初始包。生产源码没有被测试变体改写。
- 50 万个独立掉落样本：五星以下大师球均为零；五星为 378/100000 场。各星掉落计数为 `24996、34886、45053、55032、65086 / 100000`，与设定概率相符。
- 既有 `verify_starter.py --sanitize` **67 项**、`verify_encounter_lifecycle.py --sanitize` **10 项**继续通过，已更新新版本断言与 items 链接。
- render_audit 独立的 **5 组真实存储复核**通过，另行确认第二次收容失败可安全重试。

详细记录在 `reports/evidence/items-2026-09-08/world-save.json` 与 `independent-storage-review.json`。这些验证证明源码事务与模拟失败/重启的行为；物理 ESP32/NVS 断电表现和页面可见反馈由根任务做最终验收，本子任务未操作设备。
