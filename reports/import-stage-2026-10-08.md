下文保留首次本地排查时的状态。后续应用户要求进行的烧录与发布验证见 [发布记录](import-stage-release-2026-10-08.md)。

## 状态与结论

社区反馈：10 月 7 日上午版备份导入晚间更新的游戏时，提示“存档内容不兼容或暂存失败，原存档未替换”。尚未取得反馈用户的原始备份或设备日志，因此不能确认其具体失败阶段，也不能宣称该用户的问题已复现或彻底解决。

已修复一个会产生相同提示的实际风险：V21 的设备导入校验在 24 KiB 上传缓冲区、Wi-Fi 和游戏常驻内存之外，另行分配 `save_t` 与 `party_t`，合计约 13 KiB。任一分配失败都会返回通用 `STAGE`，网页误将内存资源问题与内容不兼容并列提示。本次复用现有事务工作缓冲区，不再申请这两块临时堆内存，并补充可追踪的失败阶段。

修复处于本地开发状态，**未提交、未烧录、未部署网页、未发布**。基线提交：`890f188758d87d77e5b08464faf908b261a57aed`；上一发行应用源码为 `4b614e7c8c90529f261fc9ca729774807b6f29e3`。本地改动摘要和应用 SHA-256 见 `evidence/import-stage-2026-10-08/validation.json`，不能将带工作区修改的应用描述为基线提交的发行构建。

## 修复与保护边界

- `world_backup_validate()` 持有现有保存锁，借用 `s_save_buf` 和 `s_starter_party`；两者为事务工作区，不是运行中的队伍或世界状态。串口处理原本已持有 UI 锁。后续事务会重新收集自己的状态。
- 继续在独立 `pw_import` 暂存 NVS 中读取实际内容，复用 `save_decode()` 和 `save_validate_world()`；保留真实数据版本与文件声明版本核对。没有清零玩家进度或放宽内容校验。
- 协议保留 `ERROR STAGE` 前缀，追加 `LAYOUT / FLASH / NVS / MEMORY / READ / VERSION / CONTENT / CHECKPOINT / JOURNAL`。旧工具仍安全拒绝，新工具显示阶段；未知细节回退通用提示。每次暂存前清除上一次失败原因。
- 校验失败、暂存写入/挂载失败、当前存档保存失败、恢复日志失败均不能显示导入完成；仍需用户确认、电脑预备份回读和匹配 ACK，恢复日志保持提交标记最后写入、目标构建绑定及失败回滚。
- 不改变 `save.h`、持久化布局、枚举编号、NVS 键或分区。支持来源仍为 **V5–V21**，不承诺较新格式倒灌旧固件；开发 CLI `restore.py` 的同构建保护未改动。

## 验证结果

`evidence/import-stage-2026-10-08/checks.json` 记录 13 项检查全部通过：AGENTS.md 要求的 11 项 Python/Node 检查，以及世界队伍事务和技能设置回归；另有 `tools/device/fw.sh build` 构建通过。

- V5–V21 的 23 份已提交历史布局样本通过启动迁移及真实 ESP-IDF NVS 引擎的隔离导入、重启读档、再次启动和回滚。历史样本未修改。
- 保留的真实 V20 设备存档（实际 state 4024 字节）在修复前、修复后均可通过生产暂存校验，源镜像和隔离环境的当前 NVS 不变。因此不存在“所有上午版备份都无法迁移”的证据。私人备份仅本地读取，未提交或上传。
- 禁止设备校验器直接申请堆内存的故障测试仍能成功暂存。其他故障覆盖暂存擦写、挂载、读取、解码/内容校验、checkpoint、恢复日志及卸载重试；错误阶段准确，失败不写当前 NVS。
- 生产 `world.c` 回归确认：有效及无效候选校验不改变运行队伍、世界、图鉴、道具、遭遇、dirty 状态、保存时钟或磁盘；下一次 checkpoint 重新保存原运行态，不误写导入缓冲区。
- 网页生产读取循环保留细分错误，不在断开时改成“重启中”或“导入完成”；旧固件简略错误及未知细节继续安全失败。在线静态页面与离线 ZIP 的分发测试通过。

## 交付与后续定位

减少校验内存占用需要更新固件，**仅刷新网页不能修复旧固件分配失败**。细分提示需要新固件配合刷新网页或重新下载离线工具。正式发布时同步 GitHub Pages、devbox、离线 ZIP，检查实际发布应用摘要与最终源码、CI；本地通过不等于已部署。

保留用户原始 `.pksave`。若新固件仍失败，根据细分阶段继续定位；`CONTENT` 需要原备份在隔离环境分析，`MEMORY` 需要实际设备运行时余量，`FLASH/NVS/JOURNAL` 则检查暂存分区及相应错误日志。不能仅从截图推断数据损坏。不要让用户修改文件版本号或校验值。

发布仍须说明：社区完整安装会写入 NVS 空白区，先备份后安装并恢复；分区匹配的应用更新包才走保档更新。此次修复不改变安装行为。
